% ---------- MAE ----------
\clearpage
\thispagestyle{regressionstyle}
\section{MAE}
\subsection{Mean Absolute Error}

MAE is one of the most intuitive regression metrics: it tells you, on average, how far off your predictions are in the same units as your target.
If you're predicting house prices and your MAE is \$15,000, each prediction is off by \$15K on average. This directness makes MAE the go-to metric
when you need to communicate model performance to non-technical stakeholders.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                MAE = \frac{1}{{\color{nmlred}n}} \sum_{t=1}^n |{\color{nmlcyan}Y_t} - {\color{nmlpurple}\hat{Y}_t}|
                $
            }
        };
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-0.4,0.2)$) to[bend left=15] node[pos=1, left] {number of samples} +(-1,-.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.2,-0.3)$) to[bend left=15] node[pos=1, right] {forecast value} +(1,.5); 
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(1.2,0.5)$) to[bend right=15] node[pos=1, right] {actual value} +(1,-.5);
    }
\end{center}

MAE ranges from 0 (perfect) to +infinity. To interpret it in context, compare MAE to the standard deviation of your target:
MAE $\ll$ std($Y$) suggests a useful model, while MAE $\approx$ std($Y$) means your model is barely better than predicting the mean.

\textbf{When to use MAE?}

Use MAE for demand forecasting, inventory planning, or any task where over-predicting by 5 is exactly as bad as under-predicting by 5.
Avoid MAE when large errors are disproportionately costly (use RMSE), when you need scale-free comparison across different targets (use MAPE),
or when you need a differentiable loss function for training (use MSE).

% strength and weakness box
\coloredboxes{
    \item Robust to outliers. Unlike MSE, a single bad prediction doesn't dominate the score. If 99 predictions are off by 1 and one is off by 100, MAE = 1.99 while RMSE = 10.0.
    \item Directly interpretable. MAE = 5.2 means ``on average, predictions miss by 5.2 units.'' No square roots or percentage conversions needed.
}
{
    \item All errors are weighted equally. A model with many small errors gets the same MAE as one with fewer but larger errors. If large errors are costly, use RMSE.
    \item Not differentiable at zero, so it cannot be directly used as a loss function in gradient descent. In practice, Huber loss or smooth L1 are used instead.
}

\orangebox{Did you know that...}
{Minimizing MAE leads to predicting the \textbf{median}, while minimizing MSE leads to predicting the \textbf{mean}.
This is why MAE is more robust to outliers --- the median is less affected by extreme values than the mean. If your target distribution
is skewed (e.g., income, claim amounts), this distinction matters: MAE and MSE will favor different models.}

\textbf{Other related metrics}

If your MAE and RMSE differ significantly, it signals that some predictions have large errors (RMSE amplifies them). A rule of thumb:
RMSE/MAE close to 1.0 means errors are uniform; RMSE/MAE $\gg$ 1.0 means a few predictions are far off.
For percentage-based comparison across different-scale targets, use MAPE or sMAPE.

% ---------- MSE ----------
\clearpage
\thispagestyle{regressionstyle}
\section{MSE}
\subsection{Mean Squared Error}

MSE is both a metric and the most widely used loss function in machine learning. By squaring each error before averaging, it
disproportionately penalizes large mistakes — an error of 10 contributes 100 to MSE, while an error of 1 contributes just 1.
This makes MSE the right choice when large errors are catastrophic (e.g., structural engineering, medical dosing).

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                MSE = \frac{1}{{\color{nmlred}n}} \sum_{t=1}^n \left({\color{nmlcyan}Y_t} - {\color{nmlpurple}\hat{Y}_t}\right)^2
                $
            }
        };
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-0.6,0.2)$) to[bend left=15] node[pos=1, left] {number of samples} +(-1,-.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.2,-0.3)$) to[bend left=15] node[pos=1, right] {forecast value} +(1,.5); 
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(1.2,0.5)$) to[bend right=15] node[pos=1, right] {actual value} +(1,-.5);
    }
\end{center}

MSE ranges from 0 (perfect) to +infinity. The main interpretation challenge is that MSE is in squared units — if you're predicting
revenue in dollars, MSE is in dollars-squared. Take the square root to get RMSE, which returns to interpretable units.

\textbf{When to use MSE?}

Use MSE as a loss function for training models (gradient descent works smoothly since MSE is differentiable everywhere). Use it as an evaluation metric
when large errors are disproportionately costly — a 10-unit error should count more than ten 1-unit errors. Avoid MSE when your data has outliers
(use MAE) or when you need interpretable units (use RMSE).

% strength and weakness box
\coloredboxes{
    \item Differentiable everywhere, making it the default loss function for gradient-based optimization. This is why most regression models are trained with MSE even if evaluated with another metric.
    \item Heavily penalizes large errors. If your business cost is quadratic in error magnitude (e.g., a 2x bigger mistake costs 4x more), MSE directly reflects that cost structure.
}
{
    \item One outlier can dominate the entire score. A single prediction off by 100 contributes the same to MSE as 10,000 predictions off by 1. Always check RMSE/MAE ratio to detect this.
    \item Units are squared (dollars$^2$, meters$^2$), making raw MSE values hard to interpret. Report RMSE instead when communicating results.
}

\orangebox{Did you know that...}
{MSE decomposes into variance + bias$^2$: $MSE(\hat{\theta}) = \text{Var}(\hat{\theta}) + \text{Bias}(\hat{\theta})^2$. This is the mathematical foundation
of the bias-variance tradeoff. A model with zero bias but high variance (overfitting) and a model with high bias but low variance (underfitting)
can have identical MSE — but for very different reasons. Monitoring both components separately is key to diagnosis.}

\textbf{Other related metrics}

RMSE = $\sqrt{MSE}$ restores interpretable units and is almost always preferred for reporting. If your RMSE is much larger than your MAE,
your model has a few very large errors dominating the score. MSE is primarily valuable as a training loss, while RMSE and MAE are better evaluation metrics.

% ---------- MSLE ----------
\clearpage
\thispagestyle{regressionstyle}
\section{MSLE}
\subsection{Mean Squared Log Error}

MSLE measures relative errors rather than absolute ones. Predicting 110 when the target is 100 (10\% off) gets the same
penalty as predicting 1100 when the target is 1000 (also 10\% off). This makes it ideal when you care about proportional
accuracy — getting within 10\% matters the same whether the target is \$100 or \$1M.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                MSLE = \frac{1}{{\color{nmlred}n}} \sum_{t=1}^n \left(log({\color{nmlcyan}Y_t} + 1) - log({\color{nmlpurple}\hat{Y}_t} + 1)\right)^2
                $
            }
        };
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-2.6,0.4)$) to[bend left=15] node[pos=1, left,align=center] {number\\of samples} +(-1,-.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(3.1,-0.3)$) to[bend left=15] node[pos=1, right] {forecast value} +(1,.5); 
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(0.1,0.5)$) to[bend right=15] node[pos=1, right] {actual value} +(1,-.5);
        }
\end{center}

MSLE ranges from 0 (perfect) to +infinity. Because of the log transform, MSLE penalizes under-predictions more than over-predictions
of the same magnitude — predicting 50 when the target is 100 is penalized more than predicting 150.

\textbf{When to use MSLE?}

Use MSLE when your targets span orders of magnitude (e.g., website traffic from 100 to 10M visits, real estate prices from \$50K to \$50M)
and you care about percentage accuracy rather than absolute accuracy. Avoid when targets can be negative or when under-prediction and
over-prediction are equally bad (use MSE).

% strength and weakness box
\coloredboxes{
    \item Scale-invariant. A 10\% error on a \$100 prediction and a 10\% error on a \$1M prediction contribute equally. This is critical for data spanning multiple orders of magnitude.
    \item Naturally penalizes under-predictions more heavily, which is desirable in supply chain (stockouts are worse than overstock) and capacity planning.
}
{
    \item Only works with non-negative targets. The $\log$ transform is undefined for negative values (the $+1$ shift handles zeros).
    \item The asymmetric penalty is a design choice, not always desired. If over-prediction is equally costly, use MSE or MAE instead.
}

{MSLE is equivalent to MSE applied in log-space: $MSLE = MSE(\log(Y+1), \log(\hat{Y}+1))$. This means any model trained with MSE loss on log-transformed
targets is implicitly optimizing MSLE. This trick is commonly used in Kaggle competitions for price prediction and count data.}

\textbf{Other related metrics}

Related metrics for MSLE include Mean Absolute Log Error (MALE) and Root Mean Squared Log Error (RMSLE). 

% ---------- RMSE ----------
\clearpage
\thispagestyle{regressionstyle}
\section{RMSE}
\subsection{Root Mean Squared Error}

RMSE is simply $\sqrt{MSE}$, but that square root makes all the difference: it returns the error in the same units as your target.
If you're predicting temperature in °C and RMSE is 2.3, your predictions are typically off by about 2.3°C. RMSE is the most commonly
reported regression metric in practice because it's both interpretable and sensitive to large errors.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                RMSE = \sqrt{\frac{1}{{\color{nmlred}n}} \sum_{t=1}^n \left({\color{nmlcyan}Y_t} - {\color{nmlpurple}\hat{Y}_t}\right)^2}
                $
            }
        };
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-0.2,0.3)$) to[bend left=20] node[pos=1, left] {number of samples} +(-1,-.7);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(1.5,0.6)$) to[bend right=15] node[pos=1, right] {actual value} +(1,-.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.5,-0.5)$) to[bend left=30] node[pos=1, right] {forecast value} +(1,.2); 
    }
\end{center}

RMSE ranges from 0 to +infinity. A key mathematical property: RMSE $\geq$ MAE always, with equality only when all errors
are identical. The ratio RMSE/MAE $\in [1, \sqrt{n}]$ tells you about error distribution: close to 1 means uniform errors,
much greater than 1 means a few predictions are far off.

\textbf{When to use RMSE?}

Use RMSE as your default regression evaluation metric — it's interpretable, penalizes large errors, and is familiar to stakeholders.
Avoid when outliers are expected and you don't want them to dominate (use MAE), or when you need to compare models across
different-scale targets (use MAPE or R-squared).

% strength and weakness box
\coloredboxes{
    \item Interpretable units. RMSE = 2.3°C means ``predictions are typically off by about 2.3 degrees.'' This directness makes RMSE the go-to metric for reporting.
    \item Balances sensitivity and interpretability. It penalizes large errors (like MSE) but in understandable units (unlike MSE).
}
{
    \item Scale-dependent. RMSE = 5 means nothing without knowing the target scale. Normalizing by the target range or mean (NRMSE) helps, but MAPE or R-squared are better for cross-dataset comparison.
    \item Inherits MSE's outlier sensitivity. One prediction off by 100 among 99 predictions off by 1 gives RMSE = 10.0 vs MAE = 1.99.
}

\thispagestyle{regressionstyle}
\section{RMSLE}
\subsection{Root Mean Squared Log Error}

RMSLE is to MSLE what RMSE is to MSE — it takes the square root, restoring interpretability in log-space.
Like MSLE, it measures relative (proportional) errors, but returns them in a more readable scale. RMSLE is the standard
competition metric for price prediction and count data on platforms like Kaggle.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                RMSLE = \sqrt{\frac{1}{{\color{nmlred}n}} 
                        \sum_{t=1}^n
                        \left(
                            {log{({\color{nmlcyan}Y_t} + 1)}} -
                            {log{({\color{nmlpurple}\hat{Y}_t} + 1)}}
                        \right)^2}
                $
            }
        };
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-2.,0.3)$) to[bend right=15] node[pos=1, right] {number of samples} +(1,-.8);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(0.6,0.6)$) to[bend right=15] node[pos=1, right] {actual value} +(1,-.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(3.5,-0.5)$) to[bend left=20] node[pos=1, right] {forecast value} +(.4,.9); 
    }
\end{center}

RMSLE ranges from 0 to +infinity. An RMSLE of 0.1 roughly means predictions are off by about 10\% on average (since $e^{0.1} \approx 1.10$).
This percentage interpretation makes RMSLE useful when stakeholders think in relative terms.

\textbf{When to use RMSLE?}

Use RMSLE for price prediction, count forecasting, or any target with right-skewed distribution where a 2x over-prediction should
be penalized the same regardless of the base value. Avoid when targets can be negative, or when absolute accuracy matters more
than relative accuracy (use RMSE).

% strength and weakness box
\coloredboxes{
    \item Naturally handles targets spanning orders of magnitude. Predicting 110 vs 100 (10\% off) and 1100 vs 1000 (10\% off) contribute equally, unlike RMSE where the latter dominates.
    \item Penalizes under-predictions more than over-predictions, aligning with domains where shortfalls are costlier than surpluses (inventory, capacity planning).
}
{
    \item Only defined for non-negative values. Requires $Y, \hat{Y} \geq 0$ (the $+1$ handles zeros but not negatives).
    \item The asymmetric penalty is baked in --- you cannot turn it off. If over- and under-prediction are equally bad, use RMSE on log-transformed targets instead (which IS symmetric in log-space).
}

% ---------- MAPE ----------
\clearpage
\thispagestyle{regressionstyle}
\section{MAPE}
\subsection{Mean Absolute Percentage Error}

MAPE expresses errors as percentages: a MAPE of 5\% means your predictions are off by 5\% on average. This scale-free
interpretation lets you compare model accuracy across products, regions, or time series with wildly different magnitudes.
It's the lingua franca of business forecasting — when a stakeholder asks ``how accurate is the model?'' they usually want MAPE.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                MAPE = \frac{1}{{\color{nmlred}n}} \sum_{t=1}^n \left| \frac{Y_t - \color{nmlpurple}\hat{Y}_t}{\color{nmlcyan}Y_t} \right| \times 100
                $
            }
        };
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-0.9,0.2)$) to[bend left=15] node[pos=1, left] {number of samples} +(-1,-.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(1.7,0.0)$) to[bend left=15] node[pos=1, right] {forecast value} +(1,.5); 
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(1.2,0.2)$) to[bend right=15] node[pos=1, right] {actual value} +(1,-.5);
    }
\end{center}

MAPE ranges from 0\% (perfect) to +infinity. A common interpretation scale: MAPE $<$ 10\% is excellent, 10-20\% is good,
20-50\% is reasonable, and $>$ 50\% suggests the model needs significant improvement. However, what counts as ``good'' depends heavily on the domain and forecast horizon.

\textbf{When to use MAPE?}

Use MAPE for business reporting, demand forecasting, and any scenario where ``5\% off'' is meaningful regardless of the target magnitude.
Avoid when targets can be zero or near-zero (MAPE explodes to infinity), when errors should be symmetric (MAPE penalizes over-predictions
more), or for intermittent demand with many zeros (use MASE).

% strength and weakness box
\coloredboxes{
    \item Scale-free. You can directly compare a 5\% MAPE on \$10 products with a 5\% MAPE on \$10,000 products. No normalization needed.
    \item Universally understood by business stakeholders. ``The model is 7\% off on average'' needs no further explanation.
}
{
    \item Explodes when actuals are near zero. A single $Y_t \approx 0$ can make MAPE infinite, rendering the entire score meaningless.
    \item Asymmetric: over-predictions get penalized more heavily than under-predictions of equal magnitude. Optimizing MAPE systematically biases models toward under-forecasting.
}

baseline to your predictions (e.g., shifting temperatures from Celsius to Kelvin) changes the MAPE score. This is a subtle trap
when preprocessing data with offsets or normalization.}

\textbf{Other related metrics}

If MAPE is problematic for your data, the alternatives form a clear decision tree: sMAPE fixes the asymmetry and bounds the range,
wMAPE handles the zero-denominator issue by weighting, and MASE provides a truly scale-free comparison against a naive baseline.
If your targets are intermittent (many zeros), skip percentage metrics entirely and use MASE.

% ---------- sMAPE ----------
\clearpage
\thispagestyle{regressionstyle}
\section{sMAPE}
\subsection{Symmetric Mean Absolute Percentage Error}

sMAPE was designed to fix MAPE's two biggest problems: unbounded values near zero and asymmetric penalties. By averaging the actual and
predicted values in the denominator, sMAPE stays bounded between 0\% and 200\% and is less likely to explode when actuals are small.

% formula
\vspace{0.5em}
\begin{center}
	\tikz{
		\node[inner sep=2pt, font=\Large] (a) {
			{
				$\displaystyle
				sMAPE = \frac{1}{{\color{nmlred}n}} \sum_{t=1}^n \frac{\left| {\color{nmlcyan}Y_t} - {\color{nmlpurple}\hat{Y}_t} \right|}{({|\color{nmlcyan}Y_t}| + {|\color{nmlpurple}\hat{Y}_t}|)/2} \times 100
				$
			}
		};
		\draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-0.8,0.3)$) to[bend left=15] node[pos=1, left] {number of samples} +(-1,-.5);
		\draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.6,-0.2)$) to[bend right=15] node[pos=1, left] {actual value} +(-1,.5);
		\draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(1.8,-0.2)$) to[bend left=15] node[pos=1, right] {forecast value} +(1,.5);
	}
\end{center}

sMAPE ranges from 0\% to 200\% (or 0-100\% in the variant without the 0.5 factor). Unlike MAPE, sMAPE won't produce a 10,000\% error
when the actual is near zero — the shared denominator keeps it bounded. But beware: despite the name ``symmetric,'' sMAPE still has
a subtle asymmetry (see weaknesses).

\textbf{When to use sMAPE?}

Use sMAPE when you want a percentage metric like MAPE but your data includes small values that would make MAPE explode.
Common in forecasting competitions (M3, M4 used sMAPE as a primary metric). Avoid when you need true symmetry between
over- and under-predictions (use wMAPE), or when targets include exact zeros (use MASE).

% strength and weakness box
\coloredboxes{
    \item Bounded range [0\%, 200\%] prevents the extreme values that plague MAPE. A forecast can never produce an ``infinity\%'' error.
    \item Handles near-zero actuals gracefully. When $Y_t = 0$, the denominator becomes $|\hat{Y}_t|/2$ instead of MAPE's division-by-zero.
}
{
    \item Despite its name, sMAPE is NOT truly symmetric. Example: $Y=100, \hat{Y}=90$ gives 5.3\%, but $Y=100, \hat{Y}=110$ gives 4.8\%. Over-predictions get a slightly lower penalty.
    \item Still undefined when both $Y_t = 0$ and $\hat{Y}_t = 0$ simultaneously. For intermittent demand with many zeros, use MASE instead.
}

\sloppy
\orangebox{Did you know that...}
{SMAPE explains why the geometric mean often produces the best forecast combination. 
When you have two forecasts, \( x \) and \( y \), you need to find a single estimate, \( z \), that minimizes the total SMAPE error:
\[
s(x,z)+s(y,z) = \frac{|x - z|}{x + z} + \frac{|y - z|}{y + z}
\]
The best choice for \( z \) is the geometric mean:
\[
z = \sqrt{x \cdot y}
\]
This result matters in real-world forecasting. Many competitions and industry applications use this approach to improve forecasting accuracy.}

\textbf{Other related metrics}

sMAPE is closely related to MAPE and wMAPE. If the asymmetry of sMAPE is a concern, consider wMAPE instead.
For a scale-independent baseline comparison, use MASE.

% ---------- wMAPE ----------
\clearpage
\thispagestyle{regressionstyle}
\section{wMAPE}
\subsection{Weighted Mean Absolute Percentage Error}

wMAPE solves MAPE's most dangerous flaw: the zero-denominator explosion. Instead of dividing each error by its individual actual value,
wMAPE divides the total absolute error by the total of actuals. Think of it as MAE normalized by the sum of actuals — it gives a percentage
that's robust to individual zeros while reflecting each item's economic importance.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                wMAPE = \frac{\sum_{t=1}^n |{\color{nmlcyan}Y_t} - {\color{nmlpurple}\hat{Y}_t}|}{\sum_{t=1}^n |{\color{nmlcyan}Y_t}|} \times 100
                $
            }
        };
        \draw[overlay,-latex,nmlcyan,semithick] ($(a.north)+(0.8,-0.1)$) to[bend right=15] node[pos=1, left] {actual value} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.0,0.0)$) to[bend left=15] node[pos=1, right] {forecast value} +(1,.5); 
    }
\end{center}


wMAPE ranges from 0\% to +infinity. It only fails if ALL actuals are zero (the entire series is zeros), which is a degenerate case.
Critically, wMAPE naturally weights errors by their economic importance: a 10\% error on a \$1M product contributes more than a
10\% error on a \$100 product, because the absolute error is larger.

\textbf{When to use wMAPE?}

Use wMAPE in retail and supply chain forecasting where you need a percentage metric but individual SKUs can have zero sales.
It's the go-to metric when you want each item's error weighted by its revenue contribution. Avoid when you need each observation
weighted equally regardless of magnitude (use MAPE), or when you need a baseline comparison (use MASE).

% strength and weakness box
\coloredboxes{
    \item Immune to MAPE's zero-denominator problem. Individual zeros in the actuals don't cause infinity — they simply contribute their absolute error to the numerator.
    \item Naturally revenue-weighted. High-value items dominate the score, which aligns with business priority: a 5\% miss on your top product matters more than a 50\% miss on a niche item.
}
{
    \item Not a true per-item percentage. wMAPE = 8\% doesn't mean ``each prediction is 8\% off'' — it means ``total error is 8\% of total actuals.'' Individual items can be much worse.
    \item Dominated by high-volume items. If your top product has good predictions but small products are terrible, wMAPE can mask the problem.
}

% ---------- MASE ----------
\clearpage
\thispagestyle{regressionstyle}
\section{MASE}
\subsection{Mean Absolute Scaled Error}

MASE answers the question: ``Is my model better than simply predicting tomorrow's value as today's value?'' It divides your model's
MAE by the MAE of this naive ``random walk'' forecast. MASE $<$ 1 means your model adds value; MASE $>$ 1 means you'd be better off
with no model at all. This makes MASE the gold standard for comparing forecasts across different time series.
% formula
\vspace{0.5em}
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                MASE = \frac{1}{{\color{nmlred}n}} \sum_{t=1}^n \frac{|{\color{nmlcyan}Y_t} - {\color{nmlpurple}\hat{Y}_t}|}{\frac{1}{n-1} \sum_{t=2}^n |{\color{nmlcyan}Y_t} - {\color{nmlcyan}Y_{t-1}}|}
                $
            }
        };
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-1.5,0.2)$) to[bend left=15] node[pos=1, left] {number of samples} +(-1,-.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.4,-0.3)$) to[bend left=15] node[pos=1, right] {forecast value} +(1,.5);
        \draw[overlay,-latex,nmlcyan,semithick] ($(a.north)+(1.2,-0.3)$) to[bend right=15] node[pos=1, left] {actual value} +(-1,.5);
    }
\end{center}
\vspace{0.5em}
MASE = 0.6 means your model's errors are 40\% smaller than the naive baseline. MASE = 1.2 means your model is 20\% worse.
Unlike MAPE, MASE never divides by individual actuals, so it handles zeros and intermittent demand gracefully.

\textbf{When to use MASE?}

Use MASE when comparing forecast accuracy across multiple time series with different scales (e.g., forecasting 100 SKUs simultaneously).
It's the recommended metric for intermittent demand (many zeros) where MAPE/sMAPE fail. Avoid for non-time-series problems where
a naive lag-1 baseline is meaningless.

% strength and weakness box
\coloredboxes{
    \item No division-by-zero problems. MASE divides by the mean of the naive forecast's errors, not individual actuals. Handles zeros, intermittent demand, and small values cleanly.
    \item Built-in baseline comparison. MASE $<$ 1 means ``better than naive,'' MASE $>$ 1 means ``worse than naive.'' No need for a separate benchmark.
}
{
    \item Requires time-ordered data. The naive forecast ($Y_{t-1}$) only makes sense for time series. For cross-sectional data (e.g., predicting house prices), MASE is not applicable.
    \item Harder to explain to stakeholders than MAPE. ``Our model is 0.7 MASE'' doesn't have the immediate clarity of ``our model is 5\% off.''
}

\clearpage
\thispagestyle{customstyle}

\orangebox{Did you know that...}
{MASE was proposed by Hyndman and Koehler (2006) specifically because every existing error metric had a fatal flaw for comparing across
time series: MAE is scale-dependent, MAPE explodes at zeros, and RMSE is dominated by series with larger values. MASE was designed
from scratch to have none of these problems. It's now the recommended metric in Hyndman's influential \textit{Forecasting: Principles and Practice}.}

\textbf{Other related metrics}

MASE is most commonly compared with MAPE and sMAPE. Unlike MAPE, MASE avoids division-by-zero issues and provides a meaningful comparison against a naive forecast baseline.
For directional accuracy, consider MDA.

% ---------- MDA ----------
\clearpage
\thispagestyle{regressionstyle}
\section{MDA}
\subsection{Mean Directional Accuracy}

In many applications, predicting the \textit{direction} of change matters more than the exact magnitude. A stock trader doesn't need to know
the price will be \$152.37 — they need to know it will go \textit{up}. MDA measures exactly this: what fraction of the time does your model
correctly predict whether the target will increase or decrease?

% formula
\vspace{0.5em}
\begin{center}
    \tikz{
    \node[inner sep=2pt, font=\Large] (a) {
        {
            $\displaystyle
            MDA = \frac{1}{{\color{nmlred}n}} \sum_{t=1}^{n} {\color{nmlgreen}\mathds{1}}_{{\color{nmlyellow}sign}({\color{nmlcyan}y_t} - {\color{nmlcyan}y_{t-1}}) == {\color{nmlyellow}sign}({\color{nmlpurple}\hat{y}_t} - {\color{nmlcyan}y_{t-1}})}
            $
        }
    };

    % Draw arrows for annotations
    \draw[overlay,-latex, nmlred, semithick] ($(a.south)+(-2.4,0.4)$) to[bend left=15] node[pos=1, left] {number of samples} +(-1,-.5);
    \draw[overlay,-latex,nmlcyan,semithick] ($(a.north)+(0.2,-0.3)$) to[bend right=15] node[pos=1, left] {actual value} +(-1,.5);
    \draw[overlay,-latex, nmlpurple, semithick] ($(a.north)+(3,-0.3)$) to[bend left=15] node[pos=1, right] {forecast value} +(1,.5);
    \draw[overlay,-latex, nmlgreen, semithick] ($(a.south)+(-0.2,0.6)$) to[bend left=15] node[pos=1, left] {indicator} +(-0.8,-.5);
    \draw[overlay,-latex, nmlyellow, semithick] ($(a.south)+(2.6,0.5)$) to[bend right=15] node[pos=1, right] {sign function} +(1,-.5);
    }
\end{center}
\vspace{0.5em}

MDA ranges from 0 to 1. MDA = 0.5 means your model is no better than a coin flip at predicting direction. MDA = 0.6
means it gets the direction right 60\% of the time. In financial markets, even MDA = 0.55 can be profitable if
combined with proper position sizing.

\textbf{When to use MDA?}

Use MDA in financial forecasting (stock direction, FX movements), energy price prediction, or any domain where the cost of being
wrong about direction exceeds the cost of being wrong about magnitude. Avoid when magnitude matters (use MAE/RMSE)
or when the time series is mostly flat (MDA becomes unstable on small changes).

% strength and weakness box
\coloredboxes{
    \item Scale-independent and magnitude-independent. A model predicting ``up by \$1'' and one predicting ``up by \$100'' get the same MDA credit if both correctly predict the direction.
    \item Binary interpretation. ``The model gets the direction right 65\% of the time'' requires no domain knowledge to understand.
}
{
    \item Ignores magnitude entirely. A model that correctly predicts ``up'' but estimates +\$1 when the actual move is +\$1000 gets full credit. Always pair MDA with a magnitude metric like MAE.
    \item Sensitive to flat periods. When the target barely changes, small noise can flip the sign, making MDA unreliable.
}

\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/MDA_trading_example.png}
\end{figure*}

\textbf{Figure. MDA in a trading context.} Blue/red shading shows correct/incorrect direction predictions. The forecast
(blue line) doesn't need to match the price exactly — it just needs to predict whether the next move is up or down. This model achieves
MDA = 0.68, meaning it gets the direction right about 2/3 of the time.

\orangebox{Did you know that...}
{A model with MDA = 0.50 is equivalent to random guessing. But in financial markets, even a small edge matters: a model with MDA = 0.55
that correctly sizes its positions can be highly profitable. This is why hedge funds track directional accuracy alongside
traditional error metrics — and why MDA alone is never sufficient without a magnitude metric like MAE.}

\textbf{Other related metrics}

MDA focuses solely on directional accuracy. For magnitude-based evaluation, use MAE or RMSE. For a scale-independent comparison to a baseline forecast, consider MASE.

% ---------- MPD ----------
\clearpage
\thispagestyle{regressionstyle}
\section{MPD}
\subsection{Mean Poisson Deviance}

MPD is a metric used to evaluate the performance of regression models when the target variable follows a Poisson distribution. This distribution is common for count data, such as the number
of events occurring in a fixed time or space (e.g., website clicks per hour, phone calls received per day).

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{MPD} = \frac{1}{{\color{nmlred}n}} \sum_{t=1}^{n} 2 \left( {\color{nmlcyan}Y_t} \log \left( \frac{{\color{nmlcyan}Y_t}}{{\color{nmlpurple}\hat{Y}_t}} \right) - ( {\color{nmlcyan}Y_t} - {\color{nmlpurple}\hat{Y}_t} ) \right)
                $
            }
        };
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-2.2,0.2)$) to[bend left=15] node[pos=1, left] {number of samples} +(-1,-0.5);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.3,0.0)$) to[bend left=15] node[pos=1, right] {actual value} +(1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.3,0)$) to[bend right=15] node[pos=1, right] {predicted value} +(1,-0.5);
    }
\end{center}

MPD ranges from 0 (perfect) to $+\infty$. There's no universal ``good'' threshold --- compare your model's MPD against a baseline that predicts the training mean count. MPD is undefined at $Y_t=0$ unless you adopt the convention $0\log 0 = 0$ (which scikit-learn does).

\textbf{When to use MPD?}

Use MPD for insurance claim frequency, ad click counts, support-ticket arrivals, defect counts --- anywhere your target is non-negative integers with variance proportional to the mean. Avoid MPD when targets are heavily zero-inflated (use Tweedie deviance) or when business cost is in absolute units, not relative ones (use MAE).

% strength and weakness box
\coloredboxes{
    \item Scales with the count. $\text{MPD}(y{=}100, \hat{y}{=}150) \approx 20.3$ while $\text{MPD}(y{=}1, \hat{y}{=}1.5) \approx 0.2$ --- the same 50\% miss is penalized in proportion to the count, matching Poisson variance.
    \item Native loss for Poisson GLMs. \texttt{PoissonRegressor} and XGBoost with \texttt{objective="count:poisson"} already optimize MPD --- no train/eval mismatch.
}
{
    \item Predictions must be strictly positive --- $\log(\hat{y})$ blows up at zero. Clip predictions to a small floor or use a model with a log link.
    \item Heavily zero-inflated data makes MPD dominated by the few non-zero rows. Use Tweedie deviance with $1<p<2$ instead.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/MPD_cross_section.png}
\end{figure*}

\textbf{Figure. MPD} as a function of predicted value when $Y=10$. The asymmetric V is the practical takeaway: predicting 5 when the truth is 10 costs more deviance than predicting 15. This matches the business reality of most count problems --- undercounting alerts, tickets, or claims is usually more costly than overcounting them.

\orangebox{Did you know that...}
{MPD is twice the gap between the model's log-likelihood and that of a saturated model that fits every point exactly. Minimizing MPD is therefore maximum-likelihood estimation under Poisson assumptions --- which is why \texttt{PoissonRegressor} optimizes MPD directly. Train and eval use the same metric, eliminating loss/score mismatch.}

\textbf{Other related metrics}

MPD, MGD, and Tweedie deviance all live in the same exponential family --- pick based on variance structure: $\propto$ mean (MPD), $\propto$ mean$^2$ (MGD), or between (Tweedie). If MPD ranks two models very differently from MAE, the model with worse MPD is usually biased on high-count rows --- check residuals conditional on predicted count.

% ---------- MGD ----------
\clearpage
\thispagestyle{regressionstyle}
\section{MGD}
\subsection{Mean Gamma Deviance}

MGD is a metric for evaluating regression models when the target variable follows a Gamma distribution. This distribution is often used for modeling continuous positive data with a
positive right-skewed distribution, such as insurance claims, response times, or medical expenditures.

% formula
\begin{center}
    \tikz{
    \node[inner sep=2pt, font=\Large] (a) {
        {
            $\displaystyle
            \text{MGD} = \frac{1}{{\color{nmlred}n}} \sum_{t=1}^{n} 2 \left( \log\left(\frac{{\color{nmlpurple}\hat{y}_t}}{{\color{nmlcyan}y_t}}\right) + \frac{{\color{nmlcyan}y_t}}{{\color{nmlpurple}\hat{y}_t}} - 1 \right)
            $
        }
    };
    
    \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-2.5,0.2)$) to[bend left=15] node[pos=1, left] {number of samples} +(-1,-.5);
    \draw[overlay,-latex, nmlcyan, semithick] ($(a.north)+(1.2,-0.2)$) to[bend left=15] node[pos=1, right] {actual value} +(1,.5);
    \draw[overlay,-latex, nmlpurple, semithick] ($(a.south)+(1.2,0.2)$) to[bend right=15] node[pos=1, right] {predicted value} +(1,-.5);
}
\end{center}

MGD ranges from 0 to +infinity, with 0 indicating a perfect model fit for continuous positive data.

\textbf{When to use MGD?}

Use MGD for claim severity, customer lifetime value, repair costs, latency/duration models --- anything strictly positive and right-skewed. Avoid MGD when targets can be zero (Gamma is undefined at 0 --- use Tweedie deviance) or when business cost is in absolute, not relative, units (use MAE or RMSE).

% strength and weakness box
\coloredboxes{
    \item MGD is tailored for right-skewed data. It handles continuous positive data with increasing variance efficiently.
    \item MGD penalizes predictions proportionally to the magnitude of the target variable, e.g., \( MGD(y=100, \hat{y}=150) = MGD(y=1.0, \hat{y}=1.5) \).
}
{
    \item Targets as well as predictions must be strictly positive, limiting the metric’s compatibility with some models.
    \item Not appropriate for data that doesn't follow a Gamma-like structure.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/MGD_cross_section.png}
\end{figure*}

\textbf{Figure. MGD} as a function of predicted value when $Y=10$. The minimum sits at $\hat{Y}=10$ and the penalty rises steeply for under-prediction but gently for over-prediction --- predicting half the truth ($\hat{Y}=5$) costs $\approx 1.6\times$ more than predicting double ($\hat{Y}=20$). MGD depends only on the ratio $\hat{Y}/Y$, so the curve's shape is set by relative error, not absolute. For insurance pricing this is the right behavior, since reserving too little is worse than reserving too much.

\orangebox{Did you know that...}
{MGD is scale-invariant: multiplying all targets and predictions by any positive constant leaves the score unchanged. Practically, a model trained on dollars scores identically when retrained on cents. This is unique to Gamma deviance --- MAE, MSE, MPD, and RMSE all change under rescaling. It's also why MGD is the standard loss in actuarial pricing, where the same model needs to work across several orders of magnitude.}

\textbf{Other related metrics}

MGD and MPD are both Tweedie-family losses --- the choice is set by your target's variance: $\propto$ mean (MPD), $\propto$ mean$^2$ (MGD), or in between (Tweedie, $1<p<2$). If MGD and RMSE rank models differently, MGD is rewarding the one calibrated in relative terms while RMSE rewards absolute calibration --- pick by which one matches your loss function. For combined frequency $\times$ severity (insurance), Tweedie is usually the right answer.

% ---------- R-squared ----------
\clearpage
\thispagestyle{regressionstyle}
\section{R-squared}
\subsection{R-squared}

R-squared answers the most fundamental question in regression: ``How much better is my model than simply predicting the mean?''
An R² of 0.85 means your model explains 85\% of the variance in the target — the remaining 15\% is unexplained noise or missing features.
This normalized 0-to-1 scale (usually) makes it the only regression metric you can interpret without knowing the target's units.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                R^2 = 1 - \frac{\sum_{t=1}^n (Y_t - {\color{nmlpurple}\hat{Y}_t})^2}{\sum_{t=1}^n ({\color{nmlcyan}Y_t} - {\color{teal!70!green}\bar{Y}})^2}
                $
            }
        };
        
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.1,0)$) to[bend left=15] node[pos=1, right] {Predicted value} +(1,.5); 
        \draw[overlay,-latex,teal!70!green, semithick] ($(a.south)+(2.1,0.1)$) to[bend right=15] node[pos=1, right] {Mean of targets} +(1,-.5); 
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(1,0.1)$) to[bend left=15] node[pos=1, left] {Target value} +(-1,-.5); 
    }
\end{center}

R² = 1 is perfect, R² = 0 means your model is no better than predicting the mean, and R² $<$ 0 means it's actively worse.
That last point trips people up: in production, a negative R² is a red flag — your model has degraded below baseline and should not be serving predictions.

\textbf{When to use R-squared?}

Use R² when you need a normalized metric to compare models across different targets or datasets — ``Model A explains 85\% of variance
on dataset X'' is meaningful without knowing X's scale. Avoid relying on R² alone for model selection: a model with R²=0.95 and
terrible tail predictions can be worse than one with R²=0.90 but uniform errors. Always pair R² with RMSE or MAE.

\enlargethispage{\baselineskip}
\coloredboxes{
    \item Scale-free. R² = 0.85 means the same thing whether you're predicting nanometers or light-years. This makes it the standard metric for cross-dataset comparison.
    \item Built-in baseline. R² = 0 is the ``predict the mean'' baseline. Unlike RMSE, you don't need to compute a separate naive model to know if yours adds value.
}
{
    \item R² can be misleadingly high. Adding features always increases R² on training data, even irrelevant ones. Use Adjusted R² (which penalizes extra features) for model selection.
    \item Sensitive to the choice of $\bar{Y}$. Using the test set mean ($\bar{Y}_{test}$) causes information leakage. Always use $\bar{Y}_{train}$ for honest evaluation.
}


\clearpage
\thispagestyle{customstyle}

\begin{center}
    \includegraphics[width=\textwidth]{figures/R2_explained.png}
\end{center}

\textbf{Figure. R² as a ratio of squared-error areas.} Left: the model's residuals drawn as purple squares (side $=|y_i - \hat{y}_i|$, so area $=$ squared error). Their total area is $SS_\text{res}$. Right: the same points but residuals are measured against the mean baseline — red squares with total area $SS_\text{tot}$. R² is one minus the ratio of the two areas. When the purple squares would be \textit{larger} than the red ones — i.e., the model is worse than predicting the mean — R² goes negative.


\orangebox{Did you know that...}
{R² is mathematically equivalent to $1 - MSE_{model}/MSE_{baseline}$, where the baseline always predicts the mean.
This means R² and MSE contain the exact same information — R² just rescales MSE to a 0-1 range. The practical implication:
if R² improves by 0.01, you can calculate exactly how many units of MSE that saved.}

\textbf{Other related metrics}

Adjusted R² penalizes adding features that don't improve the model — use it for feature selection. If R² is high on training
but low on test, your model is overfitting. For absolute-error-based evaluation, pair R² with MAE. For outlier-robust
alternatives, consider the D2 Absolute Score.



% ---------- D2 ----------
\clearpage
\thispagestyle{regressionstyle}
\section{D2}
\subsection{D2 Absolute Score}

The D-squared Absolute Score is a regression evaluation metric that measures the proportion of variance explained by a model, using the absolute deviations between predictions and true values. 
It serves as an alternative to traditional R-squared but focuses on the absolute differences rather than squared differences, making it more robust to outliers.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                D^2_{abs} = 1 - \frac{\sum_{t=1}^n \lvert {\color{nmlcyan}Y_t} - {\color{nmlpurple}\hat{Y}_t}\rvert}{\sum_{t=1}^n \lvert{\color{nmlcyan}Y_t} - {\color{teal!70!green}\bar{Y}}\rvert}
                $
            }
        };
        
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.3,0)$) to[bend left=15] node[pos=1, right] {Predicted value} +(1,.5); 
        \draw[overlay,-latex,teal!70!green, semithick] ($(a.south)+(2.3,0.1)$) to[bend right=15] node[pos=1, right] {Mean of targets} +(1,-.5); 
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(1.2,0.1)$) to[bend left=15] node[pos=1, left] {Target value} +(-1,-.5); 
    }
\end{center}

The D-squared Absolute Score lies in the range of -infinity and 1, where 1 represents a perfect model, 0 indicates no improvement over a naive model,
and negative values imply the model performs worse than the naive baseline.

\textbf{When to use D-squared}

Use D2 Absolute Score for heavy-tailed targets where R-squared is unstable --- house prices, claim severity, click-through revenue. Avoid D2 when large errors are disproportionately costly (use R-squared or RMSE).

\coloredboxes{
    \item Outlier-robust. Adding one extreme test point can swing R-squared by 0.1+; D2 barely moves. This makes D2 the more reliable score for small or heavy-tailed test sets.
    \item Built-in baseline like R-squared. $D^2=0$ means ``no better than predicting the median'' --- no separate naive model needed to judge whether your model adds value.
}
{
    \item Linear penalty hides catastrophic errors. A model off by 10 on one prediction and 0 on 99 others scores the same as one off by 0.1 on all 100. If a single large miss hurts disproportionately, use R-squared or RMSE.
    \item Be cautious about which value of $\bar{Y}$ to use. Most implementations default to $\bar{Y}_{\text {test }}$ which can lead to information leakage. It is advisable to use $\bar{Y}_{\text {train }}$ instead.
}

{The D-squared framework generalizes R-squared to arbitrary deviance functions. Using absolute deviations instead of squared differences makes D2 Absolute Score equivalent
to the proportion of absolute variance explained. In scikit-learn, this is available as \texttt{d2\_absolute\_error\_score}.}

\textbf{Other related metrics}

D2 and R-squared should agree closely on well-behaved data. A large gap (e.g., R$^2$=0.60 but D2=0.85) signals a few outliers are dragging R-squared down --- investigate the largest residuals before trusting either score. For squared-error evaluation, use R-squared. For probabilistic classification, see D-squared Log Loss in Chapter 3.

\thispagestyle{regressionstyle}
\section{Pinball Loss}
\subsection{Pinball Loss }

Most metrics evaluate point predictions (``the price will be \$50''). Pinball Loss evaluates quantile predictions (``there's a 90\%
chance the price will be below \$60''). It asymmetrically penalizes errors based on the quantile: at $q=0.9$, under-predicting
is penalized 9x more than over-predicting, because missing the upper bound of a prediction interval is more costly.

% formula
\begin{center}
    \tikz{
		\node[inner sep=2pt, font=\Large] (a) {
			{
				$\displaystyle
				L_{{\color{nmlred}q}}({\color{nmlcyan}Y}, {\color{nmlpurple}\hat{Y}}) = 
                \begin{cases} 
                    {\color{nmlred}q} \cdot ({\color{nmlcyan}Y} - {\color{nmlpurple}\hat{Y}}), & \text{if } {\color{nmlcyan}Y} \geq {\color{nmlpurple}\hat{Y}}, \\[10pt]
                    (1 - {\color{nmlred}q}) \cdot ({\color{nmlpurple}\hat{Y}} - {\color{nmlcyan}Y}), & \text{if } {\color{nmlcyan}Y} < {\color{nmlpurple}\hat{Y}}
                \end{cases}
                $
			}
		};
		% Adjusted arrows
		\draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-0.7,0.2)$) to[bend left=20] node[pos=1, left] {quantile} +(-1,-.5);
		\draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(-0.8,-0.1)$) to[bend right=20] node[pos=1, left] {actual value} +(-1,.5);
		\draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(0.4,-0.1)$) to[bend left=20] node[pos=1, right] {predicted value} +(1,.5); 
	}
\end{center}

Pinball Loss ranges from 0 (perfect) to +infinity. The key insight: at $q=0.5$, Pinball Loss reduces to MAE/2 (symmetric).
At $q=0.9$, it penalizes under-predictions 9x more than over-predictions. This is exactly what you want for upper prediction bounds.

\textbf{When to use Pinball Loss?}

Use Pinball Loss for evaluating prediction intervals, probabilistic forecasts, and any scenario with asymmetric costs.
Examples: energy grid planning ($q=0.95$ — underestimating demand causes blackouts), inventory management ($q=0.9$ —
stockouts are worse than overstock), risk management (VaR at $q=0.99$). Avoid for point prediction evaluation (use MAE/RMSE).

\coloredboxes{
    \item Customizable asymmetry. By setting $q$, you encode your business's cost structure directly into the metric. $q=0.9$ means ``it's 9x worse to under-predict.''
    \item Evaluates the full prediction distribution. By computing Pinball Loss at multiple quantiles (0.1, 0.5, 0.9), you assess the entire predictive distribution, not just the point estimate.
}
{
    \item Requires the model to output quantile predictions, not just point estimates. Standard regression models need to be adapted (e.g., quantile regression, conformal prediction).
    \item The choice of $q$ requires domain knowledge. A poorly chosen quantile makes the metric irrelevant to the actual business cost.
}

    \includegraphics[width=0.50\textwidth]{figures/Pinball_Loss.png}
    \vspace{-10pt}
\end{wrapfigure}

The plot shows how the loss increases linearly with the difference between the predicted value $\hat{Y}$ and the actual value $Y$ for various quantiles, with the loss function being asymmetric around the prediction.

\orangebox{Did you know that...}
{Pinball Loss is also called Quantile Loss and is an L1 Loss when $q=0.5$.}

\textbf{Other related metrics}

At $q=0.5$, Pinball Loss reduces to MAE (scaled by 0.5). For evaluating mean predictions rather than quantile predictions, use MAE or MSE.
For interval forecasts, consider combining Pinball Loss at multiple quantiles.

% ---------- Explained Variance Score ----------
\clearpage
\thispagestyle{regressionstyle}
\section{Explained Variance Score}
\subsection{Explained Variance Score}

EVS measures whether your model captures the \textit{pattern} in the data, even if predictions are systematically shifted.
A model that predicts $[8, 9, 10, 11]$ when the actual is $[1, 2, 3, 4]$ gets EVS = 1.0 (perfect pattern) but R² $\ll$ 0 (terrible
absolute accuracy). This makes EVS useful when you care about relative dynamics more than absolute calibration.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{EVS} = 1 - \frac{\text{Var}({\color{nmlcyan}Y} - {\color{nmlpurple}\hat{Y}})}{\text{Var}({\color{nmlcyan}Y})}
                $
            }
        };
        
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.2,0)$) to[bend right=15] node[pos=1, left] {actual value} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.3,0)$) to[bend left=15] node[pos=1, right] {predicted value} +(1,.5); 
    }
\end{center}

EVS ranges from $-\infty$ to 1. EVS = R² when the mean residual is zero (no bias). When EVS $>$ R², it signals that your model
captures the right patterns but has a systematic offset — a simple bias correction could dramatically improve R².

\textbf{When to use Explained Variance Score?}

Use EVS to diagnose whether a poor R² is due to wrong patterns (both EVS and R² are low) or just a constant offset
(EVS is high but R² is low — fix by recalibrating). Common in sensor data, financial models, and transfer learning
where systematic bias is expected and correctable. Avoid as a standalone metric — always pair with R² or MAE.

\coloredboxes{
    \item Diagnostic power. EVS $\gg$ R² tells you the model's patterns are correct but predictions need a bias correction. This is actionable: add a constant offset and R² improves immediately.
    \item Identical to R² for unbiased models. When mean(residuals) = 0, EVS = R² exactly. So EVS only matters when you suspect systematic bias.
}
{
    \item Ignores systematic offset. A model predicting $\hat{Y} = Y + 1000$ gets EVS = 1.0, which is dangerously misleading if taken at face value.
    \item Rarely used as a primary metric. In practice, if your model has systematic bias, fix the bias rather than reporting a metric that ignores it.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=\textwidth]{figures/EVS_vs_R2_three_models.png}
\end{figure*}

\textbf{Figure. EVS vs R² across three models.} The good model (left) has EVS $\approx$ R² — no bias. The biased model (center) has
EVS = 1.00 but R² = -1.77 — perfect pattern but constant offset. The noisy model (right) has both metrics low — the pattern itself
is wrong. The diagnostic: if EVS $\gg$ R², recalibrate your model; if both are low, retrain.

\orangebox{Did you know that...}
{The mathematical relationship is: EVS = R² + (mean of residuals)$^2$ / Var($Y$). So EVS $-$ R² directly measures how much of the R² gap
is caused by bias vs noise. If EVS $-$ R² is large, a simple offset correction will recover most of the missing R². If EVS $\approx$ R², the
problem is variance, not bias.}

\textbf{Other related metrics}

If EVS shows your model has the right patterns but a bias, apply a constant offset and re-evaluate with R². For outlier-robust
evaluation, use D2 Absolute Score. For a deeper diagnostic, decompose MSE into bias² + variance + noise terms.
