\chapteropener{GenAI}{purplehard}{purpleaccent}{%
Generative AI models produce text, images and speech. For many of these tasks, there is more than one acceptable output, so checking
for an exact match is too restrictive. We need to assess qualities such as how well an output follows a prompt, preserves meaning or
resembles real examples.

The metrics in this chapter measure these qualities in different ways. Some compare an output with a reference, such as a human-written
answer, while others compare collections of generated and real examples. We also look at how well a language model predicts text,
whether an image matches its prompt, and how listeners rate speech quality.

We begin with text, then move to images and speech. The final pages trace several influential benchmarks, explaining what they tested
and how they changed as models improved.}{In this chapter}

% ---------- Perplexity ----------
\clearpage
\thispagestyle{genaistyle}
\metricentry{Perplexity}{Perplexity}\label{sec:perplexity}

% reference:
% https://aclanthology.org/2021.deelio-1.5.pdf
% https://kilthub.cmu.edu/articles/journal_contribution/Evaluation_Metrics_For_Language_Models/6605324/1?file=12095765
% https://huggingface.co/docs/transformers/perplexity
% https://brenocon.com/blog/2013/01/perplexity-as-branching-factor-as-shannon-diversity-index/
% https://arxiv.org/abs/1904.09751 (Holtzman et al., The Curious Case of Neural Text Degeneration)

Perplexity measures how well a language model predicts a piece of text. At each step, the model assigns probabilities to possible
next tokens, which can be words or word pieces. We check the probabilities it gives to the tokens that actually appear in the text:
the higher those probabilities, the lower the perplexity.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{PPL} = \exp\left(-\frac{1}{{\color{nmlred}N}} \sum_{i=1}^{N} \log {\color{nmlcyan}p}({\color{nmlpurple}w_i} \mid w_{<i})\right)
                $
            }
        };

        \draw[-latex,nmlred, semithick] ($(a.south)+(-0.54,0.34)$) to[bend left=15] node[pos=1, left] {sequence length} +(-1.00,-0.45);
        \draw[-latex,nmlcyan, semithick] ($(a.north)+(1.55,-0.74)$) to node[pos=1, above] {model probability} +(0.00,0.85);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(2.08,0.63)$) to node[pos=1, below] {token at position $i$} +(0.00,-0.33);
    }
\end{metricformula}

It runs from $1$ (certain) to the vocabulary size (uniform guessing) and beyond. The average sits inside the exponential, so it is a
geometric mean of $1/p$: one token at $p = 10^{-6}$ costs $13.8$ nats, as much as a dozen ordinary tokens at $p \approx 0.3$.

\metricheading{When to use}

Use it to compare checkpoints or data mixes with a fixed tokenizer and evaluation text, or to flag distribution shift when incoming-text perplexity jumps. For generated samples, use MAUVE or human ratings. It does not apply directly to masked models like BERT; compare tokenizers using bits per byte.


\coloredboxes{
\item Cheap and label-free: one forward pass over held-out text, and lower is strictly a better fit to that text.
\item Fine-grained. A drop from $20$ to $19$ is about a $5\%$ rise in the geometric-mean token probability, so it can reveal changes a
coarse benchmark misses.
}
{
\item Tokenizer-dependent. Changing what counts as one token changes both the number of predictions and their unit. Compare bits per byte
instead.
\item Held-out fit is not sample quality. A model can assign high likelihood to repetitive continuations, so lower perplexity on human
text does not guarantee better generations.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/Perplexity_surprisal.png}
\end{metricfigure}

\metriccaption{Figure. Perplexity.}{GPT-2's surprisal $-\log p$ per token; the dashed line is the mean and perplexity is its exponential.
Expected tokens (``el'', ``Tower'') cost nothing, and ``Eiffel'' is three tokens because the tokenizer has no single piece for it.
Swapping one word costs $10.1$ nats for ``Ohio'' ($p = 0.00004$), makes ``France'' a surprise too, and nearly triples the perplexity,
from $8.3$ to $23.1$.}

\orangebox{Did you know that...}
{Holtzman et al. (2020) gave GPT-2 a prompt and compared the likelihood of its beam-search continuation with the real continuation. The
model assigned more probability to its own repetitive text. This differs from held-out perplexity, which averages probabilities over a
fixed collection of human text, but it exposes a related problem: always choosing the most likely continuation produces loops and
clichés because human writing includes less predictable choices. Predictive fit and generated-text quality can therefore move
differently.}

\metricheading{Related metrics}\metricsecondary

BLEU and ROUGE (NLP chapter) measure overlap with a reference; MAUVE compares generated and human-text distributions. If held-out
perplexity falls while MAUVE stays flat, predictive fit improved but this MAUVE evaluation found no corresponding distributional
improvement in the samples. Inspect the generations and decoding setup before drawing a conclusion. For masked models,
pseudo-perplexity scores each token while masking it in turn.

% ---------- BERTScore ----------
\metricend
\clearpage
\thispagestyle{genaistyle}
\metricentry{BERTScore}{BERTScore}\label{sec:bertscore}

% reference:
% https://arxiv.org/pdf/1904.09675
% https://github.com/Tiiiger/bert_score (default layers, baseline rescaling, hash codes)

BERTScore measures how closely generated text matches a reference in meaning. It uses a pretrained language model to compare words
in context, so different wording can still receive a high score. For example, ``the physician postponed the operation'' and ``the
doctor delayed the surgery'' describe the same event with different words.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                R_{\text{BERT}} = \frac{1}{{\color{nmlred}|x|}} \sum_{{\color{nmlcyan}x_i} \in x} \max_{{\color{nmlpurple}\hat{x}_j} \in \hat{x}} {\color{nmlcyan}x_i}^{\top} {\color{nmlpurple}\hat{x}_j}
                $
            }
        };

        \draw[-latex,nmlred, semithick] ($(a.south)+(-0.63,0.27)$) to[bend left=15] node[pos=1, left] {reference length} +(-1.00,-0.55);
        \draw[-latex,nmlcyan, semithick] ($(a.north)+(1.90,-0.49)$) to node[pos=1, above] {reference token embedding} +(0.00,0.55);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(2.60,0.59)$) to node[pos=1, below] {candidate token embedding} +(0.00,-0.65);
    }
\end{metricformula}

$R_{\text{BERT}}$ is recall: each reference token finds its best candidate match. Unit-normalized embeddings make the dot product a cosine. Precision reverses the matching; $F_{\text{BERT}}$ is their harmonic mean. Raw scores crowd near the top; optional rescaling uses a random-pair baseline. Here $0.875$ is raw similarity, not $87.5\%$ correct.

\metricheading{When to use}

Use it for summarization, translation and paraphrase evaluation when good outputs can differ in wording from their references. Check exact numbers, names and code directly. Without matched references, compare collections with MAUVE or use a model judge.


\coloredboxes{
\item Rewards paraphrase: the example scores $F_{\text{BERT}} = 0.875$ despite changing every content word; unigram precision is
$0.40$ (figure).
\item Token-level. The matching matrix shows which reference words went unmatched, so a low score points to a specific omission.
}
{
\item Configuration-dependent. Report the model, layer, IDF weighting and baseline rescaling; each changes the scale.
\item Weak on word order and negation: swapping who did what to whom scores $0.90$, and inserting ``not'' still scores $0.84$,
because most token matches survive.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/BERTScore_matching.png}
\end{metricfigure}

\metriccaption{Figure. BERTScore.}{Raw cosine similarities between reference tokens (rows) and candidate tokens (columns) from
layer $9$ of bert-base-uncased, without baseline rescaling or IDF weighting. Each row's maximum (boxed) is that token's best match and
their mean is recall; column maxima (red dots) give precision. ``Doctor'' finds ``physician'' at $0.82$, so raw
$F_{\text{BERT}} = 0.875$ where unigram precision is $0.40$.}

\orangebox{Did you know that...}
{The embeddings BERTScore uses do not come from the model's last layer. The authors tuned the layer choice against human judgments and
found that the final layers, which specialize in the masked-word prediction task, correlate worse than the layers just below them:
roberta-large uses layer $17$ of $24$ by default and bert-base-uncased layer $9$ of $12$. Two teams reporting ``BERTScore'' with
different models or layers are reporting different metrics, which is why the reference implementation prints a hash of the full
configuration next to every score.}

\metricheading{Related metrics}\metricsecondary

BLEU, METEOR and ROUGE count surface overlap; BERTScore compares contextual similarity. Low BLEU with high BERTScore can indicate a paraphrase or hide a role swap or negation: inspect meaning, and check exact values separately. MAUVE compares collections, needing human reference texts but no matched reference per sample.

% ---------- MAUVE ----------
\metricend
\clearpage
\thispagestyle{genaistyle}
\metricentry{MAUVE}{MAUVE}\label{sec:mauve}

% reference:
% https://arxiv.org/pdf/2212.14578
% https://arxiv.org/pdf/2102.01454
% https://krishnap25.github.io/mauve/

MAUVE compares collections of generated and human texts from the same setting. It groups texts by language-model features and compares each group's frequency. This can reveal missing variety or unusual outputs without a matched reference for each generated text.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{MAUVE} = \text{AUC}\Big\{\big({\color{nmlpurple}x_\lambda},\, {\color{nmlcyan}y_\lambda}\big)\Big\}_{\lambda \in (0,1)}
                $
            }
        };
        \node[below=0.15cm of a, inner sep=2pt, font=\normalsize] (b) {
            ${\color{nmlpurple}x_\lambda} = e^{-c\,\text{KL}({\color{nmlpurple}Q}\,\|\,{\color{nmlred}R_\lambda})}, \quad
              {\color{nmlcyan}y_\lambda} = e^{-c\,\text{KL}({\color{nmlcyan}P}\,\|\,{\color{nmlred}R_\lambda})}, \quad
              {\color{nmlred}R_\lambda} = \lambda\,{\color{nmlcyan}P} + (1-\lambda)\,{\color{nmlpurple}Q}$
        };

        \draw[-latex,nmlpurple, semithick] ($(b.north)+(-2.98,-0.05)$) to[bend right=15] node[pos=1, left] {model text} +(-1.00,0.30);
        \draw[-latex,nmlcyan, semithick] ($(a.north)+(1.50,-0.40)$) to node[pos=1, above] {human text} +(0.00,0.42);
        \draw[-latex,nmlred, semithick] ($(b.south)+(1.80,0.09)$) to[bend left=15] node[pos=1, left] {mixture of the two} +(-1.00,-0.30);
    }
\end{metricformula}

Each $\lambda$ mixes the distributions to give one curve point. The reference implementation adds $(0,1)$ and $(1,0)$ for integration; the sweep need not reach them. Identical histograms score $1$. Model-only mass lowers the horizontal coordinate; missing human-text mass lowers the vertical one.

\metricheading{When to use}

Use it to compare open-ended generation under the same human corpus, sample count, feature model and settings. Aim for at least
$1{,}000$ texts per side, preferably a few thousand; repeat smaller evaluations and report their variation. For short outputs with
matched references, use BERTScore or BLEU.


\coloredboxes{
\item Sees quality and diversity together. In Pillutla et al.'s $2021$ GPT-2 web-text experiment, greedy decoding scored about $0.012$
and nucleus sampling $0.936$ under the same setup.
\item Needs no matched reference for each output: only a human reference collection from the same setting and an embedding model.
}
{
\item Sample-hungry. Small evaluations can look too good and vary between runs; the follow-up recommends at least $1{,}000$ texts per
side and uses $5{,}000$.
\item Measures the embedding's view: length or topic differences can lower the score, and the embedding model and $k$ change it.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/MAUVE_frontier.png}
\end{metricfigure}

\metriccaption{Figure. MAUVE.}{\textit{Left:} human text $P$ (gray) and three model distributions $Q$ over eight embedding clusters.
\textit{Right:} the curve each model produces as $\lambda$ changes, completed with the two boundary points used for integration; MAUVE is the
area under its curve with $c = 5$, shaded for one model. A model close to the human histogram fills the square (rounding to $1.00$); one with a quarter of its mass on clusters no
human text falls in loses area along the horizontal axis; one that writes only the three commonest kinds of text loses it along the
vertical axis.}

\orangebox{Did you know that...}
{MAUVE is built like ROC AUC. A plain KL divergence between the two histograms is infinite whenever the model puts mass in a bucket
humans never use, or the reverse, so instead of one divergence the score sweeps a mixture from all-model to all-human and records two
finite divergences at each step, one per kind of error. The curve is a trade-off frontier, junk on one axis and lost diversity on the
other, and the area under it summarizes both, as ROC AUC summarizes false positives and negatives across thresholds. The shape of the
curve says which way a model fails.}

\metricheading{Related metrics}\metricsecondary

Perplexity measures how well the model predicts human text; MAUVE how well its samples resemble it, so one can improve while the other
stagnates. BERTScore compares one output to one reference. For images the same distribution-level idea is FID, which compares Gaussian
fits in feature space rather than histograms.

\thispagestyle{genaistyle}
\metricentry{IS}{Inception Score (IS)}\label{sec:is}

% reference:
% https://arxiv.org/abs/1606.03498 (Salimans et al., Improved Techniques for Training GANs)
% https://arxiv.org/abs/1801.01973 (Barratt & Sharma, A Note on the Inception Score)

Inception Score measures how confidently a classifier labels generated images and how varied its labels are across the set.
Inception-v3 supplies the class probabilities for each image, $p(y|x)$, and we average them across the set to get $p(y)$. High scores
require confident predictions spread across many classes.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{IS} = \exp\left(\mathbb{E}_{{\color{nmlpurple}x}} \left[{\color{nmlcyan}\text{KL}}(p(y|{\color{nmlpurple}x}) \| p(y))\right]\right)
                $
            }
        };
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(1.39,0.18)$) to[bend left=15] node[pos=1, left] {generated image} +(-1.00,-0.64);
        \draw[-latex,nmlcyan, semithick] ($(a.north)+(-0.13,-0.06)$) to[bend right=15] node[pos=1, left] {KL divergence} +(-1.00,0.30);
    }
\end{metricformula}

Scores range from $1$ (identical class-probability vectors for all images) to the classifier's class count ($1{,}000$ for ImageNet). Historical reports split samples into ten groups and report the mean and standard deviation of their scores. Each split estimates its own $p(y)$: fix the sample count, splits and classifier setup. That deviation is not an image-quality confidence interval.

\metricheading{When to use}

Use it to track classifier confidence and class coverage on ImageNet-like generations when no real reference set is available. It does
not measure blur or fidelity. With real samples, FID adds a distribution comparison but still needs task-specific and human checks; far
from ImageNet, choose a domain-relevant evaluator.


\coloredboxes{
\item Needs only generated images and a classifier. If every image receives the same probability vector, it equals $p(y)$ and the
score is exactly $1$ (figure).
\item Its scale reflects the effective separation of classifier labels, within that classifier.
}
{
\item Blind within a class: repeated memorized images can approach the maximum. Reference metrics may reveal the collapse, but can miss
it too.
\item Anchored to the classifier: realistic but ambiguous images can count as failures. Checkpoint, preprocessing, sample count and split
settings must match before comparing scores.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/IS_mechanism.png}
\end{metricfigure}

\metriccaption{Figure. Inception Score.}{Each row is one generated image's class distribution $p(y|x)$; the bottom row is their average, the
marginal $p(y)$. IS is the exponential of the mean KL divergence between rows and marginal, so it is high only when the rows are peaked
\emph{and} the marginal is flat: confident, diverse predictions reach $2.98$ of a possible $4$. Four equally confident predictions of
one class give $\text{IS} = 1$; uncertain predictions score only $1.06$ even though they cover all four classes.}

\orangebox{Did you know that...}
{The Inception Score is $\exp$ of a mutual information, $I(x;y) = H(y) - H(y|x)$: the label entropy across samples minus the average
entropy per sample. That reading explains the ceiling (a $1{,}000$-class network carries at most $\log 1{,}000$ nats, so
$\text{IS} \leq 1{,}000$), the loophole (one memorized image per class saturates it), and the dependence on the classifier. Real
CIFAR-10 images score about $11$ with the original TensorFlow weights and about a point and a half lower with the torchvision port,
a gap larger than many claimed improvements between GANs.}

\metricheading{Related metrics}\metricsecondary

IS and FID often move together during training. If IS rises while FID stalls, sharper predictions without broader coverage are one
possible explanation; inspect class coverage and repeated images before calling it collapse. For similarity of one image to one target,
use LPIPS.

% ---------- Fréchet Inception Distance ---------
\metricend
\clearpage
\thispagestyle{genaistyle}
\metricentry{FID}{Fréchet Inception Distance (FID)}\label{sec:fid}

% reference:
% https://papers.nips.cc/paper_files/paper/2017/file/8a1d694707eb0fefe65871369074926d-Paper.pdf
% https://arxiv.org/pdf/2401.09603
% https://arxiv.org/abs/2104.11222 (Parmar, Zhang, Zhu — On Aliased Resizing and Surprising Subtleties in GAN Evaluation)
% https://arxiv.org/abs/1911.07023 (Chong & Forsyth — Effectively Unbiased FID and Inception Score)

FID compares sets of generated and real images using features extracted by Inception-v3. Differences in feature averages and variation can reveal changes in appearance and variety, such as a face generator repeating similar expressions.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{FID} = \|{\color{nmlcyan}\mu_r} - {\color{nmlpurple}\mu_g}\|^2 + \text{Tr}\left({\color{nmlcyan}\Sigma_r} + {\color{nmlpurple}\Sigma_g} - 2({\color{nmlcyan}\Sigma_r} {\color{nmlpurple}\Sigma_g})^{1/2}\right)
                $
            }
        };

        \draw[-latex,nmlcyan, semithick] ($(a.south)+(0.33,0.29)$) to node[pos=1, below] {real distribution} +(0.00,-0.24);
        \draw[-latex,nmlpurple, semithick] ($(a.north)+(1.53,-0.27)$) to node[pos=1, above] {generated distribution} +(0.00,0.24);
    }
\end{metricformula}

The first term compares feature means; the trace term compares covariances and grows when the generated set covers less of the space.
FID is $0$ when the fitted moments match and is unbounded. Finite-sample estimates have model-dependent bias: equal counts help
comparability but do not remove it. Use the same reference set and preprocessing, report both counts and check close rankings as $N$
grows.

\metricheading{When to use}

Use FID to compare generated and reference sets under one protocol, especially against historical GAN or diffusion results. Pair text-to-image evaluation with prompt-alignment and human checks. Small samples make rankings unstable; there is no universal cutoff. For one image pair, use LPIPS or SSIM.


\coloredboxes{
\item Sensitive to variety: a generator that matches the real mean but collapses to a few modes keeps the first term at zero and pays
through the covariance term (figure).
\item In the original experiment, increasing blur, noise, swirls and black rectangles raised FID. Later work finds disagreements with
people in other settings.
}
{
\item Biased by sample size and generator: matching $N$ does not remove the bias, and close rankings can reverse as $N$ changes.
\item Assumes Gaussian features: sets with the same mean and covariance but different shapes get $\text{FID} \approx 0$ (figure), and
resize and JPEG settings shift the score by points.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/FID_mechanism.png}
\end{metricfigure}

\metriccaption{Figure. FID.}{A two-dimensional stand-in for Inception's feature space (the axes are the two feature dimensions): $500$ real
samples (gray) against $500$ generated (purple), with FID from the fitted Gaussians. A generator whose samples are shifted pays through the mean
term; one that collapses onto near-identical outputs keeps the mean and pays through the covariance term, which IS cannot see. The third
population was constructed with the same mean and covariance as the reference but a different shape. Its $500$ sampled points have
slightly different fitted moments, giving $0.025$; exactly matching fitted moments would give zero.}

\orangebox{Did you know that...}
{FID depends on how you shrink the images. Inception expects $299 \times 299$ inputs and the resize step is not part of the metric's
definition: Parmar, Zhang and Zhu (2022) showed that bilinear resizing without anti-aliasing, the default in several libraries, aliases
the image and moves FID by amounts comparable to the gaps between competing models, and saving samples as JPEG instead of PNG shifts it
again. The same generator can rank first or third depending on the evaluation code, which is why they released a fixed pipeline,
clean-fid. The distance itself is Fréchet's 1957 metric between distributions, in the closed form for Gaussians derived by Dowson and
Landau in 1982.}

\metricheading{Related metrics}\metricsecondary

IS and FID can disagree, which is a reason to inspect class coverage and repetition. LPIPS compares image pairs rather than sets. With
limited samples, Kernel Inception Distance (KID) has an unbiased standard estimator.

\thispagestyle{genaistyle}
\metricentry{LPIPS}{Learned Perceptual Image Patch Similarity (LPIPS)}\label{sec:lpips}

% references: https://arxiv.org/pdf/1801.03924

LPIPS estimates how different two images look to a person. It compares features from a pretrained neural network, weighted using human judgments. A blurred photograph and a noisy one can have the same mean squared error but look quite different.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{LPIPS} = \sum_{l} \frac{1}{H_l W_l} \sum_{h,w} \|{\color{nmlred}w_l} \odot ({\color{nmlcyan}\hat{f}^l_{hw}} - {\color{nmlpurple}\hat{g}^l_{hw}})\|^2
                $
            }
        };

        \draw[-latex,nmlcyan, semithick] ($(a.north)+(2.22,-0.22)$) to[bend right=15] node[pos=1, left] {features of image $x$} +(-1.30,0.35);
        \draw[-latex,nmlpurple, semithick] ($(a.north)+(3.54,-0.25)$) to node[pos=1, above] {features of image $y$} +(0.00,0.25);
        \draw[-latex,nmlred, semithick] ($(a.south)+(0.84,0.71)$) to node[pos=1, below] {learned weights} +(0.00,-0.62);
    }
\end{metricformula}

At each position, LPIPS normalizes feature vectors across channels, compares them and weights each channel by $w_l$, then averages across space and layers. Identical images score $0$; lower means more similar under that setup. Report the backbone and weights; validate cutoffs on the application's images.

\metricheading{When to use}

Use it for super-resolution, image-to-image translation, compression or diffusion reconstructions with a reference image. Mean pairwise LPIPS can assess sample diversity. Use pixel measures for exact fidelity and FID for unpaired image sets.


\coloredboxes{
\item About $69\%$ agreement with human two-alternative choices in the paper, versus the low sixties for SSIM and PSNR and a $74\%$ human-agreement ceiling.
\item Equal-MSE noise and blur can receive different LPIPS scores (figure).
}
{
\item Adversarial perturbations can change the score without visible effect. Backbones can rank distortions differently.
\item Training on $64\times64$ patches under-weights global layout errors. Each pair costs a network forward pass.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/LPIPS_equal_mse.png}
\end{metricfigure}

\metriccaption{Figure. LPIPS.}{Four distortions tuned to the same pixel MSE of $0.023$ (PSNR $16.3$ dB), so MSE rates them equally.
LPIPS with the AlexNet backbone gives the four-pixel shift and brightness change scores of $0.07$ and $0.03$, while noise and blur
score $0.69$ and $0.82$. It distinguishes these distortions even though their MSEs match. The low score for this shift does not mean
LPIPS always tolerates misalignment: even tiny shifts can change which image it rates as closer to the original.}

\orangebox{Did you know that...}
{Zhang et al. found that features from a network with random weights already match SSIM at predicting which of two distorted images
people find closer to the original, and that trained networks do better; the learned weights $w_l$ add a smaller improvement. Related
feature losses, often built from VGG activations, are used to train super-resolution and style-transfer models. They are not necessarily
the same calculation as LPIPS. The evaluation becomes most circular when a model is trained directly against the same LPIPS variant and
checkpoint used to score it. In that case, add an independent metric and a human comparison.}

\metricheading{Related metrics}\metricsecondary

PSNR and SSIM (Computer Vision chapter) measure pixel fidelity, while LPIPS compares deep features. High PSNR with poor LPIPS can be
consistent with blur, because blur preserves broad pixel values while removing texture. The reverse can occur when detail is sharp but
slightly displaced. These patterns are clues to inspect the images, not diagnoses. FID compares sets of images and needs no pairs.

% ---------- CLIPScore ---------
\metricend
\clearpage
\thispagestyle{genaistyle}
\metricentry{CLIP Score}{CLIP Score}\label{sec:clip-score}

% reference:
% https://arxiv.org/pdf/2104.08718 (Hessel et al., CLIPScore, EMNLP 2021)
% https://lightning.ai/docs/torchmetrics/stable/multimodal/clip_score.html

CLIP Score estimates image--text agreement without a reference image. CLIP learns to associate images with text and compares their content. For example, we can score a generated picture against ``a corgi wearing sunglasses on a beach''.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{CLIP-S} = {\color{nmlred}w} \cdot \max\left(\cos({\color{nmlcyan}c}, {\color{nmlpurple}v}),\, 0\right)
                $
            }
        };

        \draw[-latex,nmlcyan, semithick] ($(a.north)+(1.92,-0.19)$) to[bend right=15] node[pos=1, left] {text embedding} +(-2.70,0.82);
        \draw[-latex,nmlpurple, semithick] ($(a.north)+(2.39,-0.18)$) to node[pos=1, above] {image embedding} +(0.00,0.40);
        \draw[-latex,nmlred, semithick] ($(a.north)+(-1.02,-0.18)$) to[bend right=15] node[pos=1, left] {scaling weight} +(-1.00,0.40);
    }
\end{metricformula}

With CLIP ViT-B/32 in the original experiments, matching pairs often had raw cosines around $0.25$--$0.35$. The authors used $w=2.5$;
some libraries use $100$. The scaled score can exceed $1$ and is not a probability. Compare systems with the same checkpoint, scaling,
prompts and preprocessing.

\metricheading{When to use}

Use it to rank prompt adherence, evaluate captioning without references and filter training pairs at scale. Avoid it when counts,
relations, negation or attribute binding matter (use VQAScore or DSG), and for image quality (use FID).


\coloredboxes{
\item Reference-free and cheap: one CLIP forward pass per image and prompt, so it scales to millions of pairs and to prompts no human
has captioned.
\item Correlated with human judgments of captions better than BLEU, METEOR, CIDEr and SPICE on Flickr8K in the original paper, without
a single reference.
}
{
\item Compositional failures in this setup: swapping ``woman'' and ``flag'' raises the score, while adding ``not'' barely moves it
(figure). Other checkpoints may behave differently.
\item Compressed and checkpoint-bound: matched and mismatched pairs can occupy a narrow range, and ViT-B/32 and ViT-L/14 produce
different scales. Whether a small average gap is meaningful depends on the paired variation across prompts.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/CLIP_Score_matrix.png}
\end{metricfigure}

\metriccaption{Figure. CLIP Score.}{Four images and six captions, scored with CLIP ViT-B/32; cells show $2.5$ times embedding cosine. Each image's caption (boxed) beats captions for other images. Yet raw cosines span only $0.06$--$0.35$. Swapping ``flag'' and ``woman'' (dashed) raises the first image's score from $0.79$ to $0.82$; negation keeps $0.69$. Here the checkpoint responds more to the words than their arrangement.}

\orangebox{Did you know that...}
{A model can learn to exploit the judge when it is optimized directly against the same CLIP checkpoint used for evaluation. Images
optimized this way can develop text-like marks or textures that raise the score without improving the result for people. Merely using a
CLIP encoder somewhere in a system does not create the same problem: the risk depends on whether the evaluation score or a close proxy
was part of the objective. For a strong claim, add an independent evaluator and human judgments.}

\metricheading{Related metrics}\metricsecondary

CLIP Score measures broad image--text alignment; VQAScore and DSG probe composition. High CLIP Score with poor FID may suggest better alignment but worse reference-distribution matching; the reverse may suggest the opposite. Inspect examples: FID does not itself test photographic realism, and these metrics inherit their evaluators' blind spots.

% ---------- Davidsonian Scene Graph ---------
\metricend
\clearpage
\thispagestyle{genaistyle}
\metricentry{DSG}{Davidsonian Scene Graph (DSG)}\label{sec:dsg}

% reference:
% https://arxiv.org/pdf/2310.18235 (Cho et al., ICLR 2024)

DSG checks a generated image against the objects, attributes and relationships in its prompt. It makes yes/no questions for a visual question-answering (VQA) model. For ``a red bicycle leaning against a blue wall'', it asks whether a bicycle is present, whether it is red and whether the wall is blue.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{DSG} = \frac{1}{{\color{nmlred}|Q|}} \sum_{q \in Q} {\color{nmlgreen}\mathds{1}}\big[{\color{nmlpurple}a_q} = \text{yes}\big] \prod_{p \in {\color{nmlyellow}\text{pa}(q)}} {\color{nmlgreen}\mathds{1}}\big[{\color{nmlpurple}a_p} = \text{yes}\big]
                $
            }
        };

        \draw[-latex,nmlred, semithick] ($(a.south)+(-2.98,0.34)$) to node[pos=1, below] {number of questions} +(0.00,-0.30);
        \draw[-latex,nmlpurple, semithick] ($(a.north)+(-0.99,-0.49)$) to[bend right=15] node[pos=1, left] {VQA answer to $q$} +(-1.00,0.77);
        \draw[-latex,nmlyellow, semithick] ($(a.south)+(1.76,0.10)$) to node[pos=1, below] {parent questions of $q$} +(0.00,-0.30);
        \draw[-latex,nmlgreen, semithick] ($(a.north)+(2.50,-0.37)$) to node[pos=1, above] {indicator function} +(0.00,0.62);
    }
\end{metricformula}

$a_q$ is the VQA answer; $\text{pa}(q)$ lists prerequisite questions. If ``is there a bicycle?'' gets a no, ``is the bicycle red?'' counts as no regardless of its answer. A language model generates questions once per prompt; DSG scores the fraction of atomic facts satisfied.

\metricheading{When to use}

Use DSG to evaluate several objects, attributes and relations, or identify a failed detail. CLIP Score is cheaper for one alignment score at scale. Style questions, such as ``is this in the style of Hokusai?'', depend heavily on the question generator and VQA model.

\coloredboxes{
\item Diagnostic: a score of $3/5$ comes with the two failed questions, so ``the wall is red instead of blue'' is read off directly
(figure).
\item Robust to VQA hallucination: asked ``is the bicycle red?'' about an image with no bicycle, VQA models often say yes; the
dependency edges skip the question.
}
{
\item Two models' errors compound: a badly phrased question and a wrong VQA answer both count against the image, and VQA models are
weakest on the relations and counts DSG targets.
\item Binary and costly: ``is the bicycle red?'' cannot grade a reddish-orange bicycle, and a prompt with $12$ facts costs $12$ VQA
calls per image.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/DSG_question_graph.png}
\end{metricfigure}

\metriccaption{Figure. DSG.}{A constructed walkthrough of the question graph for one prompt and hypothetical VQA answers for two images. Edges are
dependencies: a question only counts if its parents were answered yes. Image A has the right objects in the wrong colors, so the two
attribute questions fail and it scores $3/5$. Image B has no bicycle, so the questions about the bicycle's color and position are
skipped; the assumed yes answers illustrate the hallucination that dependency edges are meant to block. The wall's two questions carry
the score to $2/5$.}

\orangebox{Did you know that...}
{The name comes from Donald Davidson's semantics of events: a sentence like ``the bicycle leans against the wall'' is a small logical form
with an object, its properties and a relation, each true or false on its own. DSG makes that operational: the prompt becomes a graph of
propositions whose edges encode presupposition --- ``is the bicycle red?'' has no answer if there is no bicycle. The authors found
VQA models answer such questions ``yes'' often enough to inflate scores, so an image of an empty street could earn credit for the
color of a bicycle it does not contain. The dependency edges close that hole.}

\metricheading{Related metrics}\metricsecondary

CLIP Score gives one embedding similarity; VQAScore asks one question about the whole prompt; DSG asks many smaller questions and shows
which ones failed. A disagreement between VQAScore and DSG tells us that the evaluators read the image or prompt differently. A missed
detail in the single question and a faulty decomposition are two possibilities to check, not conclusions from the scores alone.

% ---------- Visual Question Answering Score ---------
\metricend
\clearpage
\thispagestyle{genaistyle}
\metricentry{VQAScore}{Visual Question Answering Score (VQAScore)}\label{sec:vqascore}

% reference:
% https://arxiv.org/pdf/2404.01291 (Lin et al., ECCV 2024)
% https://blog.ml.cmu.edu/2024/10/07/vqascore-evaluating-and-improving-vision-language-generative-models/

VQAScore estimates how well an image matches a text description by asking a model that can answer questions about images. For example,
it turns ``a horse riding an astronaut'' into a yes/no question about whether the image shows that scene. The model's probability of
answering ``Yes'' becomes the score.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{VQAScore} = P({\color{nmlcyan}\text{``Yes''}} \mid {\color{nmlpurple}\text{image}},\, {\color{nmlred}\text{question}})
                $
            }
        };

        \draw[-latex,nmlcyan, semithick] ($(a.north)+(-0.40,-0.04)$) to[bend right=15] node[pos=1, left] {positive answer} +(-1.00,0.26);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(1.37,0.07)$) to node[pos=1, below] {generated image} +(0.00,-0.22);
        \draw[-latex,nmlred, semithick] ($(a.north)+(3.38,-0.04)$) to node[pos=1, above] {prompt as a question} +(0.00,0.22);
    }
\end{metricformula}

The score is the evaluator's probability of answering ``Yes'', not calibrated image--prompt accuracy: $0.8$ does not mean eight in ten images are faithful. The paper's strongest version uses CLIP-FlanT5. Other VQA models may have different scores and failure modes.

\metricheading{When to use}

Use it to rank text-to-image or text-to-video outputs on counts, spatial relations, attribute binding and negation, or to reward the best of several candidates. Use DSG to locate failed details, FID for realism, and CLIP Score for filtering millions of pairs.


\coloredboxes{
\item Compositional: on Winoground-style pairs, where two images and two captions differ only in word order, CLIP is near chance while
VQAScore with CLIP-FlanT5 was the strongest automatic metric in the paper.
\item The prompt is read verbatim, so nothing is lost to a question generator, and one forward pass gives the score.
}
{
\item Inherits the VQA model's failures: a model that cannot count to five scores a prompt with five cats by guessing, and the template
wording moves the probability.
\item Opaque. A middling score does not reveal what failed or whether the evaluator itself made the error; DSG's per-question answers
offer more detail.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/VQAScore_vs_CLIP.png}
\end{metricfigure}

\metriccaption{Figure. VQAScore.}{One image, four captions, two metrics: CLIP-S (gray) and a simplified VQAScore from a small VQA model (BLIP-base): its probability of
the first answer token ``yes'', renormalized over ``yes'' and ``no''. Red captions are the two hard probes of the correct caption. Both rank the wrong object last, VQAScore at $0.46$
and CLIP-S at $0.14$, and neither handles the negated caption well ($0.66$ and $0.69$). But CLIP scores the word-swapped caption
\emph{above} the correct one, $0.82$ against $0.79$, while VQAScore reads the sentence in order and ranks them the right way round,
$0.93$ against $0.82$. The paper's much larger CLIP-FlanT5 model pushes mismatched captions further down; the mechanism is the same.}

\orangebox{Did you know that...}
{VQAScore reads the probability a vision--language model gives to the answer ``Yes'' for an image and question. Perplexity aggregates the same kind of probability over a sequence. Using the probability gives a continuous score where a yes/no answer would not, but the template still matters because every conditioning token can change it. Lin et al. (2024) also asked the model for a $1$--$5$ rating; those ratings clustered near the top of the scale and were much less informative.}

\metricheading{Related metrics}\metricsecondary

CLIP Score is faster and coarser; DSG is slower and more diagnostic; VQAScore sits between them. Agreement raises confidence only when
the evaluators make sufficiently different errors. A high CLIP Score and low VQAScore can point to a compositional mistake, such as the
right objects in the wrong arrangement, but inspecting the image is still necessary.

\metricend
\clearpage
\thispagestyle{genaistyle}
\metricentry{MOS}{Mean Opinion Score (MOS)}\label{sec:mos}

% reference:
% https://arxiv.org/pdf/2204.02249
% ITU-T P.800 (absolute category rating), P.808 (crowdsourced)

MOS summarizes perceived speech quality by averaging listeners' ratings, typically on a scale from $1$ (bad) to $5$ (excellent).
Those ratings depend on who listens, what they hear and the instructions they receive, so compare systems under the same test
conditions.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{MOS} = \frac{1}{{\color{nmlred}N}} \sum_{i=1}^{N} {\color{nmlcyan}r_i}
                $
            }
        };
        \draw[-latex,nmlred, semithick] ($(a.south)+(0.23,0.34)$) to[bend left=15] node[pos=1, left] {number of ratings} +(-1.00,-0.30);
        \draw[-latex,nmlcyan, semithick] ($(a.south)+(1.54,0.63)$) to[bend right=15] node[pos=1, right] {listener rating (1--5)} +(1.00,-0.30);
    }
\end{metricformula}

Ratings often follow ITU-T's absolute category scale. Report the listeners, stimuli, sampling unit and whether the design is paired. For
illustration, $20$ independent ratings with $\sigma=0.8$ give a $95\%$ $t$-interval of roughly $\pm0.37$ around one mean. Comparing two
systems instead depends on their paired differences.

\metricheading{When to use}

Use it for the final evaluation of text-to-speech, voice conversion, codecs or enhancement, and to validate an automatic metric. It is
too costly for tracking many training runs. For close systems, a paired comparison with the same listeners has more power.


\coloredboxes{
\item PESQ, POLQA and learned quality predictors are fitted to MOS data, so a well-run listening test settles disagreements between
them.
\item Can catch perceptible artifacts that an automatic metric misses, because listeners judge the result directly rather than through
a fixed signal model.
}
{
\item Noisy and expensive: under independence, about $250$ ratings with $\sigma=0.8$ give a margin near $\pm0.1$. A system comparison
depends on the paired design, variability and power; repeated ratings are not independent.
\item The mean hides the distribution: a system everyone rates $3$ and one that half rate $5$ and half rate $1$ have the same MOS
(figure). Report the interval too.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/MOS_same_mean.png}
\end{metricfigure}

\metriccaption{Figure. MOS.}{Twenty listeners rate each of three systems and all three land on $\text{MOS} = 3.0$ with a median of $3$. The
consensus system is one everyone finds mediocre; the polarized one half the panel likes and half cannot stand; the skewed one leans
toward $2$ with a few enthusiasts. Neither mean nor median distinguishes them, but their rating distributions do. The $\pm$ values are
$95\%$ $t$-intervals for these constructed samples; the zero width for the consensus system follows from giving every listener the
same rating. Report the distribution and uncertainty with the mean, and compare systems under the same protocol.}

\orangebox{Did you know that...}
{A MOS does not have a fixed natural-speech ceiling. Clean recordings often score below $5$, but their mean changes with the recordings,
listeners, scale, anchors and test conditions. This is why claims of ``parity with ground truth'' should compare a system with natural
recordings in the same test and report uncertainty. A non-significant difference is not proof of equivalence; an equivalence test needs
a margin chosen in advance. The scale is also ordinal --- the step from $2$ to $3$ need not equal the step from $4$ to $5$ --- so the
mean is a useful convention rather than a physical unit.}

\metricheading{Related metrics}\metricsecondary

PESQ predicts perceived speech quality from a reference signal, while STOI predicts intelligibility. A disagreement with a well-designed
listening test shows that the automatic metric does not capture this case; inspect the audio and protocol before assigning the cause.
Comparison MOS (CMOS: the same listeners rate A against B on a $-3$ to $+3$ scale) and MUSHRA-style tests can offer more power for close
systems.

% ---------- Perceptual Evaluation of Speech Quality ---------
\metricend
\clearpage
\thispagestyle{genaistyle}
\metricentry{PESQ}{Perceptual Evaluation of\\ Speech Quality (PESQ)}\label{sec:pesq}

% reference:
% ITU-T P.862 (2001), P.862.1 (MOS-LQO mapping), P.862.2 (wideband)
% https://lightning.ai/docs/torchmetrics/stable/audio/perceptual_evaluation_speech_quality.html

PESQ predicts perceived speech quality by comparing a processed recording with its clean original. It aligns timing and levels, then uses a model of human hearing to assess changes such as compression or noise reduction, without a listening test.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                {\color{nmlcyan}\text{MOS-LQO}} = 0.999 + \frac{4.999 - 0.999}{1 + e^{-1.4945\,{\color{nmlpurple}\text{PESQ}} + 4.6607}}
                $
            }
        };

        \draw[-latex,nmlcyan, semithick] ($(a.north)+(-3.55,-0.34)$) to node[pos=1, above] {predicted MOS} +(0.00,0.30);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(2.91,0.22)$) to[bend left=15] node[pos=1, left] {raw P.862 score} +(-1.00,-0.55);
    }
\end{metricformula}

The raw P.862 score runs from $-0.5$ to $4.5$; P.862.1 maps narrowband scores to a MOS-like $1.02$--$4.55$ scale. Wideband PESQ
(P.862.2, $16$ kHz) uses another mapping. Compare the same mode, implementation and material; ``transparent'' and ``poor'' have no
universal cutoffs.

\metricheading{When to use}

Use it to reproduce speech-codec, telephony and enhancement experiments with the same setup and a clean reference. ITU-T withdrew P.862
in January $2024$ and points new work to P.863 (POLQA), so justify PESQ in a new evaluation. Avoid it for intelligibility (use STOI),
music, unsupported sampling modes or cases without a reference.


\coloredboxes{
\item Aligns before it compares: a $20$ ms delay or a $6$ dB gain change leaves PESQ at its maximum while waveform SNR collapses
(figure).
\item Standardized core: P.862 specifies the algorithm and original validation. Mode, version, preprocessing and implementation can
still move results, so report them.
}
{
\item Needs a clean reference at $8$ or $16$ kHz. Validated on codec distortions, it can favor denoisers that remove speech detail.
\item Not differentiable: training needs an approximation. Implementations may require patent or software licences; ITU publishes the recommendation, not the software licence.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/PESQ_alignment.png}
\end{metricfigure}

\metriccaption{Figure. PESQ.}{The same eight-second sentence under eight conditions. Waveform SNR (left) compares samples directly: a $20$ ms
delay or a $6$ dB gain change makes the signals disagree sample by sample and the SNR falls to $-3.4$ and $6.0$ dB, numbers that
would suggest heavy damage. PESQ (right; narrowband P.862 mapped to MOS-LQO) aligns and level-equalizes first and returns its maximum
of $4.55$ for both, and $4.33$ for telephone band-limiting. Red marks these three changes that SNR punishes much more than PESQ. Added white noise, which is audible, moves it from $3.76$ at $40$ dB SNR
down to $1.45$ at $10$ dB.}

\orangebox{Did you know that...}
{PESQ treats added sound and missing sound differently. After aligning the signals and converting them to loudness on a perceptual
frequency scale, it computes two disturbance densities: a symmetric one for any difference and an asymmetric one that weights
components present in the degraded signal but absent from the reference far more heavily. Listeners forgive a codec that softens a
consonant more than one that adds a whistle, and the metric encodes that. It is also why PESQ can favor a denoiser that suppresses
speech along with the noise: removed speech counts as a mild loss, while the noise it would have left counts as an addition.}

\metricheading{Related metrics}\metricsecondary

STOI predicts intelligibility, while PESQ predicts perceived quality. If one rises while the other falls, the two objectives may be
trading off, or one metric may be outside the conditions where it works well. Listen to the audio and run the relevant listening test
before deciding which. For reference-free monitoring in production, learned predictors such as DNSMOS and NISQA estimate quality from
the degraded signal alone.

% ---------- Short-Time Objective Intelligibility ---------
\metricend
\clearpage
\thispagestyle{genaistyle}
\metricentry{STOI}{Short-Time Objective Intelligibility (STOI)}\label{sec:stoi}

% reference:
% Taal, Hendriks, Heusdens, Jensen (2011), IEEE TASLP — An Algorithm for Intelligibility Prediction of Time-Frequency Weighted Noisy Speech
% https://lightning.ai/docs/torchmetrics/stable/audio/short_time_objective_intelligibility.html
% https://www.mathworks.com/help/audio/ug/measure-speech-intelligibility-and-perceived-audio-quality-with-stoi-and-visqol.html
% Shannon et al. (1995), Science — Speech recognition with primarily temporal cues

STOI estimates how easy speech is to understand by comparing a noisy or processed recording with its clean original. It compares their
energy envelopes, the patterns of rising and falling sound energy, over short intervals in different frequency bands.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{STOI} = \frac{1}{{\color{nmlred}J M}} \sum_{j=1}^{J} \sum_{m=1}^{M} \operatorname{corr}\big({\color{nmlcyan}x_{j,m}},\, {\color{nmlpurple}\tilde{y}_{j,m}}\big)
                $
            }
        };

        \draw[-latex,nmlred, semithick] ($(a.south)+(-1.69,0.42)$) to[bend left=15] node[pos=1, left] {bands $\times$ segments} +(-1.00,-0.30);
        \draw[-latex,nmlcyan, semithick] ($(a.north)+(1.88,-0.75)$) to[bend right=15] node[pos=1, left] {clean envelope} +(-1.00,0.99);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(3.21,0.63)$) to node[pos=1, below] {processed envelope} +(0.00,-0.30);
    }
\end{metricformula}

$x_{j,m}$ is the clean envelope in band $j$, segment $m$; $\tilde{y}_{j,m}$ is the processed one. STOI normalizes level differences,
then clips large deviations so a few samples do not dominate the correlation. Higher is better predicted intelligibility, but there is
no universal conversion to a percentage of words understood.

\metricheading{When to use}

Use it for speech enhancement, noise suppression and hearing aids when the goal is understanding noisy speech. Avoid it for clean
speech, where it saturates and says little about quality. With strongly modulated maskers such as competing talkers, consider ESTOI.


\coloredboxes{
\item In the original experiments, STOI correlated strongly with intelligibility across several noisy-speech conditions and could
move differently from quality metrics.
\item Inspectable: the per-band, per-segment correlations show where the processed and clean envelopes differ (figure).
}
{
\item Intrusive and unaligned: needs the clean reference sample-aligned (a $20$ ms delay alone drops it from $1.0$ to $0.70$) and
evaluates only $150$ Hz--$4.3$ kHz.
\item Tested on stationary and real-world noises, but less reliable for some modulated maskers. ESTOI can work better there; only a
listening test supports a percentage of words understood.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/STOI_envelopes.png}
\end{metricfigure}

\metriccaption{Figure. STOI.}{\textit{Top:} the energy envelope of one band ($952$ Hz) for clean speech and the same speech in white
noise at $0$ dB SNR over three $384$ ms segments, with silent frames removed. Noise fills the valleys between syllables; the clean--noisy correlation is $0.98$
in the segment with a strong syllable onset and $0.73$ in the quieter one. \textit{Bottom:} the correlation for all $15$ bands and
every segment, from a simplified calculation with non-overlapping segments; two cells are slightly negative (red). Their mean is $0.76$; the reference implementation gives $0.77$ here, $0.91$ at $10$ dB SNR
and $0.70$ at $-5$ dB.}

\orangebox{Did you know that...}
{STOI ignores almost everything about a sound except the slow rise and fall of energy in each frequency band, and that is the point.
Shannon and colleagues showed in 1995 that speech stays intelligible when its fine structure is replaced by noise as long as the
envelopes of a handful of bands are preserved, an insight that also informed cochlear-implant research. STOI measures this carrier of
intelligibility, so processing that preserves the envelopes can score well despite changes in timbre, pitch or phase. Its clipping step
does not simply remove all extra energy; it limits how much large local deviations influence each correlation.}

\metricheading{Related metrics}\metricsecondary

PESQ estimates quality, while STOI estimates intelligibility; both need the clean reference and both were validated against listening
tests. When PESQ improves and STOI falls, the scores flag a possible tradeoff rather than proving its cause. Listen to the audio and test
intelligibility with people. WER (NLP chapter) on a recognizer fed the processed audio is a separate downstream check, not a substitute
for human intelligibility.

% ---------- Benchmarks ---------
\metricend
\clearpage
\thispagestyle{genaistyle}
\metricentrytitle{Benchmarks}{Benchmarks}\label{sec:benchmarks}
\begingroup
\setlength{\metricheadingbefore}{6pt}
\setlength{\metricheadingafter}{-1.5pt}


Checking a model on a handful of examples can reveal obvious failures, but it cannot tell us how reliably the model performs. A benchmark
makes the test repeatable by fixing the tasks, test data and scoring rules. When models face the same test under the same conditions, we
can compare their results and see which capabilities improve.

Benchmark leaderboards age quickly, so this section is a short history rather than a list of today's hardest tests. We follow several
influential benchmarks: what each introduced, why it mattered and how long it remained useful. When a model reached a human baseline or
score ceiling, we name the model, year and evaluation setup. That setup matters because prompts, tool access, attempts and compute can all
change a score. Test questions seen during training and results near the ceiling also weaken the comparison.

\metricheading{GLUE --- General Language Understanding Evaluation}
% reference:
% https://arxiv.org/pdf/1804.07461
% https://arxiv.org/pdf/1905.00537
% https://gluebenchmark.com/
% https://super.gluebenchmark.com/

The General Language Understanding Evaluation (GLUE, $2018$) brought nine sentence and sentence-pair tasks into one evaluation, including
sentiment classification, paraphrase detection and natural language inference. By May $2019$, models had passed its non-expert human
baseline, leaving little room to tell stronger systems apart. Its creators responded with SuperGLUE, a harder set of tasks. In January
$2021$, a $1.5$-billion-parameter DeBERTa became the first single model to pass SuperGLUE's human macro-average: $89.9$ versus $89.8$.

\metricheading{IFEval --- Instruction-Following Eval}
% reference:
% https://arxiv.org/pdf/2311.07911

Instruction-Following Eval (IFEval, $2023$) offered a reproducible alternative to slow, subjective reviews: constraints that a program can
check. Its $541$ prompts use $25$ instruction types, including word limits, required phrases and output formats. Instruction-level accuracy counts individual
constraints; prompt-level accuracy requires every constraint in a prompt to pass. Both have strict and loose versions, and loose checks
can accept some formatting differences. These scores test whether selected instructions were followed, not whether the answer was
correct or useful. The original was English-only; M-IFEval extended the idea to French, Japanese and Spanish in $2025$.

\metricheading{BBH --- BIG-Bench Hard}
% reference:
% https://arxiv.org/pdf/2206.04615
% https://arxiv.org/pdf/2210.09261
% https://arxiv.org/pdf/2502.19187

BIG-Bench Hard (BBH, $2022$) selected $23$ BIG-Bench tasks for which the results available during its construction did not exceed the
average human-rater baseline. They include logical deduction, multi-step arithmetic and tracking shuffled objects. With chain-of-thought
prompting, however, PaLM and Codex exceeded that baseline on $10$ and $17$ tasks. Difficulty therefore depended on the evaluated models
and prompts. BBEH ($2025$) later replaced each task with a harder one in a similar reasoning domain. Its authors tuned task difficulty
against two reference models, so ``extra hard'' describes that model context rather than a permanent threshold.

\metricheading{MATH}
% reference:
% https://arxiv.org/pdf/2103.03874

MATH ($2021$) contains $12{,}500$ competition problems across seven subjects, each with a step-by-step solution and an exact final answer.
The original paper reported low scores from the models it tested. In September $2024$, OpenAI described MATH as no longer effective for
separating frontier models; o1-2024-12-17 scored $96.4\%$ pass@1 that December. Later reports also use subsets: DeepSeek-R1, for example, reported
$97.3\%$ pass@1 on MATH-500 in $2025$. That is not the full test set, so comparisons must name the split and scoring protocol.

\metricheading{GPQA --- Graduate-Level Google-Proof Q\&A}
% reference:
% https://arxiv.org/pdf/2311.12022

GPQA ($2023$) tests graduate-level physics, biology and chemistry. On its $546$-question Extended set, domain experts reached $64.8\%$
accuracy and skilled non-experts with web access reached $34.1\%$. The $448$-question main set filters for expert agreement and
non-expert difficulty; the stricter $198$-question Diamond subset requires agreement from both experts and mistakes from most
non-experts. In September $2024$, OpenAI reported o1 as the first model to outperform the PhD experts it recruited for Diamond, with
$77.3\%$ pass@1. That milestone applies to this subset and study, not to scientific expertise in general.

\metricheading{MuSR --- Multistep Soft Reasoning}
% reference:
% https://arxiv.org/pdf/2310.16049

MuSR ($2023$) used generated murder mysteries, object-placement puzzles and team-assignment problems to challenge GPT-4. New instances can be generated as models improve. Stories embed facts from a hidden reasoning tree; answers require combining those facts across the narrative. Accuracy checks the answer, not the reasoning path. Fresh instances can reduce exposure risk, but published examples can still leak.

\metricheading{MMLU-Pro}
% references:
% https://arxiv.org/pdf/2406.01574
% https://huggingface.co/spaces/TIGER-Lab/MMLU-Pro

By $2024$, scores on the original MMLU were beginning to plateau. MMLU-Pro responded with $12{,}032$ harder questions across $14$ subject
areas, ten answer options instead of four and a stronger emphasis on reasoning. During construction, its authors removed questions that
more than four of eight specified models answered correctly; that filter does not change as models improve. In the paper's experiment,
chain-of-thought prompting raised GPT-4o from $53.5\%$ to $72.6\%$, so even the prompt changed the result by $19.1$ points.

\metricheading{SQuAD}
% reference:
% https://arxiv.org/pdf/1806.03822
% https://rajpurkar.github.io/SQuAD-explorer/

SQuAD $1.1$ ($2016$) contains over $100{,}000$ questions about Wikipedia passages, all guaranteed to have an answer in the text. SQuAD
$2.0$ ($2018$) added over $50{,}000$ unanswerable questions, so a model must also decide when not to answer. Later that year, BERT reported
$93.2$ test F1 on SQuAD $1.1$ and $83.1$ on SQuAD $2.0$, both new state-of-the-art results. The versions test different tasks, so their
scores are not interchangeable.

\metricheading{ARC-AGI}
% reference:
% https://arxiv.org/pdf/1911.01547
% https://arcprize.org/arc-agi

ARC-AGI-$1$, introduced in $2019$, uses grid puzzles in which a system infers a transformation from a few examples. In December $2024$,
o3-preview scored $75.7\%$ on its semi-private set within the competition's \$10{,}000 compute limit; a configuration using $172$ times
more compute reached $87.5\%$. The jump prompted ARC-AGI-$2$, whose harder grid tasks arrived in $2025$. It also showed why results must
name the version, split and compute allowance.

ARC-AGI-$3$, introduced for the $2026$ competition, changed the task. Agents act in unfamiliar environments, receive feedback and are
scored on success and efficiency relative to people. Its results are not interchangeable with the static grid puzzles.
