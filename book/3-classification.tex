% ---------- Confusion Matrix ----------
\thispagestyle{classificationstyle}
\section{Confusion Matrix}\label{sec:confusion-matrix}
\subsection{Confusion Matrix}
A confusion matrix counts how often each actual class receives each predicted label. For two classes, it has four cells. If spam is the positive class, correctly flagged spam is a true positive (TP), while missed spam is a false negative (FN). A legitimate email flagged as spam is a false positive (FP); one correctly left alone is a true negative (TN).

\vspace{-0.5em}
\begin{center}
\tikz{
\node[inner sep=2pt, font=\Large] (a) {
$\displaystyle
C_{\textcolor{nmlred}{i}\,\textcolor{nmlcyan}{j}}
= \sum_{n=1}^{M}
\mathbf{1}\{ \; y_n = \textcolor{nmlred}{i} \;\land\; \hat{y}_n = \textcolor{nmlcyan}{j} \;\}
$
};
\draw[overlay,-latex,nmlred, semithick] ($(a.north west)+(4.15,-0.55)$) to[bend right=34] node[pos=1, left] {actual class} +(-0.45,0.90);
\draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(2.85,0.50)$) to[bend right=19] node[pos=1, right] {predicted class} +(0.55,-0.45);
}
\end{center}
\vspace{-0.5em}

Here, $M$ is the number of examples. The indicator adds one to cell $C_{ij}$ whenever an example's actual class is $i$ and its predicted class is $j$.

\textbf{When to use Confusion Matrix?}

Use the confusion matrix when you want the full per-class breakdown of correct vs incorrect predictions instead of a single summary score. It's the right tool when false positives and false negatives have different costs (medical diagnosis, fraud detection, content moderation). For model selection or hyperparameter tuning, pair it with a derived metric like F1 or MCC.

\coloredboxes{
\item Reveals which classes the model confuses. High overall accuracy can hide frequent misses in a rare class.
\item Provides the counts for decision metrics such as precision, recall and accuracy. One table lets you examine several aspects of those decisions.
}
{
\item Doesn't summarize to a single number. For model selection, leaderboards, or hyperparameter tuning you still need a derived metric.
\item Large matrices can be hard to inspect. Clear labels, class ordering and per-class summaries help; keep class counts alongside normalized rates.
}
\clearpage
\thispagestyle{customstyle}

\begin{center}
    \includegraphics[width=\textwidth]{figures/Confusion_Matrix_cells.png}
\end{center}

\textbf{Figure. Confusion Matrix.} \underline{Left:} ten predictions, each one a pair of actual and predicted label, sorted into
its cell: a true positive (TP) or true negative (TN) when the two agree, a false negative (FN) or false positive (FP) when they don't.
\underline{Right:} the four counts as the $2 \times 2$ matrix, and the metrics as reads of it. Along the top row, recall
$= 3/4$; along the bottom row, the false positive rate $= 1/6$; down the first column, precision $= 3/4$; the diagonal over
everything, accuracy $= 0.80$. These decision metrics use the four counts; ranking and probability metrics also need the original scores.

In predictive maintenance, acting on a prediction can change the outcome. If a warning triggers a repair, we cannot observe whether the machine would have failed without it. That is different from waiting for a label: to judge a prediction of failure within thirty days, we must let those thirty days pass. Both affect which cases we can fairly include in the matrix.

\orangebox{%
Did you know that...}
{Divide each row by its total and the diagonal entries give per-class recall. Divide each column by its total and they give per-class precision. The off-diagonal entries then show which mistakes contribute to those rates. Check the row and column labels first: some tools reverse the axes.
}

\textbf{Other related metrics}

When summary metrics disagree, inspect the counts rather than guessing the cause. For many classes, a normalized heatmap can make patterns easier to see, while the counts show how much evidence supports each rate.




% ---------- FPR ----------
\clearpage
\section{FPR}\label{sec:fpr}
\subsection{False Positive Rate}
\thispagestyle{classificationstyle}

The false positive rate is the fraction of actual negatives incorrectly flagged as positive. In a spam filter, FPR is the rate
at which legitimate emails end up in your spam folder. In medical screening, it's the rate of healthy patients getting a false alarm.
FPR forms the horizontal axis of the ROC curve.

\begin{center}
\tikz{
\node[inner sep=2pt, font=\Large] (a) {
{
$\displaystyle
FPR = \frac{{\color{nmlcyan}FP}}{{\color{nmlcyan}FP} + {{\color{nmlpurple}TN}}}
$
}
};
\draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.00,0.05)$) to[bend left=15] node[pos=1, right] {false positives} +(0.75,0.30); 
% \draw[overlay,-latex,teal!70!green, semithick] ($(a.south)+(2.10,0.10)$) to[bend right=15] node[pos=1, right] {mean of targets} +(1.00,-0.50); 
\draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.50,-0.05)$) to[bend right=19] node[pos=1, right] {true negatives} +(0.75,-0.30); 
}
\end{center}

FPR ranges from 0 (no false alarms) to 1 (every negative is misclassified). FPR = 1 $-$ Specificity (TNR), so a high
Specificity means a low FPR. In the ROC curve, FPR is the x-axis: a good classifier hugs the left side (low FPR).

\textbf{When to use FPR?}

Use FPR when false alarms are costly: spam filtering (legitimate email lost), fraud detection (good transactions blocked), medical
screening (healthy patients subjected to invasive follow-up). When both FPR and FNR matter, use the ROC curve to visualize the trade-off.

\coloredboxes{
\item Measures how often we wrongly flag a negative case. An FPR of $1\%$ means about ten false alarms per thousand legitimate transactions.
\item Uses only actual negatives. Changing the proportion of positives alone does not change FPR, provided the model behaves the same within each class.
}
{
\item Blind to the positive class. A model that never detects any positives (all predictions = negative) achieves FPR = 0, which looks perfect. Always pair FPR with TPR (Recall).
\item A low FPR can still produce mostly false alerts when positives are rare. Precision tells you what fraction of the alerts are correct.
}

Other metrics used alongside or instead of FPR include True Positive Rate (TPR), Precision, F1-Score, the area under the ROC curve (ROC AUC), and Specificity.


% ---------- FNR ----------
\clearpage
\section{FNR}\label{sec:fnr}
\subsection{False Negative Rate}
\thispagestyle{classificationstyle}

The false negative rate is the fraction of actual positives the model misses. In cancer screening, FNR is the rate of undetected tumors.
In fraud detection, it's the rate of fraudulent transactions that slip through. FNR = 1 $-$ Recall, so minimizing FNR is equivalent
to maximizing Recall.
\begin{center}
\tikz{
\node[inner sep=2pt, font=\Large] (a) {
{
$\displaystyle
FNR = \frac{{\color{nmlcyan}FN}}{{\color{nmlcyan}FN} + {{\color{nmlpurple}TP}}}
$
}
};
\draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.92,-0.03)$) to[bend right=15] node[pos=1, left] {false negatives} +(-1.00,0.30); 
% \draw[overlay,-latex,nmlgreen, semithick] ($(a.south)+(2.1,0.1)$) to[bend right=15] node[pos=1, right] {mean of targets} +(1,-.5); 
\draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.65,0.09)$) to[bend left=15] node[pos=1, left] {true positives} +(-1.00,-0.30); 
}
\end{center}

FNR ranges from 0 (no misses) to 1 (every positive is missed). In high-stakes domains, even a small FNR can be
catastrophic: an FNR of $5\%$ in airport security means 1 in 20 threats goes undetected.

\textbf{When to use FNR?}

Use FNR when missing a positive is the primary risk: disease screening (undiagnosed cancer), security systems (missed
threats), predictive maintenance (undetected failures). If false alarms are the bigger concern, focus on FPR instead.

\coloredboxes{
\item Measures misses among the cases we wanted to detect, which makes the result useful when missed cases have serious consequences.
\item Adding negatives alone does not change FNR: its denominator contains only actual positives.
}
{
\item Says nothing about false alarms. Pair it with FPR or precision; recall is simply $1-FNR$ and adds no new information.
\item An estimate based on few positives is uncertain. With five positive cases, one extra miss changes FNR by $20$ percentage points.
}

}

\textbf{Other related metrics}

Other metrics used alongside or instead of False Negative Rate
are Recall/Sensitivity, Specificity, Precision, F1-Score, and ROC curve.

% ---------- TPR ----------
\clearpage
\section{TPR (Recall/Sensitivity)}\label{sec:tpr-recall-sensitivity}
\subsection{True Positive Rate (Recall/Sensitivity)}
\thispagestyle{classificationstyle}

Recall is the fraction of actual positives the model correctly identifies. In cancer screening, a recall of $0.95$ means the test detects $95\%$ of the positive cases. Recall is $1-FNR$, so increasing it reduces the miss rate. It does not tell us how many healthy patients receive a false alarm.

\begin{center}
\tikz{
\node[inner sep=2pt, font=\Large] (a) {
{
$\displaystyle
Recall = \frac{{\color{nmlcyan}TP}}{{\color{nmlcyan}TP} + {{\color{nmlpurple}FN}}}
$
}
};
\draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.02,-0.03)$) to[bend right=15] node[pos=1, left] {true positives} +(-1.00,0.30); 
% \draw[overlay,-latex,nmlgreen, semithick] ($(a.south)+(2.1,0.1)$) to[bend right=15] node[pos=1, right] {mean of targets} +(1,-.5); 
\draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.69,0.09)$) to[bend left=15] node[pos=1, left] {false negatives} +(-1.00,-0.30); 
}
\end{center}

Recall ranges from 0 to 1, where 1 indicates perfect recall (all positive instances were correctly identified), and 0 indicates the worst
possible recall (no positive instances were identified).

\textbf{When to use TPR?}

Use recall when missed positives matter, such as undetected disease or fraud. Choose a threshold that catches as many positives as possible while keeping false alarms within an acceptable limit. That limit might be a minimum precision or the number of alerts a team can review. Predicting everything positive gives perfect recall, so recall alone cannot make this choice.

\coloredboxes{
\item Directly measures detection of the cases you want to find. A recall of $0.95$ means $5\%$ of positive cases go undetected.
\item Independent of the negative class. Recall depends only on TP and FN, so it's stable even when the number of negatives changes dramatically.
}
{
\item Does not penalize false alarms. Lowering the threshold usually catches more positives but also flags more negatives.
\item Ignores true negatives entirely. A model that correctly rejects $99\%$ of negatives gets no credit from Recall. For a complete picture, combine with Specificity or use MCC.
}

Precision describes the reliability of positive predictions; specificity describes correct rejections. F-beta combines precision and recall with a chosen emphasis.

\clearpage
\thispagestyle{classificationstyle}
\section{TNR (Specificity)}\label{sec:tnr-specificity}
\subsection{True Negative Rate (Specificity)}

Specificity is the fraction of actual negatives the model correctly identifies. It's the mirror of Recall —
while Recall measures how well you detect positives, Specificity measures how well you recognize negatives. TNR = 1 $-$ FPR.
In a drug test, high Specificity means few false accusations; in email filtering, it means few legitimate emails marked as spam.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
        {
        $\displaystyle
        TNR = \frac{{\color{nmlcyan}TN}}{{\color{nmlcyan}TN} + {{\color{nmlpurple}FP}}}
        $
        }
        };
        \path[room for labels] ([yshift=0.28cm]a.north) ([yshift=-0.21cm]a.south);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.90,-0.03)$) to[bend right=15] node[pos=1, left] {true negatives} +(-1.00,0.30); 
        % \draw[overlay,-latex,nmlgreen, semithick] ($(a.south)+(2.1,0.1)$) to[bend right=15] node[pos=1, right] {mean of targets} +(1,-.5); 
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.63,0.09)$) to[bend left=15] node[pos=1, left] {false positives} +(-1.00,-0.30); 
    }
\end{center}

TNR ranges from 0 to 1, where 1 indicates perfect specificity (all negative instances correctly identified) and 0 (no negative instances were correctly identified).
In hypothesis testing, specificity is inversely related to the Type I error rate.

\textbf{When to use TNR?}

When you need to assess a test's ability to identify negative cases correctly or when the cost of false positives is high (e.g., unnecessary medical procedures).

\coloredboxes{
\item It directly measures the ability to correctly identify negative cases.
\item It is crucial in scenarios where false positives have significant consequences.
\item High specificity is valuable for confirmatory tests.
}
{
\item It doesn't account for false negatives or true positives.
\item A test with high specificity but low sensitivity might miss many positive cases.
\item It should be considered alongside sensitivity for a comprehensive evaluation.
}

\thispagestyle{classificationstyle}
\section{Accuracy}\label{sec:accuracy}
\subsection{Accuracy}

Accuracy is the fraction of predictions that are correct. An accuracy of $0.92$ means the model gets $92$ out of every $100$ predictions right. It counts each example equally, whether the model correctly identifies a positive or a negative case.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                Accuracy = \frac{{\color{nmlred}TP}+{\color{nmlcyan}TN}}{{\color{nmlred}TP} + {{\color{nmlcyan}TN}} + {\color{nmlpurple}FP} + {\color{nmlgreen}FN}}
                $
            }
        };
        \path[room for labels] ([yshift=0.28cm]a.north) ([yshift=-0.51cm]a.south);
        \draw[overlay,-latex, nmlcyan, semithick] ($(a.north)+(2.00,-0.03)$) to[bend left=15] node[pos=1, right] {true negatives} +(1.00,0.30);
        \draw[overlay,-latex, nmlpurple, semithick] ($(a.south)+(2.02,0.09)$) to[bend left=15] node[pos=1, left] {false positives} +(-1.00,-0.30);
        \draw[overlay,-latex, nmlred, semithick] ($(a.north)+(0.64,-0.03)$) to[bend right=15] node[pos=1, left] {true positives} +(-1.00,0.30);
        \draw[overlay,-latex, nmlgreen, semithick] ($(a.south)+(3.41,0.09)$) to node[pos=1, below] {false negatives} +(0.00,-0.30);
    }
\end{center}

Accuracy ranges from $0$ to $1$, with $1$ meaning every prediction is correct. On a dataset with $99\%$ negatives, a model that always predicts ``negative'' achieves $99\%$ accuracy while missing every positive. This is the \textbf{accuracy paradox}: a high overall score can hide failure on the less common class.

\textbf{When to use Accuracy?}

Use accuracy when the goal is to minimize the number of wrong decisions and each error has the same cost. This can include imbalanced data, provided the test population represents the cases the model will encounter. Check performance within each class as well, especially when missing the rarer class matters.

\enlargethispage{2\baselineskip}
\coloredboxes{
\item Easy to interpret as the proportion of correct decisions, in both binary and multiclass problems.
\item Gives every evaluated example the same weight, matching an objective that counts all mistakes equally.
}
{
\item Can hide poor results for individual classes. Compare with a simple baseline, then check which errors the model prevents; even a small gain can matter at scale.
\item Counts a missed positive and a false alarm equally. Use Expected Cost or explicit error-rate requirements when their consequences differ.
}

\textbf{Other related metrics}

Balanced Accuracy gives each class's recall equal weight. Precision and Recall describe results for the positive class, while Expected Cost accounts for the consequences of different mistakes.

\clearpage
\thispagestyle{classificationstyle}
\section{Balanced Accuracy}\label{sec:balanced-accuracy}
\subsection{Balanced Accuracy}

Balanced accuracy averages the proportion of correct predictions within each class, giving every class equal weight. In binary classification, it averages sensitivity and specificity. If $95\%$ of cases are negative, always predicting ``negative'' gives $95\%$ accuracy but only $50\%$ balanced accuracy: it gets all the negatives right and misses all the positives.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                Balanced\ Accuracy = \frac{1}{2}\left(\frac{{\color{nmlcyan}TP}}{{\color{nmlcyan}TP} + {\color{nmlpurple}FN}} + \frac{{\color{nmlcyan}TN}}{{\color{nmlcyan}TN} + {\color{nmlpurple}FP}}\right)
                $
            }
        };
        \path[room for labels] ([yshift=0.54cm]a.north) ([yshift=-0.07cm]a.south);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.20,-0.07)$) to[bend right=15] node[pos=1, left] {true positives} +(-1.00,0.30);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(4.08,-0.07)$) to node[pos=1, above] {true negatives} +(0.00,0.30);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.88,0.19)$) to[bend left=15] node[pos=1, left] {misclassifications} +(-1.00,-0.30);
    }
\end{center}

Balanced accuracy ranges from $0$ to $1$. In the binary case, predicting only one class scores $0.5$, also the expected score of predictions independent of the true labels. It equals accuracy when the classes are equally common. Otherwise, either score can be higher, depending on which class the model predicts better.

\textbf{When to use Balanced Accuracy?}

Use balanced accuracy when you want success within each class to contribute equally, even if one class is much more common. It is useful for comparing detection of rare events with rejection of normal cases, but it does not represent the actual costs of those mistakes.

\enlargethispage{2\baselineskip}
\coloredboxes{
\item A common class cannot dominate the average merely because it contains more examples.
\item The same idea extends to multiple classes: calculate recall for each, then average equally.
}
{
\item Equal class weighting may not match the task's priorities. Use Expected Cost when you can specify the consequences of each error.
\item Small classes give uncertain estimates. With five positives, one additional missed positive lowers binary balanced accuracy by $10$ percentage points, if specificity stays fixed.
}

With $K$ classes represented in the data, predictions independent of the true labels have expected balanced accuracy $1/K$.}

\textbf{Other related metrics}

A gap between Accuracy and Balanced Accuracy is a reason to inspect the individual class recalls. MCC offers a different summary of the same confusion matrix, as a correlation between actual and predicted labels. Precision and Recall help when the positive class is the main concern.

% ---------- Precision ----------
\clearpage
\thispagestyle{classificationstyle}
\section{Precision}\label{sec:precision}
\subsection{Precision}

Precision is the proportion of positive predictions that are correct. If a spam filter has precision $0.80$, then $80\%$ of the messages it flags are spam and $20\%$ are legitimate messages. Here, ``positive'' means spam, so a false positive is a legitimate message sent to the spam folder.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                Precision = \frac{{\color{nmlcyan}TP}}{{\color{nmlcyan}TP} + {\color{nmlpurple}FP}}
                $
            }
        };
        \path[room for labels] ([yshift=0.28cm]a.north) ([yshift=-0.21cm]a.south);
        \draw[overlay,-latex, nmlcyan, semithick] ($(a.north)+(1.41,-0.03)$) to[bend right=15] node[pos=1, left] {true positives} +(-1.00,0.30); 
        \draw[overlay,-latex, nmlpurple, semithick] ($(a.south)+(2.09,0.09)$) to[bend left=15] node[pos=1, left] {false positives} +(-1.00,-0.30);
    }
\end{center}

Precision ranges from $0$ to $1$, but a perfect score does not tell us how many positives the model found. A fraud detector that flags just one transaction, correctly, out of $1{,}000$ fraudulent transactions has precision $1.0$ and recall $0.001$. Recall supplies the missing part of that picture.

\textbf{When to use Precision?}

Use precision when you need to know how reliable the model's positive decisions are, such as the alerts sent to a fraud investigator or the messages blocked as spam. Read it alongside recall to see how many relevant cases those decisions cover.

\coloredboxes{
\item Directly describes the fraction of alerts or returned results that are correct.
\item Makes false alarms visible among positive predictions, even when most examples are negative.
}
{
\item Depends on how common positives are. More negatives can produce more false alarms, even if sensitivity and FPR stay the same. Use a representative test population.
\item Undefined when the model predicts no positives. Check how your software reports this case.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/Precision_3d_surface.png}
\end{figure*}

\textbf{Figure. Precision.} Precision as a function of TP and FP. Precision is highest when FP is low relative to TP.

\orangebox{%
Did you know that...}
{
    Lowering a fixed model's threshold flags more cases. Recall cannot fall, but precision depends on the added cases: it can rise if enough are positive, or fall if too many are false alarms. A better model can improve both precision and recall, so the trade-off is not an unavoidable rule between them.
}

\textbf{Other related metrics}

Precision is most commonly used alongside Recall. To combine both into a single metric, use the F1-score or the F-beta score.
For a threshold-independent evaluation, consider the PR AUC.

% ---------- F1-score ----------
\clearpage
\thispagestyle{classificationstyle}
\section{F1-score}\label{sec:f1-score}
\subsection{F1-score}

F1 combines precision and recall into one score, using their harmonic mean. It measures how well the model finds positive cases while avoiding false alarms. The harmonic mean gives more influence to the lower of the two values, so a very low precision or recall holds the score down.


% formula
\vspace{0.5em}
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                F1 = \frac{2}{\textcolor{nmlcyan}{P^{-1}} + \textcolor{nmlpurple}{R^{-1}}} = \frac{2\textcolor{nmlred}{TP}}{2\textcolor{nmlred}{TP} + \textcolor{nmlgreen}{FP} + \textcolor{gray}{FN}}
                $
            }
        };
        \path[room for labels] ([yshift=0.00cm]a.north) ([yshift=-0.85cm]a.south);
        \draw[overlay,-latex, nmlcyan, semithick] ($(a.south)+(-2.61,0.09)$) to[bend left=15] node[pos=1, left] {\color{nmlcyan} precision} +(-1.00,-0.45);
        \draw[overlay,-latex, nmlpurple, semithick] ($(a.south)+(-1.12,0.09)$) to node[pos=1, below] {\color{nmlpurple} recall} +(0.00,-0.45);
        \draw[overlay,-latex, nmlgreen, semithick] ($(a.south)+(2.25,0.09)$) to node[pos=1, below] {false positive} +(0.00,-0.87);
        \draw[overlay,-latex, gray, semithick] ($(a.south)+(3.67,0.09)$) to node[pos=1, below] {\color{gray} false negative} +(0.00,-0.45);
        \draw[overlay,-latex, nmlred, semithick] ($(a.north)+(2.30,-0.03)$) to[bend right=15] node[pos=1, left] {\color{nmlred} true positive} +(-1.00,0.30);
    }
\end{center}
\vspace{0.5em}

F1 ranges from $0$ to $1$, reaching $1$ when both precision and recall are perfect. It can rise even if one of them falls, provided the other improves enough. Report both components when you need to see what changed.

\textbf{When to use F1-score?}

Use F1 when you want one summary of precision and recall for the positive class, with neither given extra weight. It can help compare alerting or retrieval systems, but it does not assign costs to their mistakes.

\coloredboxes{
\item Summarizes precision and recall in one number, while keeping a low value of either from being hidden by a high value of the other.
\item Focuses on positive cases when the many correctly rejected negatives are not the main concern.
}
{
\item The F1-score doesn't consider true negatives, which might be necessary in some scenarios.
\item It assumes that precision and recall are equally important. F-beta score can address this by allowing adjustable weighting between precision and recall.
}

\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/F1_3d_surface.png}
\end{figure*}

{A model with $100\%$ precision and $1\%$ recall gets an F1 of about $0.02$, while their arithmetic mean is $50.5\%$. The harmonic mean keeps the score low because the model misses almost all positives, even though every positive prediction is correct.}

\textbf{Other related metrics}

When precision and recall are not equally important, use the F-beta score. For a metric that also considers true negatives, consider MCC or the P4-metric.

% ---------- F-beta ----------
\clearpage
\thispagestyle{classificationstyle}
\section{F-beta}\label{sec:f-beta}
\subsection{F-beta}

F-beta combines precision and recall while letting you choose which matters more. Values of $\beta$ above $1$ emphasize recall, while values below $1$ emphasize precision. For example, $\beta = 2$ favors finding more positive cases; $\beta = 0.5$ favors making fewer false alarms among the positive predictions. Setting $\beta = 1$ gives F1.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
        {
            $\displaystyle
            F_{\beta} = \frac{(1 + \beta^2) {\color{nmlred}TP}}{(1 + \beta^2) {\color{nmlred}TP} + {\color{nmlpurple}FP} + \beta^2 {\color{nmlgreen}FN}} = \frac{(1 + \beta^2) \cdot {\color{nmlcyan}P} \cdot {\color{nmlyellow}R}}{\beta^2 \cdot {\color{nmlcyan}P} + {\color{nmlyellow}R}}
            $
        }
        };
        \path[room for labels] ([yshift=0.51cm]a.north) ([yshift=-0.43cm]a.south);
        \draw[overlay,-latex, nmlred, semithick] ($(a.north)+(-0.52,-0.10)$) to[bend right=15] node[pos=1, left] {true positives} +(-1.00,0.34);
        \draw[overlay,-latex, nmlcyan, semithick] ($(a.north)+(4.58,-0.10)$) to node[pos=1, above] {precision} +(0.00,0.30);
        \draw[overlay,-latex, nmlpurple, semithick] ($(a.south)+(-0.82,0.17)$) to[bend left=15] node[pos=1, left] {false positives} +(-1.00,-0.30);
        \draw[overlay,-latex, nmlgreen, semithick] ($(a.south)+(1.08,0.17)$) to node[pos=1, below] {false negatives} +(0.00,-0.30);
        \draw[overlay,-latex, nmlyellow, semithick] ($(a.south)+(4.85,0.17)$) to node[pos=1, below] {recall} +(0.00,-0.30);
    }
\end{center}

For $\beta > 0$, F-beta ranges from $0$ to $1$, with $1$ meaning perfect precision and recall. It is $0$ when there are no true positives but at least one false positive or false negative. If all examples and predictions are negative, the score is undefined; software may use a specified fallback value.

\textbf{When to use F-beta?}

Use F-beta when you need a single precision--recall summary but want to favor one component. Choose $\beta$ for that preference and inspect both components; a higher combined score does not tell you which mistakes changed.

\coloredboxes{
\item Lets you emphasize precision or recall while still accounting for both.
\item Includes F1 as a special case, so the same family supports different priorities.
}
{
\item The value of $\beta$ is not an error-cost ratio. Use Expected Cost if the consequences of false positives and false negatives can be specified directly.
\item Just like F1-score, F-beta doesn't consider true negatives, which might be necessary in some scenarios.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/F_beta_curves.png}
\end{figure*}

\textbf{Figure. F-beta.} F-beta against recall, with precision fixed at $0.8$. Below recall $0.8$, the $\beta = 0.5$ curve is highest because it favors the stronger component, precision. All curves meet at $0.8$; above that point, recall is stronger and the $\beta = 2$ curve is highest.

\orangebox{Did you know that...}
{As $\beta$ grows, F-beta approaches recall; as $\beta$ approaches zero, it approaches precision. F2 and F0.5 sit between these extremes, keeping both measures in the score. Neither choice means that one type of error costs exactly twice as much as the other.}

\textbf{Other related metrics}

The F-beta score generalizes the F1-score. If you need a metric that also accounts for true negatives, consider MCC or the P4-metric.

% ---------- ROC AUC ----------
\clearpage
\thispagestyle{classificationstyle}
\section{ROC AUC}\label{sec:roc-auc}
\subsection{Area Under the Receiver Operating Characteristic Curve}

ROC AUC measures how well a model ranks positive cases above negative ones. Changing the decision threshold changes the true-positive and false-positive rates. Plotting those rates against each other gives the ROC curve; its area summarizes the model's ranking across thresholds.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{ROC AUC} = \int_{0}^{1} {\color{nmlpurple}TPR}\big({\color{nmlcyan}FPR}^{-1}({\color{nmlyellow}x})\big) \, d{\color{nmlyellow}x}
                $
            }
        };
        \path[room for labels] ([yshift=0.25cm]a.north) ([yshift=-0.12cm]a.south);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(0.14,-0.46)$) to[bend right=15] node[pos=1, left] {true positive rate} +(-1.00,0.70);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.53,-0.46)$) to[bend left=15] node[pos=1, right] {false positive rate} +(1.00,0.61);
        \draw[overlay,-latex,nmlyellow, semithick] ($(a.south)+(2.86,0.51)$) to[bend left=15] node[pos=1, left] {swept from $0$ to $1$} +(-1.00,-0.64);
    }
\end{center}

An AUC of $1$ means perfect ordering, while random rankings have expected AUC $0.5$. Reversing a perfect ranking gives $0$, not $0.5$. Higher values mean better overall ordering, but what is useful depends on the task.

Another way to read AUC is to pick a positive and a negative at random. With AUC $0.90$, the positive ranks higher $90\%$ of the time if there are no ties. Tied scores count as half a correct ordering.

\textbf{When to use ROC AUC?}

Use ROC AUC to compare ranking ability before choosing a deployment threshold. When positive cases are rare, also examine Precision and Recall: even a low false-positive rate can produce many false alarms among positive predictions.

\enlargethispage{2\baselineskip}
\coloredboxes{
\item Summarizes ranking without requiring one decision threshold.
\item Has a concrete interpretation through positive--negative pairs.
}
{
\item Models with the same AUC can perform differently where you need to operate, such as at very low FPR.
\item Does not tell you precision, or how reliable the predicted probabilities are.
}

\clearpage
\thispagestyle{customstyle}


\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/ROC_AUC_curves.png}
\end{figure*}

\textbf{Figure. ROC AUC.} Two illustrative ROC curves. The blue curve achieves higher recall at the same false-positive rate and encloses more area. The dashed diagonal is the chance-ranking reference, with area $0.5$.

\orangebox{Did you know that...}
{The ROC curve was developed during World War II for analyzing radar signals. Radar operators needed to distinguish between enemy aircraft and noise,
leading to the development of signal detection theory and the receiver operating characteristic.}

\textbf{Other related metrics}

PR AUC complements ROC AUC by showing precision as recall changes. For decisions at one chosen threshold, examine the confusion matrix and metrics such as F1 or MCC.

% ---------- PR AUC ----------
\clearpage
\thispagestyle{classificationstyle}
\section{PR AUC}\label{sec:pr-auc}
\subsection{Area Under the Precision-Recall Curve}

PR AUC summarizes precision and recall across decision thresholds. Each threshold gives a pair of values: what fraction of actual positives the model finds, and what fraction of its positive predictions are correct. Plotting precision against recall gives the PR curve; PR AUC measures the area beneath it.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
        {
            $\displaystyle
            PR-AUC = \int_{{\color{nmlyellow}0}}^{{\color{nmlyellow}1}} {\color{nmlcyan}P}({\color{nmlyellow}R}) \, d{\color{nmlyellow}R}
            $
        }
        };
        \path[room for labels] ([yshift=0.25cm]a.north) ([yshift=-0.00cm]a.south);
        \draw[overlay,-latex, nmlcyan, semithick] ($(a.north)+(1.25,-0.46)$) to[bend right=15] node[pos=1, left] {precision} +(-1.00,0.70);
        \draw[overlay,-latex, nmlyellow, semithick] ($(a.north)+(1.85,-0.46)$) to[bend left=15] node[pos=1, right] {recall} +(1.00,0.30);
    }
\end{center}

The area lies between $0$ and $1$, with higher values indicating better precision across recall levels. Here, PR area uses straight lines between plotted points, calculated with the trapezoidal rule. Average precision is a different summary: it weights each precision value by the increase in recall. These conventions can give different results, especially when points are far apart.

\textbf{When to use PR AUC?}

Use PR AUC when finding positive cases and limiting false alarms are the main concerns. Suppose $100$ of $10{,}000$ transactions are fraudulent. Catching $90$ while raising $900$ false alarms gives $90\%$ recall but only about $9\%$ precision: roughly one in eleven alerts is correct. That is one point on the curve; we need the other thresholds to calculate its area.

\coloredboxes{
\item Shows the balance between finding positive cases and keeping positive predictions reliable, even when positives are rare.
}
{
\item Depends on the proportion of positives, so compare models on the same population.
\item A full-curve summary can hide poor results at the threshold you need. It does not summarize correctly rejected negatives.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/PR_AUC_curves.png}
\end{figure*}

\textbf{Figure. PR AUC.} Two illustrative PR curves. The blue curve maintains higher precision at each recall level and encloses more area. Read the curve at the recall you need to see the corresponding precision.

\orangebox{Did you know that...}
{The chance reference for a PR curve is the proportion of positive cases. With $10\%$ positives, selecting cases at random gives precision near $0.1$, so the reference area is $0.1$. Finite samples and the area convention affect the observed score. ROC AUC, in contrast, has expected value $0.5$ for random rankings.}

\textbf{Other related metrics}

PR AUC is complementary to ROC AUC. For a single-score summary that balances precision and recall at a fixed threshold, use the F1-score.
For evaluating the predicted probabilities, consider Brier Score or Log Loss; neither isolates calibration alone.
% ---------- Brier Score Loss ----------
\clearpage
\thispagestyle{classificationstyle}
\section{Brier Score Loss}\label{sec:brier-score-loss}
\subsection{Brier Score Loss}

The Brier Score measures how close predicted probabilities are to the outcomes that occur. It averages the squared difference between each probability and its outcome, coded as $0$ or $1$. If your model says ``$70\%$ chance of rain'' and it doesn't rain, that prediction contributes $(0.7 - 0)^2 = 0.49$ to the average.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
        {
            $\displaystyle
            {Brier\ Score} = \frac{1}{{\color{nmlred}N}} \sum_{i=1}^{N} ({\color{nmlpurple}y_i} - {\color{nmlcyan}p_i})^2
            $
        }
        };
        \draw[overlay,-latex, nmlpurple, semithick] ($(a.south)+(1.71,0.61)$) to[bend left=15] node[pos=1, left] {actual outcome} +(-2.70,-1.15);
        \draw[overlay,-latex, nmlcyan, semithick] ($(a.south)+(2.68,0.61)$) to node[pos=1, below] {predicted probability} +(0.00,-0.55);
        \draw[overlay,-latex, nmlred, semithick] ($(a.south)+(0.27,0.36)$) to[bend left=15] node[pos=1, left] {number of samples} +(-1.00,-0.51);
    }
\end{center}

The binary score ranges from $0$ to $1$, with lower values indicating better predictions. It reflects both calibration (agreement between probabilities and observed frequencies) and how well the probabilities distinguish higher-risk from lower-risk cases. Predicting $50\%$ for everyone in a balanced dataset can be calibrated, yet tells us nothing about individual differences.

For multiclass classification, ${Brier\ Score} = \frac{1}{N} \sum_{i=1}^{N} \sum_{j=1}^{C} (y_{ij} - p_{ij})^2$, where $y_{ij}$ is $1$ if sample $i$ belongs to class $j$ and $0$ otherwise. This sum over all $C$ classes ranges from $0$ to $2$.

\textbf{When to use Brier Score Loss?}

Use the Brier Score when evaluating probabilities matters beyond getting the class label right, such as estimating risk. To examine calibration specifically, also use a reliability diagram.

\coloredboxes{
\item Evaluates probabilities directly, without choosing a classification threshold.
}
{
\item Scaling conventions differ. Check whether an implementation reports a score on the $0$--$1$ or $0$--$2$ scale.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/Brier_Score_curves.png}
\end{figure*}

\textbf{Figure. Brier Score.} The loss for one prediction, once its outcome is known. A positive outcome gives zero loss at $p=1$; a negative outcome gives zero loss at $p=0$. A justified $70\%$ rain forecast can still incur a loss on a dry day.

\orangebox{Did you know that...}
{Glenn W. Brier introduced the score in 1950 to evaluate weather forecasts, including forecasts with several possible outcomes. It is a proper scoring rule: before an outcome is known, the forecast that minimizes expected loss is the true event probability. This rewards honest probability estimates, even though individual outcomes remain uncertain.}

\textbf{Other related metrics}

The Brier Score and Log Loss both evaluate probability predictions. Brier loss is bounded, while Log Loss grows without bound as the probability assigned to the actual outcome approaches zero. For predicted class labels, use metrics such as accuracy or F1-score.

% ---------- Log Loss ----------
\clearpage
\thispagestyle{classificationstyle}
\section{Log Loss}\label{sec:log-loss}
\subsection{Log Loss}

Log Loss measures how much probability a model assigns to the outcomes that actually occur. It takes the negative logarithm of those probabilities and averages the results, so higher probabilities give a lower loss. If your model says ``$99\%$ chance this is spam'' but the message isn't spam, it assigned only $1\%$ to the actual outcome. That prediction contributes $-\log(0.01) \approx 4.6$.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
        {
            $\displaystyle
            {Log\ Loss} = -\frac{1}{{\color{nmlred}N}} \sum_{i=1}^{N} ({\color{nmlpurple}y_i} \cdot log({\color{nmlcyan}p_i}) + (1 - {\color{nmlpurple}y_i}) \cdot log(1 - {\color{nmlcyan}p_i}))
            $
        }
        };
        \draw[overlay,-latex, nmlpurple, semithick] ($(a.south)+(-1.17,0.60)$) to[bend right=15] node[pos=1, right] {actual outcome} +(2.70,-1.19);
        \draw[overlay,-latex, nmlcyan, semithick] ($(a.south)+(0.41,0.60)$) to[bend right=15] node[pos=1, right] {predicted probability} +(1.00,-0.71);
        \draw[overlay,-latex, nmlred, semithick] ($(a.south)+(-2.60,0.34)$) to node[pos=1, below] {number of samples} +(0.00,-0.55);
    }
\end{center}

With the natural logarithm used here, Log Loss is $0$ for perfect probability predictions and has no upper bound. Assigning a probability close to zero to an outcome that occurs gives a large loss; assigning exactly zero gives infinite loss. Implementations usually handle this numerically by clipping probabilities away from zero.

The formula above is binary. For multiclass classification, $Log Loss = -\frac{1}{N} \sum_{i=1}^{N} \sum_{j=1}^{C} y_{ij} log(p_{ij})$, where $y_{ij}$ indicates whether sample $i$ belongs to class $j$.

\textbf{When to use Log Loss?}

Use Log Loss to evaluate probability predictions, especially when confident mistakes matter. It can reveal poor probability estimates even when a model's predicted class labels are mostly correct.

\coloredboxes{
    \item It is also a proper loss function, commonly used in logistic regression and neural networks.
    \item Generalizable beyond binary classification.
}
{
    \item Predictions close to 0 or 1 for the wrong class can heavily increase the loss.
    \item Requires valid probabilities, not arbitrary decision scores. Poorly calibrated probabilities can and should still be evaluated.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/Log_Loss_curves.png}
\end{figure*}

\textbf{Figure. Log Loss.} The loss for one prediction as the predicted probability of the positive class changes. The loss increases without bound when the model assigns almost no probability to the outcome that occurs, unlike the bounded Brier Score.

\orangebox{Did you know that...}
{Log Loss is mathematically equivalent to the negative log-likelihood of a Bernoulli distribution. This is why maximizing log-likelihood in logistic regression
is the same as minimizing Log Loss, making it the natural loss function for probabilistic binary classifiers.}

\textbf{Other related metrics}

Log Loss and the Brier Score evaluate overall probability quality; neither isolates calibration. A reliability diagram compares predicted probabilities with observed frequencies. D-squared Log Loss expresses improvement over a constant-probability baseline, while accuracy and F1 evaluate class labels.

% ---------- Jaccard Index ----------
\clearpage
\thispagestyle{classificationstyle}
\section{Jaccard Index}\label{sec:jaccard-index}
\subsection{Jaccard Index}

The Jaccard Index measures the overlap between two sets: the size of their intersection divided by the size of their union. In binary classification, the sets contain the samples predicted positive and those actually positive. Their shared members are true positives, giving $TP / (TP + FP + FN)$. In computer vision, the same measure is called Intersection over Union (IoU).

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle 
                J(A, B) = 
                \frac{\textcolor{nmlpurple}{|A \cap B|}}
                {\textcolor{nmlcyan}{|A \cup B|}}
                $
            }
        };
        \path[room for labels] ([yshift=0.22cm]a.north) ([yshift=-0.19cm]a.south);
        \draw[overlay,-latex, nmlpurple, semithick] ($(a.north)+(1.11,-0.10)$) to[bend right=15] node[pos=1, left] {\color{nmlpurple} Intersection} +(-1.00,0.34);
        \draw[overlay,-latex, nmlcyan, semithick] ($(a.south)+(1.11,0.16)$) to[bend left=15] node[pos=1, left] {\color{nmlcyan} Union} +(-1.00,-0.39);
    }
\end{center}

Jaccard ranges from $0$ for no overlap to $1$ for identical, nonempty sets. Adding correctly predicted negatives leaves it unchanged, so a large negative class cannot inflate the score just by contributing true negatives. If both sets are empty, the formula is undefined and an evaluation must specify how to score that case.

\textbf{When to use Jaccard Index?}

Use Jaccard when the overlap between predicted and actual positives is the focus, as in image segmentation. It gives credit for partial overlap, but does not distinguish a nearby miss from one far away.

\enlargethispage{2\baselineskip}
\coloredboxes{
    \item With $1\%$ positive cases, predicting every case as negative gives $99\%$ accuracy but Jaccard $0$. The positive-class failure remains visible.
    \item Measures a proportion, so the same overlap-to-union ratio gives the same score for large and small sets.
}
{
    \item Half of each set is not half of the union. Two masks of $100$ pixels sharing $50$ have a union of $150$, giving $J=1/3$.
    \item Leaves out true negatives. Use an additional metric if correctly recognizing negatives also matters.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=\textwidth]{figures/Jaccard_overlap.png}
\end{figure*}

\textbf{Figure. Jaccard Index.} The predicted region (cyan) overlaps the actual region (purple) more on the left than on the right. Jaccard divides the shared area by the total area covered by either region. For example, two masks of $100$ pixels sharing $50$ have a union of $150$, so their Jaccard score is $1/3$.

\orangebox{Did you know that...}
{For one pair of sets, Jaccard and Sørensen-Dice satisfy $\text{Jaccard} = \text{Dice}/(2 - \text{Dice})$. This monotonic conversion preserves rankings when both scores use the same pooled counts. Averaging separate scores across images or classes can change the rankings, because averaging and this conversion do not give the same result in either order.}

\textbf{Other related metrics}

For evaluations that include true negatives, use accuracy or balanced accuracy. The Computer Vision chapter covers the closely related Sørensen-Dice coefficient. When a distance between sets is needed, Jaccard distance is $1-J$ and satisfies the triangle inequality.

% ---------- D-squared Log Loss Score ----------
\clearpage
\thispagestyle{classificationstyle}
\section{D-squared Log Loss Score}\label{sec:d-squared-log-loss-score}
\subsection{D-squared Log Loss Score}

D-squared Log Loss measures how much a model reduces log loss compared with a constant prediction. The baseline assigns every sample the class proportions in the evaluation data: if $20\%$ of those samples are positive, it predicts $0.2$ for everyone. A score of $D^2=0.85$ means the model reduces log loss by $85\%$ relative to that baseline.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                D^2 = 1 - \frac{{\color{nmlcyan}L_{\text{model}}}}{{\color{nmlpurple}L_{\text{null}}}}
                $
            }
        };
        \path[room for labels] ([yshift=0.28cm]a.north) ([yshift=-0.24cm]a.south);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.12,-0.03)$) to[bend right=15] node[pos=1, left] {log loss of the model} +(-1.00,0.30);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.09,0.06)$) to[bend left=15] node[pos=1, left] {log loss of the null model} +(-1.00,-0.30);
    }
\end{center}

A score of $1$ means perfect probability predictions, $0$ matches the baseline, and a negative score means higher log loss than the baseline. There is no lower bound. A negative result warrants checking the probabilities and their use in decisions; it does not, by itself, show that a model has degraded over time or lost its ability to rank cases.

\textbf{When to use D-squared Log Loss Score?}

Use D-squared Log Loss to report improvement over a dataset's constant-probability baseline. Across two banks, for example, it compares relative reductions in log loss. Equal scores need not mean equal absolute loss or equal value for lending decisions.

\enlargethispage{2\baselineskip}
\coloredboxes{
    \item Gives log loss a reference point: $0$ means no improvement over the baseline and $1$ means perfect predictions.
    \item Expresses a proportional reduction in loss, much as $R^2$ does for squared error.
}
{
    \item The baseline changes with the evaluated class proportions. Using training proportions instead defines a different comparison.
    \item Inherits sensitivity to confident errors. A positive case assigned $0.001$ contributes about $6.91$ to log loss before averaging.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/D2_Log_Loss_curve.png}
\end{figure*}

\textbf{Figure. D-squared Log Loss Score.} Each line uses a different class balance and therefore a different baseline loss. A model log loss of $0.4$ gives $D^2\approx0.42$ on balanced data, but about $-1.01$ with a $95/5$ split. The model beats one constant baseline and loses to the other; normalization does not make the two populations equivalent.

\orangebox{Did you know that...}
{The D-squared framework generalizes R-squared to any deviance function, not just squared error. In scikit-learn, \texttt{d2\_log\_loss\_score} uses log loss as the deviance,
but you can also compute D-squared with other losses like absolute error or Poisson deviance.}

\textbf{Other related metrics}

Use raw Log Loss to see the loss before normalization, and a reliability diagram to examine calibration. F1 and MCC summarize decisions at a chosen threshold; they answer a different question from the quality of the probabilities.

% ---------- P4-metric ----------
\clearpage
\thispagestyle{classificationstyle}
\section{P4-metric}\label{sec:p4-metric}
\subsection{P4-metric}

P4 summarizes a binary classifier's performance on both classes. It is the harmonic mean of precision, recall, specificity, and negative predictive value (NPV). NPV is the proportion of negative predictions that are actually negative. By including specificity and NPV, P4 accounts for negative-class performance that F1 leaves out.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                P4 = \frac{4 \cdot {\color{nmlcyan}TP} \cdot {\color{nmlcyan}TN}}{4 \cdot {\color{nmlcyan}TP} \cdot {\color{nmlcyan}TN} + ({\color{nmlcyan}TP}+{\color{nmlcyan}TN})({\color{nmlpurple}FP}+{\color{nmlpurple}FN})}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.36,-0.03)$) to[bend right=15] node[pos=1, left] {true positives} +(-1.00,0.30);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.48,-0.03)$) to[bend left=15] node[pos=1, right] {true negatives} +(1.00,0.30);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(2.77,0.18)$) to[bend left=15] node[pos=1, left] {misclassifications} +(-1.00,-0.39);
    }
\end{center}

P4 ranges from $0$ to $1$, with $1$ for perfect classification when both classes are present. With $95$ positives and five negatives, predicting everyone positive gives F1 $\approx0.974$ but P4 $=0$. Here specificity is zero; NPV is undefined because there are no negative predictions, but the displayed count formula still gives P4 $=0$.

A zero TP or TN gives zero P4 when the denominator is nonzero. Zero FP or FN need not: eliminating either type of error can improve the score.

\textbf{When to use P4-metric?}

Use P4 when you want a summary that includes both classes. It can also compare candidate thresholds, since its counts change with the decisions. Judge the score against the task and a relevant baseline; there are no universal ``good'' or ``barely useful'' cutoffs.

\enlargethispage{2\baselineskip}
\coloredboxes{
    \item A low component rate pulls down the harmonic mean, making poor performance on either class visible.
    \item Swapping the positive and negative class names leaves P4 unchanged.
}
{
    \item A single number still hides which rate needs improvement. Report the component rates alongside it.
    \item Degenerate counts can make the denominator zero. Check the implementation's treatment of undefined cases.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/P4_vs_F1.png}
\end{figure*}

\textbf{Figure. P4-metric.} TP $=80$, FP $=20$, and FN $=20$ stay fixed while TN increases. Precision, recall, and F1 remain $0.8$, while specificity, NPV, and P4 rise. Adding true negatives also changes the dataset's size and class proportions; this is not a threshold sweep on one fixed test set.

\orangebox{Did you know that...}
{Mikołaj Sitarz proposed P4 in \textit{Extending F1 Metric, Probabilistic Approach}, first posted in 2022 and published in 2023. The four probabilities give the metric its name. Combining them extends F1's focus on precision and recall while making the score unchanged when the class names swap.}

\textbf{Other related metrics}

P4 and MCC both include true negatives, but summarize the confusion matrix differently: P4 combines four rates, while MCC measures the association between predicted and actual labels. Neither replaces an explicit error-cost objective. F-beta is useful when the focus is the precision--recall trade-off for the positive class.

% ---------- Cohen's Kappa ----------
\clearpage
\thispagestyle{classificationstyle}
\section{Cohen's Kappa}\label{sec:cohen-s-kappa}
\subsection{Cohen's Kappa}

Cohen's Kappa measures agreement between two annotators after accounting for how often their label choices would match by chance. If both independently use two labels $80\%$ and $20\%$ of the time, their expected agreement is $0.8\times0.8+0.2\times0.2=0.68$. Kappa compares their observed agreement with that baseline, using each annotator's own label frequencies.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \kappa = \frac{{\color{nmlcyan}p_o} - {\color{nmlpurple}p_e}}{{\color{nmlred}1} - {\color{nmlpurple}p_e}}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(-0.10,-0.10)$) to[bend right=15] node[pos=1, left] {observed agreement} +(-1.00,0.30);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(0.84,0.06)$) to[bend left=15] node[pos=1, left] {chance agreement} +(-1.00,-0.30);
    }
\end{center}

The numerator subtracts expected agreement from observed agreement; the denominator scales that improvement by the room left for perfect agreement. Kappa ranges from $-1$ to $1$: $1$ indicates perfect agreement, $0$ matches the chance baseline, and negative values indicate less agreement than that baseline. There is no universal cutoff that makes labels suitable for training.

\textbf{When to use Cohen's Kappa?}

Use Cohen's Kappa to assess agreement between two annotators, for example when checking a labeling process before training. It can also compare a model with reference labels. For ordered categories where some disagreements matter more than others, consider weighted kappa.

\enlargethispage{2\baselineskip}
\coloredboxes{
    \item Accounts for agreement expected from the annotators' label frequencies, rather than reporting only how often they match.
    \item Applies to two annotators using any number of categories.
}
{
    \item When one label dominates, high raw agreement can coexist with a low kappa. Report both and inspect the label frequencies.
    \item Agreement does not establish correctness: both annotators can make the same mistakes.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/Cohens_Kappa_levels.png}
\end{figure*}

\textbf{Figure. Cohen's Kappa.} A theoretical example of two independent annotators using the same label proportions. As one label becomes more common, expected raw agreement rises toward $1$, but kappa remains $0$: all agreement is explained by the chance baseline. Finite samples would fluctuate around these values.

\orangebox{Did you know that...}
{Jacob Cohen introduced kappa in 1960 in \textit{A Coefficient of Agreement for Nominal Scales}. In 1968, he introduced weighted kappa to allow different penalties for different disagreements. This is useful with ordered labels: confusing ``mild'' with ``severe'' can matter more than confusing ``mild'' with ``moderate.''}

\textbf{Other related metrics}

Fleiss' Kappa extends agreement assessment to multiple annotators. MCC measures association between predicted and actual labels. A low kappa is a reason to examine disagreements and label frequencies; it does not identify their cause or prove that the labels are unusable.

% ---------- MCC ----------
\clearpage
\thispagestyle{classificationstyle}
\section{MCC}\label{sec:mcc}
\subsection{Matthews Correlation Coefficient}

The Matthews Correlation Coefficient (MCC) measures the association between predicted and actual binary labels. It is their Pearson correlation, calculated from all four confusion-matrix counts. A high positive score means the predictions closely follow the actual labels, accounting for both positive and negative cases.

% formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\large] (a) {
            {
                $\displaystyle
                MCC = \frac{{\color{nmlcyan}TP} \cdot {\color{nmlcyan}TN} - {\color{nmlpurple}FP} \cdot {\color{nmlpurple}FN}}{\sqrt{({\color{nmlcyan}TP}+{\color{nmlpurple}FP})({\color{nmlcyan}TP}+{\color{nmlpurple}FN})({\color{nmlcyan}TN}+{\color{nmlpurple}FP})({\color{nmlcyan}TN}+{\color{nmlpurple}FN})}}
                $
            }
        };
        \path[room for labels] ([yshift=0.28cm]a.north) ([yshift=-0.34cm]a.south);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(-0.76,-0.03)$) to[bend right=15] node[pos=1, left] {true positives} +(-1.00,0.30);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.17,-0.03)$) to[bend left=15] node[pos=1, right] {true negatives} +(1.00,0.30);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(0.44,0.17)$) to[bend left=15] node[pos=1, left] {misclassifications} +(-1.00,-0.55);
    }
\end{center}

MCC ranges from $-1$ for completely reversed labels to $+1$ for perfect agreement. A score of $0$ means no association between predictions and outcomes. If either set of labels is constant, the displayed formula has a zero denominator; scikit-learn returns $0$ by convention. An always-negative model therefore receives $0$ in that implementation, even if most cases are negative.

\textbf{When to use MCC?}

Use MCC as an overall summary when performance on both classes matters, including on imbalanced datasets. Choose additional measures for requirements it does not express, such as a minimum recall, reliable probabilities, or the cost of specific errors.

\coloredboxes{
    \item Uses both correct predictions and both types of error, so it includes information that F1 leaves out.
    \item Swapping positive and negative class names leaves the correlation unchanged.
}
{
    \item A correlation is less direct to interpret than a proportion correct. MCC $=0.65$ does not mean that $65\%$ of predictions are correct.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/MCC_3d_surface.png}
\end{figure*}

\textbf{Figure. MCC.} TP and FP vary while FN $=20$ and TN $=80$ stay fixed. The score rises as true positives increase or false positives decrease. Negative values indicate an inverse association: positive predictions are less likely to be actual positives than negative predictions are.

\orangebox{Did you know that...}
{In 2020, Davide Chicco and Giuseppe Jurman compared MCC with accuracy and F1 using six synthetic examples and a genomics case study. MCC exposed failures that the other two scores obscured, including on imbalanced data. They recommended favoring MCC over those measures; the study did not establish one best metric for every application.}

\textbf{Other related metrics}

MCC and F1 use different scales and summarize different aspects of a classifier. Similar values do not establish balanced performance across classes. Inspect precision, recall, specificity, and the confusion matrix to understand the results. ROC AUC adds a view of score ordering across thresholds.

% ---------- EC ----------
\clearpage
\thispagestyle{classificationstyle}
\section{EC}\label{sec:ec}
\subsection{Expected Cost}

Expected Cost (EC) measures the average assigned cost of a system's decisions. These costs can represent money or another agreed consequence. In our loan example, suppose approving a non-creditworthy applicant costs $\$80{,}000$, while rejecting a creditworthy applicant costs $\$40{,}000$. We assign zero cost to correct decisions and average the costs incurred across applications.

\begin{center}
\tikz{
\node[inner sep=2pt, font=\Large] (a) {
{
$\displaystyle
EC = \frac{1}{{\color{nmlred}N}} \sum_{t=1}^{N} {\color{nmlpurple}C}({\color{nmlcyan}h_t}, {\color{nmlyellow}d_t})
$
}
};
\path[room for labels] ([yshift=0.16cm]a.north) ([yshift=-0.73cm]a.south);
\draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-0.63,0.34)$) to[bend left=15] node[pos=1, left] {number of samples} +(-1.00,-0.49);
\draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(1.28,0.61)$) to[bend left=15] node[pos=1, left] {true class} +(-2.70,-1.38);
\draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(0.67,-0.60)$) to[bend right=15] node[pos=1, left] {cost matrix} +(-1.00,0.78);
\draw[overlay,-latex,nmlyellow, semithick] ($(a.south)+(1.94,0.61)$) to[bend right=15] node[pos=1, right] {decision} +(1.00,-0.31); 
}
\end{center}

The cost matrix assigns a value $C(h,d)$ to each true class $h$ and decision $d$. The formula averages those values over the test samples, so lower EC is better. Decisions can be actions such as approving, rejecting, or referring an application for review; they need not be the class labels themselves.

\textbf{When to use EC?}

Use EC when different decisions have consequences that you can specify. The average above reflects the test set's class proportions. If rare cases were deliberately oversampled, average costs within each class and weight those averages by the proportions expected in deployment, assuming the within-class error behavior remains relevant.

\coloredboxes{
\item Makes the consequences of decisions explicit, in units meaningful for the application.
\item Evaluates decisions without needing probability predictions, including decisions made by rules.
}
{
\item Requires a defensible cost matrix and a population relevant to the intended use.
\item If probabilities are used to choose the least costly decision, their calibration also matters.
}

\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.45\textwidth]{figures/EC_cost_matrix.png}
\end{figure*}

Consider a loan approval scenario with two true classes: $H_1$ (Creditworthy) and $H_2$ (Not Creditworthy), and two decisions: $D_1$ (Approve Loan) and $D_2$ (Reject Loan).

All costs in the figure, tables, and calculation are in thousands of dollars. Under these assumptions, approving a non-creditworthy applicant costs twice as much as rejecting a creditworthy one.

\begin{center}
\begin{tabular}{|c|c|c|}
\hline
 & $D_1$ (Approve Loan) & $D_2$ (Reject Loan) \\
\hline
$H_1$ (Creditworthy) & $c_{11} =  0$ & $c_{12} = 40$ \\
\hline
$H_2$ (Not Creditworthy) & $c_{21} = 80$ & $c_{22} =  0$ \\
\hline
\end{tabular}
\end{center}

For each of the three applications below, we look up the cost of the decision given the applicant's true class.

\begin{center}
\begin{tabular}{|c|c|c|c|}
\hline
Sample (t)& True Class (h) & Predicted Decision (d) & Cost Incurred \\
\hline
1 & Creditworthy & Approve Loan & $C(h_1, d_1) = 0$ \\
\hline
2 & Not Creditworthy & Approve Loan & $C(h_2, d_2) = 80$ \\

The mean cost is $40$ thousand dollars per application:
\[
EC = \frac{0 + 80 + 40}{3} = 40
\]

\orangebox{%
Did you know that...}
{
    NIST's speaker-verification evaluations use a Detection Cost Function: an application of EC that combines missed detections and false alarms, weighted by specified costs and the expected proportion of target-speaker trials. EC is also called expected loss; in decision theory, minimizing it maximizes expected utility when utility is defined as negative cost.
}

\textbf{Other related metrics}

F1 combines precision and recall, while ROC AUC evaluates score ordering across thresholds. Neither requires an explicit cost for each decision. EC lets those application costs determine the evaluation. If correct decisions cost $0$ and every error costs $1$, EC equals one minus accuracy.
