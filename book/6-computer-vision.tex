\chapteropener{Computer Vision}{mintlight}{mintaccent}{%
Images are scored at three levels. Pixels: PSNR and SSIM compare a reconstructed image with its original, one by intensity and one by
local structure. Regions: pixel accuracy, Dice and panoptic quality compare predicted masks with ground truth, and differ in how they
treat class imbalance and object identity. Points: PCK and OKS score keypoints by their distance to the truth, with a tolerance that
scales with the object. The recurring lesson is that per-pixel agreement is not perception: a blurry image can win on PSNR, and a mask
shifted by a few pixels can lose on Dice while looking right.}{In this chapter}

% ---------- Pixel Accuracy ----------
\clearpage

\section{Pixel Accuracy}
\subsection{Pixel Accuracy}


Segmentation models assign a class to every pixel in an image, and Pixel Accuracy reports the fraction of those pixels that got the right label --- the direct analog of classification accuracy, computed over pixels instead of samples. It is the first number most practitioners check on a new model. Like plain accuracy, it can flatter a model whose easy majority class --- usually the background --- fills most of the frame.

\begin{center}
\tikz{
\node[inner sep=2pt, font=\Large] (a) {
{
$\displaystyle
Pixel Accuracy = \frac{\sum_{j=1}^{k} {\color{nmlcyan}n_{jj}}}{\sum_{j=1}^{k} {\color{nmlpurple}t_{j}}}
$
}
};
\draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(2.5,-0.2)$) to[bend left=15] node[pos=1, right] {correct pixels} +(1,.5);
\draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(2.5,0.1)$) to[bend left=15] node[pos=1, left] {total pixels} +(-1,-.5);
}
\end{center}

$PA$ runs from $0$ to $1$, but read it against the largest class's frequency, not against zero. If background covers $85\%$ of the frame, a model that labels every pixel ``background'' --- segmenting nothing of interest --- already scores $PA = 0.85$.


\textbf{When to use Pixel Accuracy?}

Use it as a quick sanity check on tasks where classes cover comparable areas: foreground/background splits of similar size, or document binarization. Avoid it when one class dominates the frame (medical lesions, road cracks, small objects) --- report mean IoU or Mean Pixel Accuracy instead, which average per-class scores so minority classes still count.

\coloredboxes{
\item Cheap and unambiguous. A single division over the confusion-matrix diagonal --- no thresholds to set, no per-class weights to agree on.
\item Honest when classes are balanced. On a roughly even split, $PA = 0.95$ really does mean $95\%$ of pixels are correct.
}
{
\item Dominated by the majority class. With $85\%$ background, a model that finds none of the foreground still scores $PA = 0.85$. Mean Pixel Accuracy or IoU exposes this.
\item Hides per-class failure. One global number can't reveal that a model nails roads but misses every pedestrian; for that you need a per-class breakdown.
}

Despite this,

\[
\text{Pixel Accuracy} = \frac{\text{Correctly predicted pixels}}{\text{Total number of pixels}} = \frac{6}{9} \approx 66\%
\]

Pixel accuracy therefore reflects overall correctness but does not reveal whether the model performs poorly on minority classes. 
This is to show that high PA does not necessarily indicate superior segmentation performance.

To compensate for this, Mean Pixel Accuracy (MPA), calculates accuracy per class and then averages across all classes.
This adjustment ensures that smaller classes are not overshadowed by dominant ones, making MPA a more balanced evaluation
metric in class-imbalanced datasets.

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=\textwidth]{figures/Pixel_Accuracy_imbalance.png}
\end{figure*}

\textbf{Figure. Pixel Accuracy.} Each bar is a class: its width is the class's share of pixels and its height is that class's accuracy, so the bar's \emph{area} is the class's contribution to Pixel Accuracy. The wide, well-segmented background pulls PA up to $89\%$; Mean Pixel Accuracy ($54\%$) weights every class equally and so exposes the collapse on the small classes.

\orangebox{Did you know that...}
{Pixel Accuracy is the \textbf{micro-average} of per-class accuracy --- every pixel votes once, so common classes dominate. Mean Pixel Accuracy is the \textbf{macro-average} --- every class votes once, regardless of size. It is the same micro-versus-macro split you meet in classification F1, and a wide gap between the two is always a symptom of class imbalance.}

\textbf{Other related metrics}
Other metrics in this family are Mean Pixel Accuracy (mPA), Intersection over Union (IoU) and Frequency Weighted IoU (FWIoU).

\clearpage
\thispagestyle{cvstyle}
\section{PCK}
\subsection{Percentage of Correct Keypoints}

A keypoint is a labeled landmark on an object --- an elbow, a knee, the corner of an eye. PCK reports the percentage of predicted keypoints that land within a distance threshold of the truth, where the threshold scales with object size: a $10$-pixel miss is serious on a close-up face but negligible on a distant body.

\begin{center}
\tikz{
    \node[inner sep=2pt, font=\Large] (a) {
        $\displaystyle
        PCK(\alpha) = \frac{1}{\textcolor{nmlgreen}{N}} \sum_{i=1}^{N} 1\!\left(\textcolor{nmlpurple}{d_i} \le \textcolor{nmlyellow}{\alpha L}\right)
        $
    };
    \draw[overlay,-latex,nmlyellow, semithick] ($(a.north)+(0.5,0.05)$) to[bend left=15] 
        node[pos=1, right] {threshold Radius} +(1,.5); 
    \draw[overlay,-latex,nmlgreen, semithick] ($(a.south)+(-1.15,0.1)$) to[bend left=15]
        node[pos=1, left] {Num. keypoints} +(-1,-.5);
    \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.2,0.05)$) to[bend right=15] 
        node[pos=1, right] {Euclidean distance} +(1,-.5); 
}
\end{center}

For each keypoint $i$ we measure the Euclidean distance $d_i$ to the ground truth and count it correct when $d_i \le \alpha L$, where $L$ is a reference length (head or torso size) and $\alpha$ sets the tolerance. Since the result depends entirely on $\alpha$, PCK is always reported with its threshold, as PCK@$0.2$ or PCK@$0.5$.


\textbf{When to use PCK?}

Use PCK for human pose estimation, facial landmark detection, and animal pose tracking --- anywhere a prediction within a body-scaled tolerance counts as a hit. Avoid it when you need a single number that also rewards sub-threshold precision (use OKS, which scores distance continuously), or when every pixel of error should count.

\enlargethispage{\baselineskip}
\coloredboxes{
\item Scale-invariant by construction. Normalizing the threshold by object size lets you compare a webcam selfie and a full-body stadium shot on the same footing.
\item Forgiving of small jitter. A few pixels of localization noise won't flip a keypoint from correct to wrong, so the score tracks usable accuracy.
}
{
\item Threshold-dependent. The same model can post PCK@$0.5 = 0.95$ but PCK@$0.2 = 0.70$; comparing across papers means matching $\alpha$ first.
\item Not differentiable. As a pass/fail count it can't serve as a training loss --- models optimize a regression loss on coordinates and report PCK only at evaluation.
}
\clearpage

\begin{figure}[htbp]
    \centering
    \includegraphics[width=\textwidth]{figures/PCK_threshold_visual.png}
\end{figure}

\textbf{Figure. PCK.} To find a correct keypoint (green), we determine whether the predicted keypoint (blue) falls within a threshold distance from the ground truth (black).  
The threshold is defined as a fraction $\alpha$ of a reference length $L$, typically the torso length.  

The radius of the circle around each ground-truth joint is $r = \alpha \cdot L$.  

In practice, we choose a small $\alpha$ for high-precision tasks, such as hand or facial keypoint detection.  
We use a larger $\alpha$ when approximate locations suffice, for example in full-body pose estimation for activity recognition.


\orangebox{Did you know that...}
{The common variant \textbf{PCKh} normalizes by head size instead of torso length --- a head box is far more stable to annotate than a torso that bends and foreshortens, which is why PCKh@$0.5$ is the standard score on the MPII pose benchmark.}

\textbf{Other related metrics}

For a continuous similarity score instead of a hard threshold, see Object Keypoint Similarity (OKS).
PCK variants include PCKh (head-normalized) and PCK@$0.2$ (fixed threshold at $20\%$ of torso length).

% ---------- OKS ----------
\clearpage
\thispagestyle{cvstyle}
\section{OKS}
\subsection{Object Keypoint Similarity}

Object Keypoint Similarity is the scoring rule behind the COCO keypoint leaderboard, and it fixes what PCK discards. Where PCK calls a prediction simply right or wrong, OKS scores each keypoint on a smooth Gaussian of the distance error, normalized by object size so the same miss costs more on a small person than a large one.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{similarity}_i = \exp\!\left(-\,\frac{{\color{nmlpurple}d_i}^{2}}{2\,{\color{nmlcyan}s}^{2}\,{\color{nmlyellow}k_i}^{2}}\right)
                $
            }
        };
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(1.55,-0.15)$) to[bend left=15] node[pos=1, right] {distance error} +(0.8,.5);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(1.3,0.15)$) to[bend right=15] node[pos=1, left] {object scale} +(-0.8,-.5);
        \draw[overlay,-latex,nmlyellow, semithick] ($(a.south)+(2.35,0.15)$) to[bend left=15] node[pos=1, right] {keypoint tolerance} +(0.9,-.5);
    }
\end{center}

Each keypoint scores in $[0, 1]$ --- $1$ for a perfect hit, falling toward $0$ as the prediction drifts --- and a pose's OKS is the average over its visible keypoints, so occluded or unannotated joints never drag it down.

\textbf{When to use OKS?}

Use OKS to rank pose-estimation models, or whenever you need one comparable score across objects of very different sizes. Avoid it when you want a result you can state in a sentence (PCK's ``within $X$ pixels'' is far more legible), or when your dataset has no per-keypoint $k_i$ tolerances, since OKS cannot be computed without them.


\coloredboxes{
\item Scale-invariant. Normalizing by object size makes a $5$-pixel error cost the same whether the person fills the frame or stands far in the background.
\item Smooth, not pass/fail. The Gaussian falloff rewards getting closer even once you are already ``correct,'' so a better-localized model scores higher --- a difference PCK cannot see.
}
{
\item Needs per-keypoint constants. The $k_i$ tolerances are calibrated from human-annotator variance on one dataset; reuse another dataset's values blindly and the scores stop meaning much.
\item Harder to read than PCK. OKS $= 0.78$ has no units --- you can't translate it into ``lands within $N$ pixels,'' which makes per-keypoint debugging awkward.
}

\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/OKS_gaussian_falloff.png}
\end{figure*}

\textbf{Figure. OKS.} OKS scores a keypoint with a smooth Gaussian falloff of its distance error: strict keypoints (eyes, $k = 0.05$) demand precise predictions, while lenient ones (hips, $k = 0.20$) tolerate larger errors. The gray step is PCK's hard pass/fail, shown for contrast --- OKS is its continuous generalization.

\orangebox{Did you know that...}
{OKS is to keypoints what IoU is to bounding boxes: the COCO benchmark thresholds it (at $0.50, 0.55, \dots, 0.95$) to compute a keypoint Average Precision --- the leaderboard score that drove pose models like OpenPose and HRNet.}

\textbf{Other related metrics}

OKS is the continuous counterpart of PCK. For segmentation rather than keypoint evaluation, consider IoU or the Dice Coefficient.

\thispagestyle{cvstyle}
\section{PSNR}
\subsection{Peak Signal-to-Noise Ratio}

PSNR scores how faithfully a reconstructed image matches the original, in decibels, higher is better; it is the standard number for
JPEG compression, denoising and super-resolution. It rescales the mean squared error by the largest possible pixel value, so a score
means the same whether pixels run $0$--$255$ or $0$--$1$.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\large] (a) {
            {
                $\displaystyle
                    PSNR = 10 \cdot \log_{10}\left(\frac{\color{nmlred}MAX^2}{\color{nmlpurple}MSE}\right)
                $
            }
        };
        \draw[overlay,-latex,nmlred, semithick] ($(a.north)+(2.1,-0)$) to[bend right=15] node[pos=1, left] {maximum possible pixel} +(-0.8,.4);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.east)+(-0.3,-0.35)$) to[bend right=10] node[pos=1, right] {mean squared error} +(0.6,-0.15);
    }
\end{center}

with $O$ the original and $R$ the reconstruction, both $h \times w$:

\vspace{4pt}

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\large] (a) {
            {
                $\displaystyle
                 MSE = \frac{1}{\color{teal!70!green}h \cdot \color{nmlcyan}w} \sum_{i=1}^{h} \sum_{j=1}^{w}
                 \left(\color{nmlred} O(i,j) \color{black} - \color{nmlpurple} R(i,j) \right)^2
                $
            }
        };
        \draw[overlay,-latex,teal!70!green, semithick] ($(a.west)+(1.7,-0.3)$) to[bend left=15] node[pos=1, left] {height} +(-1,-.5);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.west)+(2.4,-0.3)$) to[bend right=15] node[pos=1, right] {width} +(0.5,-.5);
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(1,0.5)$) to[bend right=15] node[pos=1, right] {original pixel value} +(0.8,-.4);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.3,-0.4)$) to[bend right=15] node[pos=1, left] {reconstructed pixel value} +(-0.8,.4);
    }
\end{center}

Every $+10$ dB means the mean squared error fell tenfold, and a perfect match sends PSNR to $\infty$. Above $30$ dB usually reads as a
clean reconstruction; below $20$ dB the artifacts are obvious.



\textbf{When to use PSNR?}

Use PSNR for compression, denoising and super-resolution, where a clean reference exists and pixel fidelity is the goal. Avoid it as a
proxy for perceived quality: a small brightness shift or a one-pixel offset craters PSNR while the image looks fine; use SSIM or LPIPS
instead.

\enlargethispage{3\baselineskip}
\coloredboxes{
\item A universal baseline: decades of compression and restoration papers report it, so values compare across methods and datasets.
\item Cheap and deterministic: a closed-form function of MSE with no training, parameters or randomness, so two implementations always agree.
}
{
\item Poorly correlated with perception: a heavily blurred image and a sharp one with faint noise can post the same PSNR.
\item Distracted by global shifts: a constant added to every pixel, barely visible to the eye, drops PSNR sharply.
}

\orangebox{Did you know that...}
{The ``peak'' in PSNR means the error is measured against the \textbf{maximum possible} pixel value ($255$ for 8-bit), not the image's actual signal --- so a dark photo and a bright one with the same absolute error get the same score. A direct consequence: PSNR values are only comparable at the same bit depth.}

\thispagestyle{cvstyle}
\section{S{\o}rensen–Dice Coefficient}
\subsection{S{\o}rensen–Dice Coefficient}


When a segmentation model outlines a region --- an organ, a road, a building footprint --- the Dice coefficient measures how much the predicted mask overlaps the ground truth, counting the shared area twice and dividing by the total size of both masks. It runs from $0$ (no overlap) to $1$ (a perfect match), and it is the dominant accuracy metric in medical image segmentation.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                Dice = \frac{2\, |{\color{nmlcyan}A} \cap {\color{nmlpurple}B}|}{|{\color{nmlcyan}A}| + |{\color{nmlpurple}B}|}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.0,-0.1)$) to[bend right=15] node[pos=1, left] {predicted set} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.0,-0.1)$) to[bend left=15] node[pos=1, right] {ground truth set} +(1,.5);
    }
\end{center}

Here $A$ is the set of predicted-positive pixels and $B$ the set of ground-truth-positive pixels, so the numerator $2|A \cap B|$ is twice their overlap. On binary problems Dice equals the F1-score, the harmonic mean of precision and recall --- which is why it balances false positives against false negatives instead of letting one dominate.

\textbf{When to use S{\o}rensen–Dice Coefficient?}

Use Dice for segmentation with class imbalance --- small foreground objects against a large background --- where it rewards overlap without being swamped by the easy background pixels that inflate Pixel Accuracy. Avoid it when boundary precision is the real concern: a mask can score Dice $> 0.9$ while its edges stay visibly ragged, so pair it with a boundary metric like Hausdorff distance.

\enlargethispage{\baselineskip}
\coloredboxes{
\item Robust to background imbalance. The formula never counts true-negative (background) pixels, so a model gets no credit for the easy, empty majority of the frame.
\item Balances precision and recall. Being the F1-score, it falls if a model over-segments (false positives) or misses parts of the object (false negatives) --- one cannot hide the other.
}
{
\item Not a true distance. It breaks the triangle inequality, so it can't be dropped into algorithms (clustering, nearest-neighbor search) that assume metric geometry.
\item Blind to boundary quality. A mask overlapping most of the target scores high even with a jagged outline, so two predictions with equal Dice can differ sharply at the edges.
}

\end{figure*}

\textbf{Figure. S{\o}rensen–Dice Coefficient.} Dice for three levels of overlap between a predicted mask and the ground truth. Only the intersection (cyan) counts toward the score, so as the masks drift apart Dice falls from $0.85$ to $0.25$. IoU is shown alongside --- always the stricter of the two.

\orangebox{Did you know that...}
{Because Dice is differentiable once you swap the hard $0/1$ masks for predicted probabilities, it doubles as a loss function: ``soft Dice loss'' trains many segmentation networks directly on the metric they are scored by, sidestepping the imbalance that trips up cross-entropy. (Dice and S{\o}rensen introduced the coefficient independently in $1940$s ecology.)}

\textbf{Other related metrics}

The Dice coefficient is mathematically equivalent to the F1-score and closely related to the Jaccard Index (IoU):
$Jaccard = \frac{Dice}{2 - Dice}$. For panoptic segmentation evaluation, see Panoptic Quality (PQ).

% ---------- Panoptic Quality ----------
% references: 
% https://openaccess.thecvf.com/content_CVPR_2019/papers/Kirillov_Panoptic_Segmentation_CVPR_2019_paper.pdf
% https://www.nature.com/articles/s41598-023-35605-7
\clearpage
\thispagestyle{cvstyle}
\section{PQ}
\subsection{Panoptic Quality}

In panoptic segmentation, every pixel gets a class and, for countable objects, an instance ID --- a street scene becomes ``road,'' ``sky,'' and ``car \#1, car \#2, car \#3'' at once. Panoptic Quality grades this in one number, scoring amorphous ``stuff'' (sky, road) and countable ``things'' (cars, people) on the same scale where older pipelines needed a separate metric for each.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                PQ = \frac{\sum_{(p,g) \in {\color{nmlcyan}TP}} IoU(p,g)}{|{\color{nmlcyan}TP}| + \frac{1}{2}|{\color{nmlpurple}FP}| + \frac{1}{2}|{\color{nmlred}FN}|}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.5,-0.1)$) to[bend left=15] node[pos=1, right] {matched segment pairs} +(1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.5,0.3)$) to[bend left=15] node[pos=1, left] {false positives} +(-1,-.5);
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(3.2,0.3)$) to[bend right=15] node[pos=1, right] {false negatives} +(1,-.5);
    }
\end{center}

It also splits into $PQ = SQ \times RQ$, both terms in $[0, 1]$: Segmentation Quality (SQ) is the average IoU of correctly matched segments, and Recognition Quality (RQ) is an F1-score on detection. So a low PQ tells you which half failed --- loose masks (low SQ) or missed and hallucinated objects (low RQ).

\textbf{When to use PQ?}

Use PQ for panoptic segmentation --- scene parsing for autonomous driving or robotics, where every pixel needs a label and individual objects (each car, each pedestrian) must be told apart. Avoid it when your task is only half of that: for semantic segmentation with no instances use mean IoU; for instance detection without dense ``stuff,'' use Average Precision (AP).


\enlargethispage{\baselineskip}
\coloredboxes{
\item One score for two sub-problems. Stuff and things are graded on the same scale, so you compare a whole scene parser end-to-end instead of juggling separate semantic and instance metrics.
\item Penalizes both error types. The $\frac{1}{2}|FP|$ and $\frac{1}{2}|FN|$ terms in the denominator dock a model for hallucinated segments and for missed ones, not just for sloppy overlap.
}
{
\item Every segment counts equally. A tiny mislabeled sign and a whole missed building move the score by the same amount, so PQ can understate errors on the regions that matter most.
\item Inherits IoU's boundary blindness. Matching uses IoU above $0.5$, so a segment can count as ``correct'' yet have a visibly wrong outline --- fine boundary quality goes unmeasured.
}

\textbf{Figure. PQ.} Since $PQ = SQ \times RQ$, each model is a point on the SQ--RQ plane and equal-PQ scores trace hyperbolas. Models B (segments well, misses objects) and C (finds objects, sloppy masks) give up opposite halves yet land on the same low contour --- a strong PQ needs both.

\orangebox{Did you know that...}
{The IoU $> 0.5$ matching rule hides a neat property: two segments cannot both overlap the same region by more than half, so each prediction matches \emph{at most one} ground-truth segment. The pairing is therefore unique --- no greedy or Hungarian assignment needed, unlike the matching step in object-detection metrics.}

\textbf{Other related metrics}

PQ decomposes into Segmentation Quality (SQ, average IoU of matched segments) and Recognition Quality (RQ, an F1-like score).
For semantic-only segmentation, use mean IoU. For instance-only, use Average Precision (AP).

\thispagestyle{cvstyle}
\section{SSIM}
\subsection{Structural Similarity Index}

SSIM scores how similar two images look to a person rather than how far apart their pixel values are. It compares them on three fronts --- luminance, contrast, and structure --- within small local windows, which is why it separates distortions that MSE and PSNR rate as identical: two images with the same MSE, one faintly brightened and one structurally blurred, earn the different scores a human would give them.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                SSIM(x,y) = \frac{(2{\color{nmlcyan}\mu_x}{\color{nmlpurple}\mu_y} + c_1)(2{\color{nmlred}\sigma_{xy}} + c_2)}{({\color{nmlcyan}\mu_x}^2 + {\color{nmlpurple}\mu_y}^2 + c_1)({\color{nmlcyan}\sigma_x}^2 + {\color{nmlpurple}\sigma_y}^2 + c_2)}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(-0.5,-0.1)$) to[bend right=15] node[pos=1, left] {statistics of image $x$} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(1.0,-0.1)$) to[bend left=15] node[pos=1, right] {statistics of image $y$} +(1,.5);
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(0.5,0.5)$) to[bend left=15] node[pos=1, left] {cross-covariance} +(-1,-.5);
    }
\end{center}

SSIM ranges from $-1$ to $1$, though on natural images it rarely falls below $0$; a score of $1$ means the two images are structurally identical. As practical anchors, SSIM above $0.95$ usually looks near-perfect to a viewer, while values near $0.7$ show clearly visible degradation.

\textbf{When to use SSIM?}

Use SSIM for image compression, denoising, and super-resolution where a human views the result --- it is the standard companion to PSNR. Avoid it when images aren't spatially aligned, since it assumes pixel correspondence and a small shift or crop tanks the score at unchanged quality; for learned perceptual similarity across differing content, use LPIPS.

\enlargethispage{\baselineskip}
\coloredboxes{
\item Tracks perception. Scoring luminance, contrast, and structure separately, SSIM agrees with human quality ratings far more often than MSE or PSNR --- the reason it became the standard.
\item Produces a quality map. Computed over local windows, it yields a per-region score, so you can see where an image degraded instead of reading one global number.
}
{
\item A global average hides local damage. The reported SSIM is the mean over all windows, so one badly corrupted region can be masked by many clean ones --- read the SSIM map, not just the number.
\item Single-scale. Classic SSIM fixes one window size and misses distortions that appear only at coarser or finer scales; MS-SSIM evaluates several scales and is usually preferred.
}
