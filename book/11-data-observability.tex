% ---------- Expected Range ----------
\clearpage
\thispagestyle{observabilitystyle}
\section{Expected Range}\label{sec:expected-range}
\subsection{Comparing a Metric with Its History}

An expected range describes the values a monitor considers normal. A measurement outside it is flagged for investigation, not automatically treated as a data error. The example below uses a baseline $\mu_t$ and a spread $\sigma_t$ estimated from earlier measurements.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{anomaly at } t \iff \big|\, {\color{nmlcyan}x_t} - {\color{nmlpurple}\mu_t} \,\big| > {\color{nmlyellow}z}\, {\color{nmlpurple}\sigma_t}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.94,-0.26)$) to[bend right=15] node[pos=1, left] {today's measurement} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(1.95,-0.24)$) to[bend left=15] node[pos=1, right] {baseline from history} +(0.25,.5);
        \draw[overlay,-latex,nmlyellow, semithick] ($(a.south)+(3.28,0.23)$) to[bend right=15] node[pos=1, left] {sensitivity} +(-0.8,-.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(3.66,0.15)$) to[bend left=15] node[pos=1, right] {spread of history} +(-0.55,-.5);
    }
\end{center}

Here, $z$ controls the width: a smaller value flags more deviations; a larger one flags fewer. Three standard deviations is a common starting point, not a universal default. Available settings depend on the implementation. A useful monitor also lets people label alerts as expected or unexpected, so its baseline or alert rules can be adjusted.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_expected_range.png}
\end{center}

\textbf{Figure. Expected Range.} Simulated daily order counts. \underline{Left:} the first $21$ days establish a mean for each weekday and a pooled spread of about $200$ rows. \underline{Right:} subsequent counts are checked against the weekday mean $\pm 3\sigma$, updated using unflagged observations. Days $26$ and $31$ fall below the range; lower weekend counts are expected.

\textbf{When to use it?}

Use historical ranges when a metric varies predictably over time. Match the baseline to patterns such as weekdays and weekends, and tune it to the cost of missed incidents and false alerts. Use fixed rules for known requirements, such as zero duplicate keys. This example detector illustrates the approach; production implementations differ.

% ---------- Row Count ----------
\clearpage
\thispagestyle{observabilitystyle}
\section{Row Count}\label{sec:row-count}
\subsection{Volume}

Row count is the number of rows in a table or a selected part of it. Tracking it over time helps identify missing, incomplete or repeated loads. In this chapter, each measurement counts the rows received on one day, called a daily partition.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{rows}_{t} = \sum_{r \in T} \mathds{1}\big[\, {\color{nmlcyan}p(r)} = {\color{nmlpurple}t} \,\big]
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(0.9,0.3)$) to[bend left=15] node[pos=1, left] {row's partition value} +(-1,-.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(1.7,-0.2)$) to[bend left=15] node[pos=1, right] {the partition being scanned} +(0.6,.5);
    }
\end{center}

Here, $T$ is the table and $p(r)$ is row $r$'s partition date. The formula counts rows whose date matches the day being checked, equivalent to a filtered SQL \texttt{COUNT(*)}. A count from database metadata may be faster, but can be approximate or delayed and may cover the whole table.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_row_count.png}
\end{center}

\textbf{Figure. Row Count.} Daily counts for a simulated orders table. No rows arrive on day $26$; only $2{,}600$ arrive on day $31$. Both fall below the expected range. On day $36$, repeating $6\%$ of the load raises the count to $5{,}358$, still within the range. A normal count does not guarantee that the rows are correct or unique.

\textbf{When to use it?}

Use it to check the volume of scheduled loads. Compare the same time window at each scan and allow for weekly patterns. If rows can arrive late, recheck earlier partitions or group by arrival time. For irregular loads, compare against an expected batch size or schedule rather than a daily historical range.

% ---------- Freshness ----------
\clearpage
\thispagestyle{observabilitystyle}
\section{Freshness}\label{sec:freshness}
\subsection{Most Recent Timestamp}

Freshness is the time since the latest timestamp in a chosen column. It shows how old the most recent data is at scan time. An arrival timestamp measures when data last reached the table; an event timestamp measures when the latest recorded event occurred.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{freshness}_t = {\color{nmlpurple}t_{\text{scan}}} - \max_{r \in T} {\color{nmlcyan}\text{ts}(r)}
                $
            }
        };
        \path[room for labels] ([yshift=0.57cm]a.north) ([yshift=-0.00cm]a.south);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(0.19,-0.09)$) to[bend right=15] node[pos=1, left] {time of the scan} +(-1.00,0.30);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(2.76,-0.03)$) to node[pos=1, above] {newest timestamp} +(0.00,0.30);
    }
\end{center}

The maximum is taken over the table $T$, ignoring null timestamps. If the latest arrival is at 01:30 and the scan is at 06:00, freshness is $4.5$ hours. Some databases expose a last-modified timestamp in metadata. That records a table update, which need not mean that newer events arrived.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_freshness.png}
\end{center}

\textbf{Figure. Freshness.} The orders table is scanned at 06:00 each day, usually $4.5$ hours after its latest arrival. No load arrives on day $26$, so freshness reaches $28.5$ hours. On day $31$, the load stops early and freshness reaches $5.6$ hours. Both exceed the expected range.

\textbf{When to use it?}

Use it when data must arrive before a deadline. Choose the timestamp to match that requirement and account for time zones and the loading schedule. Pair it with a volume check: one recent row can make an incomplete table appear fresh. If all timestamps are null, report a missing measurement rather than zero age.

% ---------- Schema Changes ----------
\clearpage
\thispagestyle{observabilitystyle}
\section{Schema Changes}\label{sec:schema-changes}
\subsection{Columns and Types}

Schema monitoring detects changes to a table's column names and data types. For example, a removed column can break a query, while a numeric type change can affect precision. A change needs review, but may be intentional.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \Delta_t = {\color{nmlcyan}S_t} \,\triangle\, {\color{nmlpurple}S_{t-1}}, \qquad \text{anomaly} \iff \Delta_t \neq \varnothing
                $
            }
        };
        \path[room for labels] ([yshift=0.50cm]a.north) ([yshift=-0.47cm]a.south);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(-3.34,-0.03)$) to node[pos=1, above] {columns and types now} +(0.00,0.22);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(-1.69,0.07)$) to node[pos=1, below] {at the previous scan} +(0.00,-0.22);
    }
\end{center}

Each schema $S_t$ is a set of column-name and type pairs. The symmetric difference $\triangle$ lists pairs present in only one scan. A type change or rename appears as an old pair removed and a new one added. This check flags any difference; an approved schema can also serve as the reference.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_schema.png}
\end{center}

\textbf{Figure. Schema Changes.} \underline{Left:} the table grows from six columns to seven on day $34$. \underline{Right:} \texttt{discount\_pct} is added and \texttt{amount} changes from \texttt{DECIMAL(10,2)} to \texttt{FLOAT}. Counting columns detects the addition but would miss the type change alone.

\textbf{When to use it?}

Use it on tables that feed queries, applications or models. Review whether each change is compatible with those consumers. This check covers names and types only: a switch from dollars to cents can leave both unchanged. Monitor values as well as structure.

% ---------- Missing Values ----------
\clearpage
\thispagestyle{observabilitystyle}
\section{Missing Values}\label{sec:missing-values}
\subsection{Completeness}

Missing values percentage is the share of rows whose value in a selected column is null. It measures completeness. For example, a rise in missing country codes can indicate that a source field is no longer being loaded correctly.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{missing}\%_t = 100 \cdot \left( 1 - \frac{{\color{nmlcyan}\text{count}(c)}}{{\color{nmlred}\text{count}(*)}} \right)
                $
            }
        };
        \path[room for labels] ([yshift=0.24cm]a.north) ([yshift=-0.19cm]a.south);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(2.37,-0.04)$) to[bend right=15] node[pos=1, left] {non-null values in the column} +(-1.00,0.30);
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(2.29,0.10)$) to[bend left=15] node[pos=1, left] {rows in the partition} +(-1.00,-0.30);
    }
\end{center}

Both counts use the same partition: $\text{count}(*)$ counts all rows and $\text{count}(c)$ counts rows where column $c$ is not null. If $20$ of $100$ rows are null, the result is $20\%$. Empty strings and placeholders such as \texttt{N/A} need separate rules; they are not SQL nulls.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_missing.png}
\end{center}

\textbf{Figure. Missing Values.} About $2\%$ of country values are normally null. On day $29$, a simulated source-field rename raises this to $41\%$, outside the expected range. The hollow marker on day $26$ means no rows arrived: the percentage is undefined, not $0\%$.

\textbf{When to use it?}

Use it on fields needed for joins, reporting or model features. Set the acceptable level from the field's purpose: optional fields may legitimately contain nulls. A stable percentage does not prove completeness, and replacing nulls with a placeholder can hide a problem from this check.

% ---------- Duplicates ----------
\clearpage
\thispagestyle{observabilitystyle}
\section{Duplicates}\label{sec:duplicates}
\subsection{Uniqueness}

Duplicate percentage measures how many records share a value that should identify them uniquely. Here, it is the percentage of non-null records whose key occurs more than once, counting every copy. A repeated batch can inflate totals even when the overall row count looks normal.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{dup}\%_t = 100 \cdot \frac{1}{{\color{nmlred}|R|}} \sum_{r \in R} \mathds{1}\big[\, {\color{nmlred}n(v_r)} > 1 \,\big]
                $
            }
        };
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-0.29,0.25)$) to node[pos=1, below] {records with a non-null value} +(0.00,-0.30);
        \draw[overlay,-latex,nmlred, semithick] ($(a.north)+(2.10,-0.33)$) to node[pos=1, above] {how often record $r$'s value occurs} +(0.00,0.33);
    }
\end{center}

The set $R$ contains records with non-null keys, and $n(v_r)$ counts occurrences of record $r$'s key. For $[1,1,2,\text{null},\text{null}]$, both records with key $1$ count as duplicates: $2/3 \approx 66.7\%$. Other definitions count only extra copies; check which convention your tool uses.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_duplicates.png}
\end{center}

\textbf{Figure. Duplicates.} Daily duplicate percentages for order IDs. On day $36$, $6\%$ of the original records are inserted a second time. Per $100$ original records, $12$ of the resulting $106$ records now share a key, giving about $11.3\%$. All other non-empty days have unique order IDs.

\textbf{When to use it?}

Use it on a key, or combination of columns, expected to be unique in the scanned data. A fixed zero-tolerance rule is clearer than a learned range when duplicates are never valid. Check null keys separately and include earlier data if uniqueness must hold across partitions.

% ---------- Unique Count ----------
\clearpage
\thispagestyle{observabilitystyle}
\section{Unique Count}\label{sec:unique-count}
\subsection{Cardinality}

Unique count tells you how many different values appear in a column. Each value counts once, even if it appears in many rows. Nulls are excluded. In an orders table, counting unique customer IDs tells you how many different customers placed an order.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \text{unique}_t = \big|\, \{\, {\color{nmlcyan}c(r)} : r \in P_t,\; c(r) \neq \text{null} \,\} \,\big|
                $
            }
        };
        \path[room for labels] ([yshift=0.55cm]a.north) ([yshift=-0.00cm]a.south);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(-1.02,-0.09)$) to node[pos=1, above] {value of the column in row $r$} +(0.00,0.33);
    }
\end{center}

Here, $P_t$ is the group of rows being checked and $c(r)$ is the value in each row. For example, customer IDs $[101,101,205,\text{null}]$ give a unique count of $2$: only $101$ and $205$ are counted.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_unique_count.png}
\end{center}

\textbf{Figure. Unique Count.} Three days from the simulated orders table. On day $31$, fewer orders arrive, so fewer customers appear. On day $38$, the load size is normal, but an error keeps only the last three digits of each customer ID. Different IDs become identical, leaving just $995$ unique values. Comparing both counts helps distinguish these two problems.

\textbf{When to use it?}

Use it to monitor customer IDs, product codes or categories such as countries. If unique count falls, check whether fewer rows arrived before investigating the values. It counts different values but does not tell you what they are: replacing one country code with another can leave the count unchanged.

% ---------- Average ----------
\clearpage
\thispagestyle{observabilitystyle}
\section{Average}\label{sec:average}
\subsection{Mean}

The average is the sum of a column's non-null numeric values divided by their count. It summarizes their level in the same units as the data. For order amounts, a change may reflect different prices, a different mix of orders or a data error.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \bar{x}_t = \frac{1}{{\color{nmlred}n_t}} \sum_{r \in P_t} {\color{nmlcyan}x(r)}
                $
            }
        };
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-0.40,0.33)$) to node[pos=1, below] {non-null values in the partition} +(0.00,-0.30);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.30,-0.33)$) to[bend right=15] node[pos=1, left] {numeric value in row $r$} +(-1.00,0.61);
    }
\end{center}

Here, $n_t$ counts non-null values in partition $P_t$; nulls are omitted from the sum. For $[10,20,30]$, the average is $20$. Extreme values can move it substantially, while increases and decreases can cancel out. An unchanged average does not imply an unchanged distribution.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_average.png}
\end{center}

\textbf{Figure. Average.} Daily mean order amount. On day $23$, roughly $5\%$ of amounts are multiplied by $100$, raising the mean from about $44$ to $252$ (above the plotted scale). Negative refunds on day $32$ and a discount on amounts below $30$ on day $40$ lower the mean. All three changes are flagged.

\textbf{When to use it?}

Use it for numeric measures such as prices, durations and quantities. Check spread and quartiles to understand what changed. For skewed data, the median is less sensitive to a few extreme values. A flagged change may be legitimate, such as a promotion, rather than a loading error.

% ---------- Sum ----------
\clearpage
\thispagestyle{observabilitystyle}
\section{Sum}\label{sec:sum}
\subsection{Total}

The sum is the total of the non-null values in a numeric column. It can track daily revenue, units sold or another additive quantity. The total changes when the number of values changes, their average changes, or both.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \Sigma_t = \sum_{r \in P_t} {\color{nmlcyan}x(r)} = {\color{nmlred}n_t} \cdot {\color{nmlpurple}\bar{x}_t}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(-0.2,-0.2)$) to[bend right=15] node[pos=1, left] {numeric value in row $r$} +(-0.8,.5);
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(1.4,0.3)$) to[bend left=15] node[pos=1, left] {non-null values} +(-0.4,-.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.2,-0.2)$) to[bend left=15] node[pos=1, right] {mean} +(0.6,.5);
    }
\end{center}

For at least one non-null value, the total equals the non-null count $n_t$ times the mean $\bar{x}_t$. Use both to investigate a change. Nulls are ignored; SQL \texttt{SUM} returns null when there are no non-null inputs. Replacing that result with zero should be an explicit choice.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_sum.png}
\end{center}

\textbf{Figure. Sum.} Daily total order amount. On day $23$, multiplying roughly $5\%$ of amounts by $100$ raises the total above the plotted scale. The incomplete load on day $31$ roughly halves it. The discount on day $40$ stays within the range, showing that a moderate price change can go unflagged when daily volume also varies.

\textbf{When to use it?}

Use it when downstream reports depend on a total. Pair it with the count of non-null values and the average to distinguish changes in volume from changes in value. Monitor missing values too: losing positive amounts lowers the total, while losing negative amounts can raise it.

% ---------- Standard Deviation ----------
\clearpage
\thispagestyle{observabilitystyle}
\section{Standard Deviation}\label{sec:standard-deviation}
\subsection{Spread}

Standard deviation measures how widely numeric values are spread around their mean. It has the same units as the data. Values $[20,20,20]$ and $[10,20,30]$ share a mean of $20$, but only the second set has a non-zero standard deviation.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                s_t = \sqrt{ \frac{1}{{\color{nmlred}n_t} - 1} \sum_{r \in P_t} \big( {\color{nmlcyan}x(r)} - {\color{nmlpurple}\bar{x}_t} \big)^2 }
                $
            }
        };
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-0.9,0.3)$) to[bend left=15] node[pos=1, left] {non-null values} +(-0.6,-.5);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.0,-0.2)$) to[bend right=15] node[pos=1, left] {value in row $r$} +(-0.8,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.3,-0.2)$) to[bend left=15] node[pos=1, right] {partition mean} +(0.6,.5);
    }
\end{center}

The formula uses the sample convention, dividing by $n_t-1$, with nulls excluded and at least two values required. The population convention divides by $n_t$ instead. Squared deviations make both sensitive to extreme values; variance is the square of standard deviation.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_stddev.png}
\end{center}

\textbf{Figure. Standard Deviation.} Daily spread of order amounts. On day $23$, multiplying roughly $5\%$ of amounts by $100$ increases the spread about fortyfold, above the plotted scale. Negative refunds on day $32$ and discounts on amounts below $30$ on day $40$ also widen the spread and are flagged.

\textbf{When to use it?}

Use it alongside the mean to detect changes in variability. Adding the same constant to every value changes the mean but leaves standard deviation unchanged. With heavy-tailed data, inspect extreme values before treating an alert as an error; quartiles give a less outlier-sensitive view of the central values.

% ---------- Min / Max ----------
\clearpage
\thispagestyle{observabilitystyle}
\section{Min and Max}\label{sec:min-and-max}
\subsection{Range}

Minimum and maximum are the smallest and largest non-null values in a column. They track the extremes of the observed range. A single negative amount, invalid date or unusually large quantity can change one of them even if most rows remain unchanged.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \min_t = \min_{r \in P_t} {\color{nmlcyan}x(r)}, \qquad \max_t = \max_{r \in P_t} {\color{nmlpurple}x(r)}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(-1.17,-0.04)$) to node[pos=1, above] {smallest non-null value} +(0.00,0.30);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(3.74,-0.04)$) to node[pos=1, above] {largest non-null value} +(0.00,0.30);
    }
\end{center}

Both are computed over partition $P_t$, ignoring nulls. They are aggregate statistics determined by individual observations, so one row can trigger an alert. A larger partition also has more opportunities to contain an extreme value, even without a change in the underlying distribution.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_min_max.png}
\end{center}

\textbf{Figure. Min and Max.} Daily order-amount extremes. \underline{Left:} negative refunds on day $32$ lower the minimum to $-121$; discounts on day $40$ reduce it to $1.86$. \underline{Right:} a unit error on day $23$ raises the maximum to $22{,}410$, above the scale. Day $29$ flags a valid $487$ order: unusual does not necessarily mean wrong.

\textbf{When to use it?}

Use fixed bounds for known constraints, such as non-negative quantities, and historical ranges to identify unusual extremes. Allow for legitimate changes in volume and rare large values. These metrics do not show how many rows are affected; add an invalid-value count when that matters.

% ---------- Quartiles ----------
\clearpage
\thispagestyle{observabilitystyle}
\section{Quartiles}\label{sec:quartiles}
\subsection{Q1, Median, Q3}

Quartiles locate the $25$th, $50$th and $75$th percentiles of a numeric column. The middle quartile is the median; the distance from Q1 to Q3 is the interquartile range. Together, they describe the center and spread of the middle half of the values.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                Q_{{\color{nmlyellow}p}}(t) = \inf \big\{\, x : {\color{nmlcyan}F_t}(x) \geq {\color{nmlyellow}p} \,\big\}, \qquad p \in \{0.25, 0.5, 0.75\}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.south)+(-1.76,0.15)$) to node[pos=1, below] {share of values at or below $x$} +(0.00,-0.30);
        \draw[overlay,-latex,nmlyellow, semithick] ($(a.south)+(-0.21,0.13)$) to[bend right=15] node[pos=1, right] {the quantile level} +(1.00,-0.33);
    }
\end{center}

The function $F_t(x)$ is the share of non-null values at or below $x$. The formula selects the first value reaching the required share. Sample quantile methods differ; the figures use linear interpolation. Extreme values can shift quartiles, but their magnitude has much less influence than it has on the mean.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_quartiles.png}
\end{center}

\textbf{Figure. Quartiles.} Daily order-amount quartiles, with the mean dashed. On day $23$, multiplying roughly $5\%$ of amounts by $100$ sends the mean above the scale; Q3 rises modestly and is flagged. On day $40$, halving amounts below $30$ lowers Q1 from about $25$ to $12$, leaving that day's median and Q3 unchanged.

\textbf{When to use it?}

Use quartiles to track typical values and spread, especially in skewed distributions. Use the same quantile method when comparing systems. They summarize only three positions: tail errors or changes elsewhere can go unnoticed. Check extremes or additional percentiles when those parts of the distribution matter.

\section{Text Length}\label{sec:text-length}
\subsection{Format}

Text length is the number of characters in a non-null string. Its average, minimum and maximum summarize lengths within a partition. These checks can detect truncation, missing prefixes or a change in code format without needing to interpret the text.

% equation
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                \overline{\ell}_t = \frac{1}{{\color{nmlred}n_t}} \sum_{r \in P_t} {\color{nmlcyan}\text{len}}\big(s(r)\big)
                $
            }
        };
        \path[room for labels] ([yshift=0.30cm]a.north) ([yshift=-0.00cm]a.south);
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(-0.99,0.33)$) to[bend left=15] node[pos=1, left] {non-null strings} +(-1.00,-0.30);
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.56,-0.34)$) to[bend right=15] node[pos=1, left] {characters in the string} +(-1.00,0.62);
    }
\end{center}

The formula averages lengths over the $n_t$ non-null strings in $P_t$. Empty strings have length zero and are included. A fixed-width code should have equal minimum, average and maximum lengths. Use character length rather than byte length when multibyte characters are possible.

\begin{center}
    \includegraphics[width=\textwidth]{figures/Observability_text_length.png}
\end{center}

\textbf{Figure. Text Length.} Daily mean length of a simulated phone field. Values normally have eleven characters, including punctuation. On day $28$, roughly $60\%$ change to seven-character strings and the mean falls to $8.7$. They remain non-null text values, so a null check or data-type check would not detect this change.

\textbf{When to use it?}

Use it on fields with predictable lengths, such as product codes and formatted identifiers. A correct length does not guarantee a valid value; combine it with format checks. For free text, changes in length may be useful, but need a baseline that allows for normal variation.
