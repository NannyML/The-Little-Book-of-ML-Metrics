\chapteropener{Clustering}{orangelight}{orangeaccent}{%
Clustering groups similar observations without requiring predefined categories. For a collection of documents, the aim might be to find groups of texts about similar topics. We represent each document through numerical features, and a clustering algorithm uses those features to decide which documents belong together.

If the documents already have topic labels, we can use them to evaluate the groups the algorithm found. We check whether documents about the same topic stayed together and whether different topics got mixed into one cluster. These comparisons are called \textit{external} evaluations because they judge the clusters against another grouping. The labels serve as a reference for evaluation; the algorithm did not use them to form the clusters.

Without topic labels, we can still examine how close the documents in each cluster are to one another and how far apart the clusters are. These \textit{internal} evaluations use the numerical features and a measure of distance to assess the grouping. This chapter covers both approaches, explaining what we can learn from each when comparing clustering results.}{In this chapter}

\metricentry{Mutual Info Score}{Mutual Info Score}\label{sec:mutual-info-score}

Mutual Information (MI) measures how much one labeling tells us about another. In clustering, it asks how much knowing the cluster reduces uncertainty about the reference class. If the data contain $90\%$ class A and $10\%$ class B, and every cluster repeats those proportions, the cluster label adds no information: MI is zero.

% Formula
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                MI({\color{nmlcyan}U}, {\color{nmlpurple}V}) = \sum_{i=1}^{|{\color{nmlcyan}U}|} \sum_{j=1}^{|{\color{nmlpurple}V}|} \frac{|{\color{nmlcyan}U_i} \cap {\color{nmlpurple}V_j}|}{{\color{nmlred}N}} \log \frac{{\color{nmlred}N}\, |{\color{nmlcyan}U_i} \cap {\color{nmlpurple}V_j}|}{|{\color{nmlcyan}U_i}|\, |{\color{nmlpurple}V_j}|}
                $
            }
        };
        \draw[-latex,nmlcyan, semithick] ($(a.north)+(-1.67,-0.10)$) to[bend right=15] node[pos=1, left] {true labels} +(-1.00,0.30);
        \draw[-latex,nmlpurple, semithick] ($(a.north)+(-0.84,-0.10)$) to[bend left=15] node[pos=1, right] {predicted labels} +(1.00,0.30);
        \draw[-latex,nmlred, semithick] ($(a.south)+(0.60,0.42)$) to[bend left=15] node[pos=1, left] {total samples} +(-1.00,-0.51);
    }
\end{metricformula}

Entropy measures uncertainty in a labeling. MI is at least zero and cannot exceed the smaller of the two label entropies. For three balanced classes, the class entropy is $\log 3 \approx 1.099$ nats with natural logarithms. The ceiling varies with the labelings, so raw MI has no universal upper bound.

\metricheading{When to use}

Use MI to compare clusters with reference classes, or two clustering runs on the same observations. A larger value means the labelings share more information. When comparing results with different numbers of clusters, consider the normalized and chance-adjusted versions described below.


\coloredboxes{
    \item Renaming clusters leaves MI unchanged. Labels $[0,0,1]$ and $[1,1,0]$ keep the first two points together and the third separate.
    \item Symmetric in its inputs, so either clustering can serve as the reference for an agreement comparison.
}
{
    \item Raw MI can stay maximal when pure clusters are split further; it does not penalize that fragmentation.
    \item Requires two labelings. Their agreement alone does not show that either grouping is useful.
}

\metricsecondpage
\thispagestyle{customstyle}

\begin{metricfigure}
    \centering
    \includegraphics[width=\textwidth]{figures/MI_contingency_contributions.png}
\end{metricfigure}

\metriccaption{Figure. Mutual Info Score.}{Each cell gives a count and its contribution to MI. A nonempty cell contributes positively when its share exceeds what independent class and cluster labels would imply, and negatively when it falls below that expectation. Empty cells contribute zero. The left table totals $1.099$ nats, the entropy of three balanced classes; the right totals $0.724$. Cluster names are arbitrary, so a cell's position on the diagonal does not determine its contribution.}

\orangebox{Did you know that...}
{MI is the Kullback-Leibler divergence between the joint distribution of two labelings and the product of their marginals. If clusters and classes were statistically independent, MI would be exactly $0$ --- so MI literally measures how far the two labelings are from being independent. This is also why MI shows up in feature selection: the same formula measures how much a feature tells you about a target.}

\metricheading{Related metrics}\metricsecondary

Normalized Mutual Information (NMI) rescales MI to $[0,1]$ using the uncertainty in the two labelings. Several normalizations exist, so use the same version when comparing results. NMI still counts information shared by chance, which can be substantial when there are many clusters for few observations.

Adjusted Mutual Information (AMI) accounts for this by subtracting the MI expected from random assignments with the same group sizes, then rescaling the result. A score of $0$ matches that chance baseline. These variants help interpret agreement on the same observations; their scales alone do not make scores from unrelated datasets comparable.

\metricentry{Rand Index}{Rand Index}\label{sec:rand-index}

The Rand Index (RI) measures how often two groupings agree about a pair of points. They agree if both put the pair together or both separate it. RI divides the number of agreeing pairs by all pairs. Because some agreement occurs by chance, the Adjusted Rand Index (ARI) compares the observed agreement with a random-labeling baseline.

\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                RI = \frac{{\color{nmlcyan}TP} + {\color{nmlcyan}TN}}{{\color{nmlcyan}TP} + {\color{nmlcyan}TN} + {\color{nmlpurple}FP} + {\color{nmlpurple}FN}}
                $
            }
        };

        \draw[-latex,nmlcyan, semithick] ($(a.north)+(-0.07,-0.03)$) to[bend right=15] node[pos=1, left] {agreeing pairs} +(-1.00,0.30);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(1.31,0.09)$) to[bend left=15] node[pos=1, left] {disagreeing pairs} +(-1.00,-0.30);
    }
\end{metricformula}

RI ranges from $0$ to $1$. Independent, roughly balanced assignments to three groups give RI near $0.56$, not zero. The baseline depends on both sets of group sizes. ARI subtracts that expected agreement and rescales what remains: $0$ means agreement at the baseline, $1$ means matching groupings, and negative values indicate less agreement than expected.

\metricheading{When to use}

Use RI to describe pairwise agreement and ARI when comparing against chance. Both can compare two clustering runs without designating either as truth. Large groups contribute many more pairs than small ones, so inspect small reference classes in the contingency table rather than relying only on the aggregate.

\coloredboxes{
    \item Symmetric: swapping the two groupings returns the same RI or ARI, so neither needs to be designated as the reference.
    \item ARI provides a baseline at $0$, accounting for chance agreement under fixed group sizes.
}
{
    \item Raw RI can be high by chance. Its baseline depends on both groupings, not just the predicted cluster count.
    \item Pair weighting gives large groups more influence. Chance correction does not remove every effect of unequal group sizes.
}

\thispagestyle{customstyle}

\begin{metricfigure}
    \centering
    \includegraphics[width=\textwidth]{figures/Rand_Index_separation.png}
\end{metricfigure}

\metriccaption{Figure. Rand Index.}{Three clusterings of $300$ points in three balanced reference classes. RI is $1.00$ for the matching grouping, $0.90$ with partial overlap and $0.56$ for random assignments. In this example, many pairs are separated by both labelings even under random assignment. ARI accounts for that baseline, giving a value near zero in the random case.}

\orangebox{Did you know that...}
{RI is the accuracy of a pairwise decision: together or apart. Group sizes influence how many such decisions each class contributes. A class of $100$ points contains $4{,}950$ within-class pairs; one of ten contains just $45$. That difference helps explain why good overall pairwise agreement can hide poor recovery of a small class.}

\metricheading{Related metrics}\metricsecondary

RI and MI summarize agreement differently, while ARI and AMI also use chance baselines. A disagreement between their scores does not by itself identify a cause. The Pair Confusion Matrix separates the two kinds of pairwise error; the Contingency Matrix shows which classes and clusters overlap.

\metricentry{CH Index}{Calinski-Harabasz Index (CH Index)}\label{sec:ch-index}

The Calinski-Harabasz (CH) Index compares how spread out cluster centers are with how spread out points are inside their clusters. A higher score favors compact groups whose centers are well separated. We can calculate it without reference labels, using the points and their assigned clusters.

\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                CH = \frac{{\color{nmlcyan}BCSS} / ({\color{nmlred}k} - 1)}{{\color{nmlpurple}WCSS} / ({\color{nmlred}N} - {\color{nmlred}k})}
                $
            }
        };
        \draw[-latex,nmlcyan, semithick] ($(a.north)+(-0.19,-0.04)$) to[bend right=15] node[pos=1, left] {between-cluster sum} +(-1.00,0.30);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(-0.83,0.16)$) to[bend left=15] node[pos=1, left] {within-cluster sum} +(-1.00,-0.30);
        \draw[-latex,nmlred, semithick] ($(a.south)+(2.18,0.16)$) to node[pos=1, below] {clusters and samples} +(0.00,-0.39);
    }
\end{metricformula}

The within-cluster sum of squares ($WCSS$) adds the squared distances from points to their own cluster centers. The between-cluster sum of squares ($BCSS$) adds the squared distances from each cluster center to the overall center, weighted by cluster size. The factors $k-1$ and $N-k$ adjust the ratio for the number of clusters $k$ and observations $N$.

\metricheading{When to use}

Use CH to compare clusterings of the same data, including different choices of cluster count. Keep the features and their scaling fixed so that the scores describe the same distances. The highest score identifies the grouping CH favors among those tested.


\coloredboxes{
    \item Fast for a fitted clustering: it uses cluster centers and point-to-center distances rather than all point pairs.
    \item Adjusts for cluster count, allowing candidate values of $k$ to be compared on the same data.
}
{
    \item Uses Euclidean geometry. It may not reflect groupings based on other distances, such as cosine distance between text embeddings.
    \item Favors compact groups around centers. Curved or nested clusters may score poorly even when they are useful.
}

\metricsecondpage
\thispagestyle{customstyle}

\begin{metricfigure}
    \centering
    \includegraphics[width=.82\textwidth]{figures/Calinski_Harabasz_elbow.png}
\end{metricfigure}

\metriccaption{Figure. CH Index.}{These are k-means fits to the same simulated data with four groups. Among the tested cluster counts, CH reaches its maximum at $k=4$ and falls as the groups are split further. Here the criterion agrees with the generating setup; a score maximum does not generally establish a true number of clusters.}

\orangebox{Did you know that...}
{Caliński and Harabasz introduced this variance-ratio criterion in 1974. It resembles the F-statistic from one-way ANOVA and is often called a pseudo-F statistic. But clustering has already used the data to form separated groups, so the usual ANOVA significance interpretation does not follow. A high CH score is not a p-value.}

\metricheading{Related metrics}\metricsecondary

Davies-Bouldin also compares spread with separation, but lower values are preferred. Silhouette compares each point's average distances within and outside its cluster. The criteria can favor different clusterings; inspect the candidate groups to understand what each score rewards.

\metricentry{Contingency Matrix}{Contingency Matrix}\label{sec:contingency-matrix}

The Contingency Matrix is the clustering analog of a confusion matrix: rows are true classes, columns are predicted clusters, and cell $(i, j)$ counts the points that belong to class $i$ and ended up in cluster $j$. Unlike a confusion matrix, the row and column index sets do not have to match --- $5$ true classes and $7$ predicted clusters give a $5 \times 7$ matrix, not a square one.

\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                {\color{nmlcyan}M_{ij}} = \left|\{\, x : {\color{nmlpurple}\text{class}(x) = i},\; {\color{nmlpurple}\text{cluster}(x) = j} \,\}\right|
                $
            }
        };
        \draw[-latex,nmlcyan, semithick] ($(a.north)+(-4.33,-0.06)$) to node[pos=1, above] {cell at row $i$, col $j$} +(0.00,0.30);
        \draw[-latex,nmlpurple, semithick] ($(a.north)+(1.98,-0.04)$) to node[pos=1, above] {points in class $i$ and cluster $j$} +(0.00,0.30);
    }
\end{metricformula}

Cluster numbers need not match class numbers: renaming clusters just reorders the columns. Read across a row to see whether a class was split, and down a column to see whether a cluster mixes classes. Diagonal agreement is meaningful only after aligning the labels. Row and column totals give class and cluster sizes.

\metricheading{When to use}

Use the matrix when you have reference labels and need to see which groups split or mix. A single NMI or ARI value hides those details. For large tables, reorder or inspect selected rows and columns to make the pattern easier to follow, then use a summary metric for overall comparison.

\coloredboxes{
    \item Reveals the structure of clustering errors. An NMI of $0.7$ does not tell you whether class A leaked into cluster B or got split across three clusters --- the matrix does, in one glance.
    \item Provides the counts used by NMI, ARI, V-Measure, Homogeneity and Completeness.
}
{
    \item Does not summarize to a single number, so it can't be used directly to optimize hyperparameters or rank algorithms --- you have to derive a scalar first.
    \item Many classes and clusters can make a dense table hard to read. Reordering or selecting rows and columns can reveal patterns hidden in the full display.
}

\thispagestyle{customstyle}

    \centering

\end{metricfigure}

\metriccaption{Figure. Contingency Matrix.}{This example has three classes of $100$ points each. The columns have been reordered to align clusters with classes, so the diagonal shows $100$, $95$ and $99$ matching points. Class $1$ has four points assigned to cluster $0$ and one to cluster $2$. Without that alignment, large off-diagonal counts would not necessarily indicate mistakes.}

\orangebox{Did you know that...}
{The external scores covered here can all be calculated from this table. Its cells preserve which classes and clusters overlap, while the margins give their sizes. Pair-counting metrics summarize which points stay together; information-based metrics summarize how much one labeling tells us about the other. The same table therefore supports several different questions.}

\metricheading{Related metrics}\metricsecondary

The Pair Confusion Matrix collapses the contingency matrix to a $2 \times 2$ table by counting \emph{pairs} of points instead of individual points, which is what powers the pair-counting family (RI, ARI, FMI). When $k \neq C$, the Pair Confusion Matrix still works, but the class-vs-cluster diagnostic detail is gone --- you trade granularity for a tidy summary.

\thispagestyle{clusteringstyle}
\metricentry{Pair Confusion Matrix}{Pair Confusion Matrix}\label{sec:pair-confusion-matrix}

The Pair Confusion Matrix is a $2 \times 2$ table that summarizes, for every pair of points, whether two clusterings agree on keeping the pair together or separating it. It collapses arbitrary clusterings (any $k$, any $C$) into the same four-entry summary, which is the structure that powers RI, ARI, and the Fowlkes-Mallows Index.

\begin{center}
    $\displaystyle
    C = \begin{bmatrix}
        {\color{nmlcyan}C_{00}} & {\color{nmlpurple}C_{01}} \\
        {\color{nmlpurple}C_{10}} & {\color{nmlcyan}C_{11}}
    \end{bmatrix}
    $
\end{center}

$C_{00}$ counts pairs both clusterings separated, $C_{11}$ counts pairs both kept together, and $C_{01}, C_{10}$ are the two kinds of disagreement. The four entries together cover every pair, so the matrix is a complete partition of the pairwise decisions.

\metricheading{When to use}

Use the matrix to distinguish splitting from merging. A large $C_{10}$ counts same-class pairs placed apart; a large $C_{01}$ counts different-class pairs placed together. There are $N(N-1)/2$ unordered pairs, but implementations can calculate the totals from contingency counts without examining every pair.

\coloredboxes{
    \item Separates failure modes that summary metrics hide. $RI = 0.85$ doesn't tell you whether the algorithm is over-splitting or over-merging; comparing $C_{01}$ and $C_{10}$ does.
    \item Stays $2 \times 2$ regardless of group counts. Ten classes and three clusters give a compact summary instead of a $10 \times 3$ contingency table.
}
{
    \item Naive pair enumeration is expensive. Use an implementation that derives the totals from contingency counts.
    \item Same vs different is a coarse view: two clusterings can produce identical pair confusion matrices and still disagree on which specific class each cluster represents.
}

\thispagestyle{customstyle}

\begin{metricfigure}
    \centering
    \includegraphics[width=.82\textwidth]{figures/Pair_Confusion_Matrix.png}
\end{metricfigure}

\metriccaption{Figure. Pair Confusion Matrix.}{This $300$-point example uses scikit-learn's ordered-pair convention: both $(a,b)$ and $(b,a)$ count, but self-pairs do not. The entries total $300 \times 299 = 89{,}700$, twice the unordered count. Only about $1{,}200$ pairs disagree in each direction, giving $RI \approx 0.974$ and $ARI \approx 0.941$. This is strong agreement, even after chance correction.}

The larger ``both apart'' count reflects the number of different-class pairs, but the small off-diagonal counts show that this grouping also preserves most within-class pairs. Dividing every entry by two would use unordered pairs instead and leave RI, ARI and FMI unchanged.

\orangebox{Did you know that...}
{This matrix is the source for every pair-counting metric. $RI$ is the fraction of pairs on the diagonal; ARI rescales the same quantity for chance; the Fowlkes-Mallows Index takes a geometric mean of pairwise precision and recall computed from the same four entries; the Jaccard variant drops $C_{00}$ to avoid inflation from the typically dominant ``both apart'' count.}

\metricheading{Related metrics}\metricsecondary

FMI gives a symmetric summary of pairwise precision and recall. If merging and splitting have different consequences, keep those two rates or the off-diagonal counts separate. Use the Contingency Matrix to identify which classes are affected.

\metricentry{Completeness Score}{Completeness Score}\label{sec:completeness-score}

The Completeness Score measures whether members of each reference class stay together in one cluster. It does not require that cluster to contain only that class. Putting every point into one large cluster therefore gives completeness $1$, even though the classes are mixed. Homogeneity checks that other part of the result.

\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                Completeness = 1 - \frac{{\color{nmlcyan}H(K \mid C)}}{{\color{nmlpurple}H(K)}}
                $
            }
        };

        \draw[-latex,nmlcyan, semithick] ($(a.north)+(1.78,-0.06)$) to[bend right=15] node[pos=1, left] {cond. entropy of clusters} +(-1.00,0.30);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(2.27,0.04)$) to[bend left=15] node[pos=1, left] {entropy of clusters} +(-1.00,-0.30);
    }
\end{metricformula}

Let $C$ be the reference class and $K$ the cluster. $H(K)$ is cluster uncertainty before we know the class; $H(K\mid C)$ is what remains afterward. Completeness is $1$ when no class is split, and $0$ when the class tells us nothing about the cluster. With one cluster both entropies are zero; the score is defined as $1$.

\metricheading{When to use}

When the task requires that all members of a class stay together: topic modeling where one topic shouldn't be split, customer cohort discovery where a cohort shouldn't fragment. Always pair with Homogeneity (or use V-Measure); Completeness alone is gameable by merging everything.


\coloredboxes{
    \item Diagnoses class fragmentation directly. If Completeness drops while Homogeneity stays high, the algorithm is over-clustering --- splitting real classes into too many pieces.
    \item Clean interpretation in $[0, 1]$: $1$ means every class lives in one cluster, $0$ means class membership conveys nothing about cluster assignment.
}
{
    \item Gameable by merging. A single cluster containing every point scores Completeness $= 1$ trivially. Always evaluate alongside Homogeneity, V-Measure, or NMI.
    \item Not chance-adjusted. Random clusterings can produce non-trivial Completeness scores; AMI corrects for this baseline when needed.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \centering
    \includegraphics[width=\textwidth]{figures/Completeness_Score_tradeoff.png}
\end{metricfigure}

\metriccaption{Figure. Completeness Score.}{Three clusterings of the same $3$-class data. With $k=3$, both scores hit $1$. Collapsing into one big cluster keeps Completeness at $1$ (every class is fully contained somewhere) but sends Homogeneity to $0$ --- the inflation that makes Completeness misleading on its own. Over-splitting into $k=9$ does the opposite: every cluster is pure, but each class spreads across multiple clusters and Completeness falls to $0.50$.}

\orangebox{Did you know that...}
{Completeness and Homogeneity are the same formula with the arguments swapped: $\text{Homogeneity} = 1 - H(C \mid K)/H(C)$ and $\text{Completeness} = 1 - H(K \mid C)/H(K)$. So Completeness on (true, predicted) equals Homogeneity on (predicted, true). This is why V-Measure --- the harmonic mean of the two --- is symmetric in its arguments when $\beta=1$, giving the two components equal weight.}

\metricheading{Related metrics}\metricsecondary

Completeness and Homogeneity always need to be read together; one without the other is incomplete. If Completeness is high and Homogeneity is low, you're over-merging; the opposite signals over-splitting. V-Measure gives the harmonic-mean summary, and AMI provides the chance-corrected version of the same intuition.

\thispagestyle{clusteringstyle}
\metricentry{Homogeneity Score}{Homogeneity Score}\label{sec:homogeneity-score}

Homogeneity measures whether each cluster contains only one reference class. Pure clusters need not keep a class together: assigning each point its own cluster gives homogeneity $1$. Read it alongside completeness to detect such splitting.

\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                Homogeneity = 1 - \frac{{\color{nmlcyan}H(C \mid K)}}{{\color{nmlpurple}H(C)}}
                $
            }
        };
        \draw[-latex,nmlcyan, semithick] ($(a.north)+(1.63,-0.04)$) to[bend right=15] node[pos=1, left] {cond. entropy of classes} +(-1.00,0.30);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(2.18,0.04)$) to[bend left=15] node[pos=1, left] {entropy of classes} +(-1.00,-0.30);
    }
\end{metricformula}

Here $H(C)$ is class uncertainty before we know the cluster. $H(C \mid K)$ is the uncertainty left within clusters, weighted by their sizes. In the next page's mixed example, about $0.37$ nats remain from $1.10$, giving homogeneity about $0.66$. The score ranges from $0$ to $1$, with $1$ for pure clusters. If there is only one reference class, $H(C)=0$ and homogeneity is defined as $1$.

\metricheading{When to use}

Use Homogeneity when each cluster should be class-pure, such as customer segments that should not mix profiles or document clusters that should not span topics. Pair it with Completeness or use V-Measure to detect over-splitting.


\coloredboxes{
    \item Surfaces over-merging directly. If Homogeneity drops while Completeness stays high, the algorithm has merged distinct classes into the same cluster --- the exact failure mode the score is designed to detect.
    \item Clean $[0, 1]$ interpretation: $1$ means every cluster holds a single class, $0$ means clusters mirror the class distribution and say nothing.
}
{
    \item Gameable by over-splitting. Setting $k = n$ (each point its own cluster) gives Homogeneity $= 1$ trivially. Always pair with Completeness or report V-Measure.
    \item Not chance-adjusted. Random clusterings can produce non-trivial Homogeneity scores; AMI corrects for this baseline.
}

    \centering

\end{metricfigure}

\metriccaption{Figure. Homogeneity Score.}{The class composition of every cluster for three clusterings, with each cluster's class entropy

\orangebox{Did you know that...}
{Giving every point its own cluster guarantees homogeneity $1$, but does not guarantee low completeness or V-Measure. For $100$ points in $50$ two-point classes, singleton clusters have completeness about $0.85$ and V-Measure about $0.92$. Combining purity and class preservation is useful, but it does not remove chance effects or always give over-splitting a low score.}

\metricheading{Related metrics}\metricsecondary

Homogeneity and Completeness mirror each other: if Homogeneity is high but Completeness is low, the algorithm is over-splitting; the opposite signals over-merging. V-Measure summarizes the pair as a harmonic mean; AMI provides the chance-corrected information-theoretic version of the same intuition.

\metricentry{V-Measure}{V-Measure}\label{sec:v-measure}

V-Measure combines cluster purity and class preservation in one score. With equal weight, it is the harmonic mean of homogeneity and completeness, so it is pulled toward the weaker component. Homogeneity $1$ and completeness $0.5$, for example, give $V \approx 0.67$ rather than their arithmetic mean of $0.75$.

\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                V = \frac{(1 + {\color{nmlred}\beta}) \cdot {\color{nmlcyan}h} \cdot {\color{nmlpurple}c}}{{\color{nmlred}\beta} \cdot {\color{nmlcyan}h} + {\color{nmlpurple}c}}
                $
            }
        };

        \draw[-latex,nmlcyan, semithick] ($(a.north)+(1.18,-0.06)$) to[bend right=15] node[pos=1, left] {homogeneity} +(-1.00,0.30);
        \draw[-latex,nmlpurple, semithick] ($(a.north)+(1.79,-0.19)$) to[bend left=15] node[pos=1, right] {completeness} +(1.00,0.30);
        \draw[-latex,nmlred, semithick] ($(a.south)+(-0.16,0.06)$) to[bend left=15] node[pos=1, left] {weighting parameter} +(-1.00,-0.30);
    }
\end{metricformula}

At $\beta = 1$, $V = 2hc/(h+c)$ gives both components equal weight. For positive $\beta$, values above $1$ emphasize completeness and values below $1$ emphasize homogeneity. The score ranges from $0$ to $1$; reaching $1$ requires both components to equal $1$. If both are zero, V-Measure is defined as zero.

\metricheading{When to use}

Use V-Measure when both pure clusters and intact reference classes matter. Choose and report the same positive $\beta$ when comparing models: $\beta=0.5$, for example, would give purity more weight. Also consider AMI when agreement by chance matters; V-Measure itself is not chance-adjusted.


\coloredboxes{
    \item Combines two complementary criteria. A weak component lowers the score, though over-splitting can still receive a high value.
    \item Tunable via $\beta$: when the application explicitly weights purity over class preservation (or vice versa), V-Measure adjusts continuously, no need to swap metrics.
}
{
    \item Not chance-adjusted. Random clusterings can produce non-zero V-Measure; AMI corrects for this baseline.
    \item Hides the diagnostic. $V = 0.7$ doesn't say whether you're over-merging or over-splitting --- read Homogeneity and Completeness separately to identify the failure mode.
}

\orangebox{Did you know that...}
{At $\beta = 1$, V-Measure on (true, predicted) equals V-Measure on (predicted, true) --- it is symmetric in its arguments, because Completeness on (true, predicted) equals Homogeneity on (predicted, true) and the harmonic mean is symmetric in $h$ and $c$. So the same metric works for evaluating against ground truth and for comparing two clusterings to each other --- no need to designate one as the reference.}

\metricheading{Related metrics}\metricsecondary

At $\beta=1$, V-Measure equals NMI using the arithmetic mean of the label entropies. AMI adds chance correction; ARI uses pairwise agreement with its own chance baseline. Differences between these scores can reflect their weighting as well as chance agreement. Inspect the contingency table before attributing them to a particular kind of split or merge.

\metricentry{Davies-Bouldin Index}{Davies-Bouldin Index}\label{sec:davies-bouldin-index}

The Davies-Bouldin (DB) Index compares the spread inside clusters with the distance between their centers. For each pair, it divides their combined spread by the distance between their centers. It keeps the largest ratio for each cluster, then averages those values across clusters. Lower scores favor compact, well-separated groups.

\begin{metricformula}
    \tikz{
    \node[inner sep=2pt, font=\Large] (a) {
    {
    $\displaystyle
    DB = \frac{1}{k} \sum_{{\color{nmlpurple}i}=1}^{k} \max_{{\color{nmlpurple}i} \neq {\color{nmlcyan}j}} R_{{\color{nmlpurple}i}{\color{nmlcyan}j}}, \qquad
    R_{{\color{nmlpurple}i}{\color{nmlcyan}j}} = \frac{s_{\color{nmlpurple}i} + s_{\color{nmlcyan}j}}{d_{\color{nmlpurple}i\color{nmlcyan}j}}
    $
    }
    };

    \draw[-latex,nmlpurple, semithick] ($(a.north)+(3.14,-0.46)$) to[bend right=15] node[pos=1, left] {within-cluster spread} +(-1.00,0.58);
    \draw[-latex,nmlcyan, semithick] ($(a.south)+(2.04,0.55)$) to[bend left=15] node[pos=1, left] {centroid distance} +(-1.00,-0.80);
    }
\end{metricformula}

Here $s_i$ is the average distance from points in cluster $i$ to its center, $d_{ij}$ is the distance between two centers, and $k$ is the number of clusters. If two clusters each have spread $1$ and their centers are $4$ apart, their ratio is $(1+1)/4=0.5$. DB averages the largest ratio for each cluster, giving a nonnegative score.

\metricheading{When to use}

Use DB to compare clusterings with compact groups around centers, such as k-means results with different cluster counts. Evaluate them on the same observations and features. The lowest score identifies the grouping DB favors among those tested.


\coloredboxes{
    \item Fast when there are relatively few clusters: it uses point-to-center and center-to-center distances, not all point pairs.
    \item Checks each cluster against the one with the largest ratio of combined spread to separation, so a poorly separated pair can raise the overall score.
}
{
    \item The version here uses Euclidean distances and centers. It may fit curved or density-based groups poorly, even when they capture useful structure.
    \item Sensitive to outliers. They can increase cluster spread and raise DB, while also moving the centers used in the ratios.
}

\orangebox{Did you know that...}
{DB gives each cluster one contribution to the average, regardless of its size. The mean silhouette instead gives each point one contribution, so larger clusters contribute more points. CH pools squared distances. These different ways of summarizing a grouping help explain why the indices need not favor the same result.}

\metricheading{Related metrics}\metricsecondary

CH adds up squared distances across the data, while DB gives each cluster equal weight in its average. Silhouette instead evaluates each point against its own cluster and the nearest alternative. Its plot can help locate points that fit poorly, even when the overall clustering score looks good.

\metricentry{FMI}{Fowlkes-Mallows Index (FMI)}\label{sec:fmi}

The Fowlkes-Mallows Index (FMI) combines pairwise precision and recall. Precision asks what fraction of pairs placed together belong to the same reference class; recall asks what fraction of same-class pairs remain together. FMI takes the square root of their product, giving a geometric mean that falls when either component is weak.

\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                FMI = \sqrt{\frac{{\color{nmlcyan}TP}}{{\color{nmlcyan}TP} + {\color{nmlpurple}FP}} \cdot \frac{{\color{nmlcyan}TP}}{{\color{nmlcyan}TP} + {\color{nmlpurple}FN}}}
                $
            }
        };

        \draw[-latex,nmlcyan, semithick] ($(a.north)+(-0.16,-0.16)$) to[bend right=15] node[pos=1, left] {correctly paired} +(-1.00,0.36);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(0.53,0.10)$) to[bend left=15] node[pos=1, left] {incorrectly paired} +(-1.00,-0.30);
    }
\end{metricformula}

FMI lies between its precision and recall inputs, within $[0,1]$. It is not chance-adjusted: two independent, roughly balanced groupings with $k$ groups each have FMI near $1/k$. If either grouping contains only singletons, there are no together-pairs for one denominator; scikit-learn returns zero, even when both singleton groupings match.

\metricheading{When to use}

Use FMI for balanced pair-counting comparisons, including hierarchical clustering, when partial structure matters and chance correction is not essential. Use ARI when chance correction matters.


\coloredboxes{
    \item Penalizes imbalance: pairwise precision $0.9$ and recall $0.5$ give FMI $0.67$, below their arithmetic mean $0.7$. A strong component cannot hide a weak one.
    \item Bounded in $[0, 1]$: $1$ means exact pair agreement; $0$ means no pair grouped together in one clustering is also grouped in the other.
}
{
    \item Not chance-adjusted. Random clusterings can produce non-trivial FMI values; use ARI when chance correction matters.
    \item Combines the two error directions symmetrically. Keep precision and recall separate if merging and splitting have different costs.
}

\begin{metricfigure}
    \centering
    \includegraphics[width=.82\textwidth]{figures/FMI_plane.png}
\end{metricfigure}

\metriccaption{Figure. FMI.}{The examples use $300$ points in three equal reference classes; the curves join equal FMI values. Splitting each class into roughly two pure groups preserves precision at $1$ but loses about half the together-pairs, giving FMI about $0.71$. One cluster recovers every reference pair but also merges all three classes: recall is $1$, precision about $0.33$ and FMI about $0.58$. ARI scores that one-cluster result zero.}

\orangebox{Did you know that...}
{Fowlkes and Mallows introduced their index in 1983 to compare hierarchical clusterings at successive cuts. For the same pairwise precision and recall, their geometric mean is at least as large as the harmonic mean used by pairwise F1, and no larger than the arithmetic mean. All three coincide when precision and recall match.}

\metricheading{Related metrics}\metricsecondary

ARI adjusts pairwise agreement for chance, whereas FMI combines pairwise precision and recall without that adjustment. A positive ARI indicates agreement above its baseline, even if numerically lower than FMI. An ARI near zero, as in the one-cluster example, indicates agreement close to that baseline. The Contingency Matrix shows which groups are responsible for the agreement or disagreement.

\metricentry{Silhouette Score}{Silhouette Score}\label{sec:silhouette-score}

The Silhouette Score compares each point's average distance to its own cluster with an alternative cluster, then averages across points. High values mean points are closer to their own groups under the chosen distance. Low or negative values suggest assignments worth inspecting; they do not prove those assignments wrong.

\begin{metricformula}
\tikz{
\node[inner sep=2pt, font=\Large] (a) {
{
$\displaystyle
s(i) =
\begin{cases}
\dfrac{{\color{nmlcyan}b(i)} - {\color{nmlpurple}a(i)}}{\max\left\{ {\color{nmlpurple}a(i)}, {\color{nmlcyan}b(i)} \right\}}  & \text{if}\; |C_I| > 1 \\[4pt]
0  & \text{if}\; |C_I| = 1
\end{cases}
$
}
};

\draw[-latex,nmlcyan, semithick] ($(a.north)+(-1.19,-0.03)$) to[bend right=15] node[pos=1, left] {separation} +(-1.00,0.30);
\draw[-latex,nmlpurple, semithick] ($(a.north)+(0.28,-0.04)$) to[bend left=15] node[pos=1, right] {cohesion} +(1.00,0.30);
}
\end{metricformula}

For point $i$, $a(i)$ averages distances to the other points in its cluster. To get $b(i)$, average its distances to each other cluster separately and take the smallest average. If $a(i)=2$ and $b(i)=6$, its silhouette is $(6-2)/6 \approx 0.67$. Here $|C_I|$ is the size of its assigned cluster; a singleton receives zero.

\metricheading{When to use}

Use silhouette for point-level diagnostics with a distance appropriate to the task. Scores range from $-1$ to $1$: near zero, the two average distances are similar; below zero, another cluster is closer on average. It can compare candidate groupings without labels, but is not a general solution for curved or density-based clusters.


\coloredboxes{
    \item Per-point detail. A silhouette plot shows which points and clusters deserve closer inspection.
    \item Supports suitable pairwise dissimilarities, including cosine and edit distance, without requiring cluster centers.
}
{
    \item Full calculation uses pairwise distances. For large data, use a reproducible sample that retains small clusters, or a faster suitable criterion.
    \item Favors compact, separated groups. Curved or density-based clusters can score lower even when they capture the intended structure.
}

\orangebox{Did you know that...}
{Peter Rousseeuw introduced silhouettes in 1987 as both a numerical and a graphical way to assess clustering. The plot lets us see whether low values occur in one group or throughout the data. That can guide inspection of the assignments, features and distance; the average alone cannot identify which of those choices needs attention.}

\metricheading{Related metrics}\metricsecondary

CH and Davies-Bouldin are faster options when distances to Euclidean centers suit the task. Silhouette allows other dissimilarities and shows individual point scores, but it can favor compact, separated groups too. The methods need not choose the same cluster count; compare what each one measures with the structure you want to recover.
