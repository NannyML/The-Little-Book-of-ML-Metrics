\chapteropener{Clustering}{orangelight}{orangeaccent}{%
Clustering has no labels to score against, so its metrics come in two families. Internal indices (silhouette, Calinski--Harabasz,
Davies--Bouldin) judge a partition by its own geometry: how tight the clusters are and how far apart. External indices (Rand, mutual
information, homogeneity, completeness, V-measure, Fowlkes--Mallows) compare a partition with a reference labeling when one exists, and
have to be corrected for chance because random partitions already agree somewhat. A good internal score does not mean the clusters mean
anything, and a good external score is only as good as its reference; read both with the contingency matrix at hand.}{In this chapter}


% ---------- Mutual Info Score ----------
\clearpage
\thispagestyle{clusteringstyle}
\section{Mutual Info Score}
\subsection{Mutual Info Score}

Mutual Information (MI) measures how much knowing one variable reduces uncertainty about another. In clustering, that's how much knowing the predicted cluster label tells you about the true class. A cluster that contains only one class gives high MI; a cluster that mixes classes evenly gives MI near $0$.

% Formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                MI({\color{nmlcyan}U}, {\color{nmlpurple}V}) = \sum_{i=1}^{|{\color{nmlcyan}U}|} \sum_{j=1}^{|{\color{nmlpurple}V}|} \frac{|{\color{nmlcyan}U_i} \cap {\color{nmlpurple}V_j}|}{{\color{nmlred}N}} \log \frac{{\color{nmlred}N}\, |{\color{nmlcyan}U_i} \cap {\color{nmlpurple}V_j}|}{|{\color{nmlcyan}U_i}|\, |{\color{nmlpurple}V_j}|}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(-1.5,-0.1)$) to[bend right=15] node[pos=1, left] {true labels} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(0.0,-0.1)$) to[bend left=15] node[pos=1, right] {predicted labels} +(1,.5);
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(0.0,0.3)$) to[bend left=15] node[pos=1, left] {total samples} +(-1,-.5);
    }
\end{center}

MI ranges from $0$ (no information) to $+\infty$. The upper bound depends on label entropy, so raw MI is not comparable across datasets. NMI rescales to $[0, 1]$; AMI further subtracts chance agreement and ranges from $-1$ to $1$.

\textbf{When to use Mutual Info Scores?}

When you have ground-truth labels and want to compare clusterings across runs or algorithms. Use NMI for cross-dataset comparison, AMI when chance agreement could inflate the score (few clusters, balanced classes). Avoid raw MI alone --- the unbounded scale is hard to interpret.

\enlargethispage{\baselineskip}
\coloredboxes{
    \item Permutation-invariant. MI doesn't care which integer label is assigned to a cluster --- $\text{MI}([0,0,1],[0,0,1]) = \text{MI}([0,0,1],[1,0,0])$. This matters because cluster algorithms output arbitrary integer labels.
    \item Detects partial structure that purity-style metrics miss. If a class is split into two clusters that each contain only that class, MI rewards the alignment; purity would treat it as a failure.
}
{
    \item Raw MI has no upper bound, so a high value on one dataset doesn't mean anything compared to a high value on another. Always report NMI or AMI instead.
    \item Requires ground-truth labels. For unsupervised evaluation without labels, use the Silhouette Score or Davies-Bouldin Index.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=\textwidth]{figures/Clustering_external_metrics_comparison.png}
\end{figure*}

\textbf{Figure.} Six external clustering metrics on the same 3-class problem, comparing well-separated clusters (cyan) against overlapping ones (red). All metrics drop on the overlapping case. Note that the MI scale depends on the number of classes (here bounded by $\log 3 \approx 1.1$) --- raw MI is not directly comparable across datasets, which is why NMI and AMI exist.

\orangebox{Did you know that...}
{MI is the Kullback-Leibler divergence between the joint distribution of two labelings and the product of their marginals. If clusters and classes were statistically independent, MI would be exactly $0$ --- so MI literally measures how far the two labelings are from being independent. This is also why MI shows up in feature selection: the same formula measures how much a feature tells you about a target.}

\textbf{Other related metrics}

For cross-dataset comparison on a bounded $[0, 1]$ scale, use NMI. For chance-adjusted scoring, use AMI. When MI ranks two clusterings very differently from the Adjusted Rand Index, it usually means one of them captures partial structure (multiple clusters splitting a single class) that pair-counting metrics miss.

% ---------- rand index ----------
\clearpage
\thispagestyle{clusteringstyle}
\section{Rand Index}
\subsection{Rand Index}

The Rand Index (RI) is the fraction of point pairs on which two clusterings agree --- whether they both place the pair together, or both separate them. On three balanced classes with random labels, $RI \approx 0.56$ already: most pairs are correctly apart by chance, so RI inflates regardless of clustering quality. The Adjusted Rand Index (ARI) subtracts that chance baseline, so a score of $0$ means random and $1$ means identical clusterings.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                RI = \frac{{\color{nmlcyan}TP} + {\color{cyan}TN}}{{\color{nmlcyan}TP} + {\color{cyan}TN} + {\color{nmlpurple}FP} + {\color{nmlpurple}FN}}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.5,-0.1)$) to[bend right=15] node[pos=1, left] {agreeing pairs} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(2.0,0.3)$) to[bend left=15] node[pos=1, left] {disagreeing pairs} +(-1,-.5);
    }
\end{center}

RI ranges from $0$ to $1$, but the chance baseline depends on the number of clusters and approaches $1$ as $k$ grows --- raw RI drifts upward regardless of clustering quality. ARI's chance-corrected scale runs from $-0.5$ to $1$.

\textbf{When to use the Rand Index?}

When you have ground-truth labels and want a pair-counting similarity score. In practice, report ARI rather than raw RI --- the chance correction is essential. Avoid pair-counting on heavily imbalanced data, where the dominant class drives $TN$ and masks errors; use NMI or AMI instead.

\coloredboxes{
    \item Symmetric in true vs predicted. Swapping the two arguments returns the same score, which makes RI/ARI convenient for comparing two clusterings without designating a reference.
    \item ARI has a clear chance baseline at $0$, so scores stay comparable across datasets and across different values of $k$ --- something raw RI and raw MI cannot offer.
}
{
    \item Raw RI inflates with the number of clusters. When $k$ is large, most pairs end up in different clusters and $TN$ dominates, so RI drifts toward $1$ even for poor clusterings. Always report ARI.
    \item Pair-counting misses partial structure. Splitting one true class into two pure sub-clusters hurts RI but rewards MI/NMI --- the two families can rank the same clustering very differently.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=\textwidth]{figures/Rand_Index_separation.png}
\end{figure*}

\textbf{Figure.} Three clusterings of $300$ points across $3$ classes: perfect (left), partial overlap (center), and random label assignment (right). Raw RI stays high across all three ($1.00$, $0.90$, $0.56$) because between-cluster pairs vastly outnumber within-cluster pairs, so $TN$ dominates the score. ARI subtracts that chance baseline and collapses to $0$ for random labels, exposing the inflation.

\orangebox{Did you know that...}
{RI is the accuracy of treating clustering as a pairwise binary classification: each of the $\binom{n}{2}$ point pairs is either ``same cluster'' or ``different cluster'', and RI counts the fraction where the two clusterings agree. Every failure mode of raw accuracy applies --- including the class-imbalance inflation that makes RI useless on skewed data without the ARI correction.}

\textbf{Other related metrics}

If RI is high but AMI is low, the clustering matches pair-by-pair but loses information-theoretic structure --- often a sign that the algorithm has created many small clusters that trivially separate pairs without reflecting class identity. The Pair Confusion Matrix gives the raw $TP$, $TN$, $FP$, $FN$ counts behind RI; the Fowlkes-Mallows Index combines them as a geometric mean of pair-wise precision and recall.

% ---------- calinski harabasz index ----------
\clearpage
\thispagestyle{clusteringstyle}
\section{CH Index}
\subsection{Calinski Harabasz Index}

The Calinski-Harabasz (CH) Index scores a clustering without ground-truth labels by comparing how tight clusters are internally against how far apart they sit from each other. Higher CH means tighter clusters and wider gaps between centers --- the two properties that define a ``good'' partition when there is nothing to compare to.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                CH = \frac{{\color{nmlcyan}BCSS} / ({\color{nmlred}k} - 1)}{{\color{nmlpurple}WCSS} / ({\color{nmlred}N} - {\color{nmlred}k})}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.5,-0.1)$) to[bend right=15] node[pos=1, left] {between-cluster sum} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(0.5,0.3)$) to[bend left=15] node[pos=1, left] {within-cluster sum} +(-1,-.5);
        \draw[overlay,-latex,nmlred, semithick] ($(a.north)+(2.5,-0.1)$) to[bend left=15] node[pos=1, right] {clusters and samples} +(1,.5);
    }
\end{center}

CH has no upper bound and absolute values are not comparable across datasets --- its main use is picking $k$ by maximizing CH on the same data. The degrees-of-freedom normalization ($k-1$ and $N-k$) is what stops the score from drifting upward as $k$ grows.

\textbf{When to use the CH Index?}

When you have no ground-truth labels and need to choose $k$, or quickly score a clustering's compactness-vs-separation. Avoid CH on non-convex or unequally-sized clusters --- it favors convex, equally-sized blobs and misranks elongated or hierarchical structure. Use the Silhouette Score there.

\enlargethispage{\baselineskip}
\coloredboxes{
    \item Fast: only needs centroids and point-to-centroid distances, so it scales linearly in $n$. Silhouette is $O(n^2)$ --- CH is the natural choice when sweeping $k$ on $100\text{k}+$ points.
    \item Degrees-of-freedom normalization keeps CH comparable across different $k$ on the same dataset, which is what makes the elbow/maximum trick work.
}
{
    \item Assumes Euclidean geometry. CH misranks clusterings on non-Euclidean data (text embeddings with cosine distance, graph data); compute it in an embedding where Euclidean distance is meaningful.
    \item Favors convex, equally-sized clusters. Long, curved, or nested clusters score low even when they reflect real structure --- DBSCAN clusterings can look terrible by CH despite being correct.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.75\textwidth]{figures/Calinski_Harabasz_elbow.png}
\end{figure*}

\textbf{Figure.} CH against $k$ on data with $4$ true clusters. The score climbs steeply as $k$ approaches the true count, peaks at $k=4$, then decays as further splits start fragmenting real clusters. Read the curve as ``where does CH stop rising'' --- the peak is the elbow.

\orangebox{Did you know that...}
{CH is structurally the $F$-statistic from one-way ANOVA applied to cluster assignments: between-group variance over within-group variance, normalized by degrees of freedom. That is why it works as a model-selection criterion --- you are literally asking ``is the variance between clusters significantly larger than the variance within them?'', the same question ANOVA answers for group means.}

\textbf{Other related metrics}

The Silhouette Score also picks $k$ without labels and handles non-convex clusters better, but costs $O(n^2)$. The Davies-Bouldin Index is minimized at the optimal $k$, the opposite direction from CH --- when CH and Davies-Bouldin disagree on the best $k$, cluster sizes are usually very uneven, which CH penalizes harder than Davies-Bouldin.

\clearpage
\thispagestyle{clusteringstyle}
\section{Contingency Matrix}
\subsection{Contingency Matrix}

The Contingency Matrix is the clustering analog of a confusion matrix: rows are true classes, columns are predicted clusters, and cell $(i, j)$ counts the points that belong to class $i$ and ended up in cluster $j$. Unlike a confusion matrix, the row and column index sets do not have to match --- $5$ true classes and $7$ predicted clusters give a $5 \times 7$ matrix, not a square one.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                {\color{nmlcyan}M_{ij}} = \left|\{\, x : {\color{nmlpurple}\text{class}(x) = i},\; {\color{nmlpurple}\text{cluster}(x) = j} \,\}\right|
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(-2.0,-0.1)$) to[bend right=15] node[pos=1, left] {cell at row $i$, col $j$} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.5,0.3)$) to[bend left=15] node[pos=1, right] {points in class $i$ and cluster $j$} +(1,-.5);
    }
\end{center}

Large diagonal entries mean clusters align with classes; large off-diagonals identify which classes the algorithm conflates. Row sums recover class sizes and column sums recover cluster sizes --- a mismatch flags imbalanced clusters.

\textbf{When to use the Contingency Matrix?}

When you have ground-truth labels and need to diagnose \emph{where} a clustering fails, not just measure overall quality. A single number from NMI or ARI hides the error structure; the matrix shows it. Avoid the matrix for high-$k$ problems --- a $50 \times 50$ grid is unreadable. Use it as a first lookup, then summarize with NMI or ARI.

\coloredboxes{
    \item Reveals the structure of clustering errors. An NMI of $0.7$ does not tell you whether class A leaked into cluster B or got split across three clusters --- the matrix does, in one glance.
    \item Foundation for every external metric. NMI, ARI, V-Measure, Homogeneity, and Completeness all derive from the contingency matrix --- once you have it, the summary metrics are one-liners.
}
{
    \item Does not summarize to a single number, so it can't be used directly to optimize hyperparameters or rank algorithms --- you have to derive a scalar first.
    \item Scales poorly with $k$ and $C$. A $20 \times 20$ matrix is still readable; beyond that, the matrix becomes a wall of numbers and you need a row/column reordering or a summary metric.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.5\textwidth]{figures/Contingency_Matrix_heatmap.png}
\end{figure*}

\textbf{Figure.} Contingency Matrix on a $3$-class clustering. The diagonal carries the agreement ($100$, $95$, $99$ out of $100$ per class); the off-diagonals expose the error pattern: class $1$ leaked $4$ points into cluster $0$ and $1$ point into cluster $2$. Read row by row to see where each class went.

\orangebox{Did you know that...}
{Every external clustering metric can be derived from this matrix. NMI is the mutual information between row and column marginals normalized by their entropies; ARI counts agreeing pairs as a quadratic function of the entries; Homogeneity is one minus the conditional entropy of rows given columns. The contingency matrix plays the same role for clustering metrics that the confusion matrix plays for classification ones.}

\textbf{Other related metrics}

The Pair Confusion Matrix collapses the contingency matrix to a $2 \times 2$ table by counting \emph{pairs} of points instead of individual points, which is what powers the pair-counting family (RI, ARI, FMI). When $k \neq C$, the Pair Confusion Matrix still works, but the class-vs-cluster diagnostic detail is gone --- you trade granularity for a tidy summary.

% ---------- pair confusion matrix ----------
\clearpage
\thispagestyle{clusteringstyle}
\section{Pair Confusion Matrix}
\subsection{Pair Confusion Matrix}

The Pair Confusion Matrix is a $2 \times 2$ table that summarizes, for every pair of points, whether two clusterings agree on keeping the pair together or separating it. It collapses arbitrary clusterings (any $k$, any $C$) into the same four-entry summary, which is the structure that powers RI, ARI, and the Fowlkes-Mallows Index.

\begin{center}
    $\displaystyle
    C = \begin{bmatrix}
        {\color{nmlcyan}C_{00}} & {\color{nmlpurple}C_{01}} \\
        {\color{nmlpurple}C_{10}} & {\color{nmlcyan}C_{11}}
    \end{bmatrix}
    $
\end{center}

$C_{00}$ counts pairs both clusterings separated, $C_{11}$ counts pairs both kept together, and $C_{01}, C_{10}$ are the two kinds of disagreement. The four entries together cover every pair, so the matrix is a complete partition of the pairwise decisions.

\textbf{When to use the Pair Confusion Matrix?}

When you want to debug a clustering at the pair-counting level --- to see whether the algorithm is over-splitting (high $C_{10}$: same true class, different predicted cluster) or over-merging (high $C_{01}$: different true class, same predicted cluster). Avoid for large $n$; counting $\binom{n}{2}$ pairs scales quadratically and gets slow past a few hundred thousand points.

\coloredboxes{
    \item Separates failure modes that summary metrics hide. $RI = 0.85$ doesn't tell you whether the algorithm is over-splitting or over-merging; comparing $C_{01}$ and $C_{10}$ does.
    \item Works for any $k$ and $C$. The Contingency Matrix can't handle a $10$-class problem clustered into $3$ groups cleanly; the pair confusion matrix just counts pairs and stays $2 \times 2$.
}
{
    \item $O(n^2)$ to construct naively. Heavy for very large datasets --- sample first or use a sparse implementation.
    \item Same vs different is a coarse view: two clusterings can produce identical pair confusion matrices and still disagree on which specific class each cluster represents.
}

\clearpage

\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.45\textwidth]{figures/Pair_Confusion_Matrix.png}
\end{figure*}

\textbf{Figure.} Pair Confusion Matrix on a $300$-point clustering: $C_{00} = 58{,}812$ pairs separated by both clusterings, $C_{11} = 28{,}544$ pairs kept together, and roughly $1{,}200$ disagreements each way. The diagonal dominates because pairs that should be apart vastly outnumber pairs that should be together --- exactly the $TN$-heavy baseline that inflates raw RI and motivates ARI's chance correction.

When $C_{01} \gg C_{10}$, the algorithm is over-merging (false positives on the ``same cluster'' decision) and pair-wise precision drops; when $C_{10} \gg C_{01}$ it's over-splitting and pair-wise recall drops. So even when the two clusterings get a similar RI score, the imbalance between $C_{01}$ and $C_{10}$ tells you \emph{how} they fail.

\orangebox{Did you know that...}
{This matrix is the source for every pair-counting metric. $RI$ is the fraction of pairs on the diagonal; ARI rescales the same quantity for chance; the Fowlkes-Mallows Index takes a geometric mean of pairwise precision and recall computed from the same four entries; the Jaccard variant drops $C_{00}$ to avoid inflation from the typically dominant ``both apart'' count.}

\textbf{Other related metrics}

The Fowlkes-Mallows Index surfaces the precision-recall asymmetry between $C_{01}$ and $C_{10}$ as a single number, useful when one direction of error matters more. The Contingency Matrix gives the same information at the class level rather than the pair level; use it when the diagnostic needs to identify \emph{which} classes are conflated, not just \emph{how many} pairs are wrong.

% ---------- Completeness Score ----------
\clearpage
\thispagestyle{clusteringstyle}
\section{Completeness Score}
\subsection{Completeness Score}

The Completeness Score measures whether all members of a true class end up in the same cluster. It is asymmetric: lumping every point into one giant cluster gives Completeness $= 1$ trivially, because every class is contained somewhere. That's why Completeness is always reported alongside Homogeneity.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                Completeness = 1 - \frac{{\color{nmlcyan}H(K \mid C)}}{{\color{nmlpurple}H(K)}}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.5,-0.1)$) to[bend left=15] node[pos=1, right] {cond. entropy of clusters} +(1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(2.0,0.3)$) to[bend left=15] node[pos=1, left] {entropy of clusters} +(-1,-.5);
    }
\end{center}

$H(K \mid C)$ is the uncertainty about cluster labels that remains once you know the class --- it falls to $0$ when each class lands in exactly one cluster. Dividing by $H(K)$ rescales to $[0, 1]$: $1$ means classes never get split, $0$ means class membership tells you nothing about cluster assignment.

\textbf{When to use the Completeness Score?}

When the task requires that all members of a class stay together: topic modeling where one topic shouldn't be split, customer cohort discovery where a cohort shouldn't fragment. Always pair with Homogeneity (or use V-Measure); Completeness alone is gameable by merging everything.

\enlargethispage{\baselineskip}
\coloredboxes{
    \item Diagnoses class fragmentation directly. If Completeness drops while Homogeneity stays high, the algorithm is over-clustering --- splitting real classes into too many pieces.
    \item Clean interpretation in $[0, 1]$: $1$ means every class lives in one cluster, $0$ means class membership conveys nothing about cluster assignment.
}
{
    \item Gameable by merging. A single cluster containing every point scores Completeness $= 1$ trivially. Always evaluate alongside Homogeneity, V-Measure, or NMI.
    \item Not chance-adjusted. Random clusterings can produce non-trivial Completeness scores; AMI corrects for this baseline when needed.
}

\clearpage

\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=\textwidth]{figures/Completeness_Score_tradeoff.png}
\end{figure*}

\textbf{Figure.} Three clusterings of the same $3$-class data. With $k=3$, both scores hit $1$. Collapsing into one big cluster keeps Completeness at $1$ (every class is fully contained somewhere) but sends Homogeneity to $0$ --- the inflation that makes Completeness misleading on its own. Over-splitting into $k=9$ does the opposite: every cluster is pure, but each class spreads across multiple clusters and Completeness falls to $0.50$.

\orangebox{Did you know that...}
{Completeness and Homogeneity are the same formula with the arguments swapped: $\text{Homogeneity} = 1 - H(C \mid K)/H(C)$ and $\text{Completeness} = 1 - H(K \mid C)/H(K)$. So Completeness on (true, predicted) equals Homogeneity on (predicted, true). This is why V-Measure --- the harmonic mean of the two --- is symmetric in its arguments and doesn't care which side you call ``true.''}

\textbf{Other related metrics}

Completeness and Homogeneity always need to be read together; one without the other is incomplete. If Completeness is high and Homogeneity is low, you're over-merging; the opposite signals over-splitting. V-Measure gives the harmonic-mean summary, and AMI provides the chance-corrected version of the same intuition.

% ---------- Homogeneity Score ----------
\clearpage
\thispagestyle{clusteringstyle}
\section{Homogeneity Score}
\subsection{Homogeneity Score}

The Homogeneity Score is the mirror of Completeness: it measures whether each cluster contains points from only one true class. It is asymmetric the other way --- splitting every point into its own cluster gives Homogeneity $= 1$ trivially, because a one-point cluster is pure by definition. Always paired with Completeness.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                Homogeneity = 1 - \frac{{\color{nmlcyan}H(C \mid K)}}{{\color{nmlpurple}H(C)}}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.5,-0.1)$) to[bend left=15] node[pos=1, right] {cond. entropy of classes} +(1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(2.0,0.3)$) to[bend left=15] node[pos=1, left] {entropy of classes} +(-1,-.5);
    }
\end{center}

$H(C \mid K)$ is the class uncertainty that remains once you know the cluster --- it falls to $0$ when each cluster contains points from only one class. Dividing by $H(C)$ rescales to $[0, 1]$: $1$ means clusters are perfectly pure, $0$ means cluster assignment tells you nothing about class membership.

\textbf{When to use the Homogeneity Score?}

When the task requires each cluster to be class-pure: customer segmentation where one segment shouldn't mix profiles, document clustering where one cluster shouldn't span topics. Always pair with Completeness (or use V-Measure); Homogeneity alone is gameable by over-splitting --- in the limit, $k = n$ gives Homogeneity $= 1$ trivially.

\enlargethispage{\baselineskip}
\coloredboxes{
    \item Surfaces over-merging directly. If Homogeneity drops while Completeness stays high, the algorithm has merged distinct classes into the same cluster --- the exact failure mode the score is designed to detect.
    \item Clean $[0, 1]$ interpretation: $1$ means each cluster contains a single class, $0$ means clusters mirror the marginal class distribution and convey no information.
}
{
    \item Gameable by over-splitting. Setting $k = n$ (each point its own cluster) gives Homogeneity $= 1$ trivially. Always pair with Completeness or report V-Measure.
    \item Not chance-adjusted. Random clusterings can produce non-trivial Homogeneity scores; AMI corrects for this baseline.
}


\clearpage

\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=\textwidth]{figures/Completeness_Score_tradeoff.png}
\end{figure*}

\textbf{Figure.} The same three clusterings as the Completeness page, read from Homogeneity's angle. With $k=3$, Homogeneity hits $1$. Collapsing into one big cluster sends Homogeneity to $0$ --- one cluster containing every class, the symmetric failure mode that Completeness alone cannot detect. Over-splitting into $k=9$ pushes Homogeneity to $1$ trivially, exposing its gameable direction.

\orangebox{Did you know that...}
{At the extremes, Homogeneity and Completeness behave like precision and recall. $k = 1$ scores Completeness $= 1$ but Homogeneity $= 0$ (one big bucket, all classes mixed); $k = n$ scores Homogeneity $= 1$ but Completeness near $0$ (every point its own bucket, classes scattered). V-Measure takes their harmonic mean precisely to penalize both extremes --- the same trick that makes the F-score useful when precision and recall pull in opposite directions.}

\textbf{Other related metrics}

Homogeneity and Completeness mirror each other: if Homogeneity is high but Completeness is low, the algorithm is over-splitting; the opposite signals over-merging. V-Measure summarizes the pair as a harmonic mean; AMI provides the chance-corrected information-theoretic version of the same intuition.

% ---------- V Measure ----------
\clearpage
\thispagestyle{clusteringstyle}
\section{V Measure}
\subsection{V Measure}

V-Measure is the harmonic mean of Homogeneity and Completeness --- the F-score of clustering. It collapses the two-metric tradeoff into a single bounded number, penalizing extremes the way an F-score penalizes precision-recall imbalance. A clustering with Homogeneity $= 1$ and Completeness $= 0.5$ scores $V = 0.67$, not the arithmetic mean $0.75$.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                V = \frac{(1 + {\color{nmlred}\beta}) \cdot {\color{nmlcyan}h} \cdot {\color{nmlpurple}c}}{{\color{nmlred}\beta} \cdot {\color{nmlcyan}h} + {\color{nmlpurple}c}}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.5,-0.1)$) to[bend right=15] node[pos=1, left] {homogeneity} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(1.5,-0.1)$) to[bend left=15] node[pos=1, right] {completeness} +(1,.5);
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(0.0,0.3)$) to[bend left=15] node[pos=1, left] {weighting parameter} +(-1,-.5);
    }
\end{center}

At $\beta = 1$ (the default), $V = 2hc/(h+c)$ is the standard harmonic mean. $\beta > 1$ tilts the score toward completeness, $\beta < 1$ toward homogeneity. The range is always $[0, 1]$, with $1$ requiring both components to be exactly $1$.

\textbf{When to use V-Measure?}

When you want a single external clustering score and care about both cluster purity and class preservation. Use $\beta \neq 1$ only when the application weights one side --- topic modeling often takes $\beta = 0.5$ when topic purity matters more. Avoid V-Measure when chance baselines matter; use AMI instead, the chance-corrected information-theoretic analog.

\enlargethispage{\baselineskip}
\coloredboxes{
    \item The harmonic mean punishes both gameable extremes ($k=1$ or $k=n$) that fool Homogeneity or Completeness in isolation --- $V$ stays low if either component does.
    \item Tunable via $\beta$: when the application explicitly weights purity over class preservation (or vice versa), V-Measure adjusts continuously, no need to swap metrics.
}
{
    \item Not chance-adjusted. Random clusterings can produce non-zero V-Measure; AMI corrects for this baseline.
    \item Hides the diagnostic. $V = 0.7$ doesn't say whether you're over-merging or over-splitting --- read Homogeneity and Completeness separately to identify the failure mode.
}

\orangebox{Did you know that...}
{At $\beta = 1$, V-Measure on (true, predicted) equals V-Measure on (predicted, true) --- it is symmetric in its arguments, because Completeness on (true, predicted) equals Homogeneity on (predicted, true) and the harmonic mean is symmetric in $h$ and $c$. So the same metric works for evaluating against ground truth and for comparing two clusterings to each other --- no need to designate one as the reference.}

\textbf{Other related metrics}

For chance correction, use AMI --- the information-theoretic analog of V-Measure with the random baseline subtracted. ARI provides the pair-counting alternative on the same chance-corrected scale. When V-Measure is high but ARI is low, the clustering captures information-theoretic structure (mutual information between labels) but disagrees pair-wise --- often a sign that one true class is split into multiple pure sub-clusters.

% ---------- Davis Bouldin Index ----------
\clearpage
\thispagestyle{clusteringstyle}
\section{Davies Bouldin Index}
\subsection{Davies Bouldin Index}

The Davies-Bouldin (DB) Index scores a clustering without labels by asking, for each cluster, how much it overlaps with its worst neighbor. It takes the maximum of $(s_i + s_j)/d_{ij}$ over neighboring clusters --- sum of cluster widths divided by centroid distance --- then averages those worst-case ratios across $k$. Lower is better; the minimum identifies the optimal $k$.

\begin{center}
    \tikz{
    \node[inner sep=2pt, font=\Large] (a) {
    {
    $\displaystyle
    DB = \frac{1}{k} \sum_{{\color{nmlpurple}i}=1}^{k} \max_{{\color{nmlpurple}i} \neq {\color{cyan}j}} R_{{\color{nmlpurple}i}{\color{cyan}j}}, \qquad
    R_{{\color{nmlpurple}i}{\color{cyan}j}} = \frac{s_{\color{nmlpurple}i} + s_{\color{cyan}j}}{d_{\color{nmlpurple}i\color{cyan}j}}
    $
    }
    };
    \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(2.5,0.05)$) to[bend left=15] node[pos=1, right] {within-cluster spread} +(1,.5);
    \draw[overlay,-latex,cyan, semithick] ($(a.south)+(2.5,-0.05)$) to[bend left=15] node[pos=1, right] {centroid distance} +(1,-.5);
    }
\end{center}

$s_i$ is the average point-to-centroid distance inside cluster $i$ and $d_{ij}$ is the centroid distance between $i$ and $j$. DB is bounded below by $0$; in practice, $0.2$--$0.5$ is a strong clustering, values above $1$ indicate significant overlap, and the optimal $k$ is the one that \emph{minimizes} the score.

\textbf{When to use the Davies-Bouldin Index?}

When you have no labels and need a cheap internal score for picking $k$, especially when the worst-overlapping pair matters most. Avoid DB on non-convex or density-based clusters --- the centroid distance assumes Euclidean geometry, and the max over neighbors makes the score sensitive to one bad cluster pair. Use the Silhouette Score there.

\enlargethispage{\baselineskip}
\coloredboxes{
    \item Fast and label-free. Only needs centroids and within-cluster distances --- $O(nk)$, cheaper than Silhouette's $O(n^2)$. Practical for sweeping $k$ on large datasets.
    \item Surfaces the worst neighbor pair. The $\max$ over $j$ means a single overlapping pair drags the score down --- useful for catching one bad cluster among otherwise good ones.
}
{
    \item Assumes Euclidean centroids. Built on within-cluster distance to centroid plus centroid-to-centroid distance, so it misranks non-Euclidean clusterings and density-based clusters (DBSCAN-style) just like CH.
    \item Sensitive to within-cluster outliers. A single outlier inflates $s_i$, raising every $R_{ij}$ involving cluster $i$ even if the rest of the cluster is fine.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.75\textwidth]{figures/Davies_Bouldin_elbow.png}
\end{figure*}

\textbf{Figure.} DB against $k$ on data with $4$ true clusters. The minimum at $k=4$ recovers the correct count; values to the left (under-clustering) leave clusters too wide, values to the right (over-clustering) shrink centroid distances and inflate $R_{ij}$. DB $=0.24$ at the minimum is a strong clustering; values above $1$ would signal significant overlap.

\orangebox{Did you know that...}
{DB and CH read the same data and can disagree on the optimal $k$. CH averages between-cluster dispersion and rewards equal-sized clusters; DB takes the worst-case max and rewards uniformly well-separated pairs. When they disagree, DB usually picks a $k$ that gives a few compact clusters at the expense of the rest, while CH prefers configurations where the typical pair is well-separated. Reading both is the safest sanity check.}

\textbf{Other related metrics}

The Silhouette Score is the other label-free option, costing $O(n^2)$ but handling non-convex clusters better. CH is the third internal candidate --- it's maximized rather than minimized. When DB picks a different $k$ than Silhouette, DB has been swayed by one bad cluster pair (the $\max$ in the formula); Silhouette averages every point's neighbor distance and tends to be more robust to a single ugly cluster.

% ---------- Fowlkes-Mallows Index ----------
\clearpage
\thispagestyle{clusteringstyle}
\section{FMI}
\subsection{Fowlkes-Mallows Index}

The Fowlkes-Mallows Index (FMI) is the geometric mean of pairwise precision and recall on the ``same cluster'' decision. The geometric mean rewards balance: if either pair-wise precision or recall is low, FMI drops --- one-sided clusterings cannot hide behind a strong score in just one direction.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                FMI = \sqrt{\frac{{\color{nmlcyan}TP}}{{\color{nmlcyan}TP} + {\color{nmlpurple}FP}} \cdot \frac{{\color{nmlcyan}TP}}{{\color{nmlcyan}TP} + {\color{nmlpurple}FN}}}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.0,-0.1)$) to[bend right=15] node[pos=1, left] {correctly paired} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.5,0.3)$) to[bend left=15] node[pos=1, left] {incorrectly paired} +(-1,-.5);
    }
\end{center}

FMI ranges from $0$ to $1$ and is bounded above by the smaller of pair-wise precision and recall. It is not chance-adjusted: random clusterings on $k$ balanced classes score roughly $1/k$ by chance, so use ARI when that baseline matters.

\textbf{When to use the FMI?}

When you want a balanced pair-counting score and chance correction is not essential. Useful for hierarchical clustering evaluation where partial structure matters. Avoid FMI alone for chance-sensitive comparisons; use ARI as the chance-corrected pair-counting alternative.

\enlargethispage{\baselineskip}
\coloredboxes{
    \item Geometric mean penalizes imbalance. Pair-wise precision $= 0.9$ and recall $= 0.5$ gives FMI $= 0.67$, not the arithmetic mean $0.7$ --- one-sided clusterings cannot hide behind a strong precision or recall alone.
    \item Bounded in $[0, 1]$ with a clear interpretation: $1$ means every pair agreement is exact, $0$ means no pair that one clustering grouped together was also grouped by the other.
}
{
    \item Not chance-adjusted. Random clusterings can produce non-trivial FMI values; use ARI when chance correction matters.
    \item $O(n^2)$ via direct pairwise comparison. Computable in $O(n + c^2)$ from the contingency matrix, but still heavy for very large datasets.
}

\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=\textwidth]{figures/Clustering_external_metrics_comparison.png}
\end{figure*}

\textbf{Figure.} FMI in the third pair of bars: $1.00$ on well-separated clusters drops to $0.96$ on the overlapping case. On the same data ARI moves $1.00 \to 0.94$, slightly more sensitive --- the difference comes from FMI using a geometric mean of pair precision and recall, while ARI subtracts a chance baseline.

\orangebox{Did you know that...}
{FMI is the only pair-counting metric built as a geometric mean. The pairwise F1 uses the harmonic mean of the same pair-wise precision and recall, ARI subtracts chance from the raw counts, and RI uses arithmetic accuracy --- four different averages, four different sensitivities. The geometric mean sits between the harmonic and arithmetic means, which is why FMI penalizes imbalance more than RI but less than F1 would.}

\textbf{Other related metrics}

FMI is the pair-counting cousin of RI and ARI. When FMI is high but ARI is low, the chance baseline is doing the work --- the clustering looks reasonable on the geometric-mean score but doesn't beat random on the chance-corrected version. Prefer ARI for cross-dataset comparison, FMI for in-dataset sensitivity to balanced precision/recall on pairs.


% ---------- Silhouette Score ----------
\clearpage
\thispagestyle{clusteringstyle}
\section{Silhouette Score}
\subsection{Silhouette Score}

The Silhouette Score compares each point's distance to other points in its own cluster against its distance to the nearest other cluster. Averaging across all points gives a score in $[-1, 1]$: near $+1$ means tight, well-separated clusters; near $0$ means points sit on boundaries; below $0$ means points have been placed in the wrong cluster.

\begin{center}
\tikz{
\node[inner sep=2pt, font=\Large] (a) {
{
$\displaystyle
s(i) =
\begin{cases}
\dfrac{{\color{cyan}b(i)} - {\color{nmlpurple}a(i)}}{\max\left\{ {\color{nmlpurple}a(i)}, {\color{cyan}b(i)} \right\}}  & \text{if}\; |C_I| > 1 \\[4pt]
0  & \text{if}\; |C_I| = 1
\end{cases}
$
}
};
\draw[overlay,-latex,cyan, semithick] ($(a.north)+(-0.9,0.05)$) to[bend right=15] node[pos=1, left] {separation} +(-1,.5);
\draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(0.2,0.05)$) to[bend left=15] node[pos=1, right] {cohesion} +(1,.5);
}
\end{center}

$a(i)$ is the mean distance from point $i$ to other points in its own cluster (cohesion); $b(i)$ is the mean distance to points in the nearest other cluster (separation). Average $S$ above $0.7$ is strong, $0.5$--$0.7$ is reasonable, below $0.25$ usually means the clustering doesn't reflect the data's geometry. Because the score is defined per-point, you can inspect which points are poorly assigned --- something CH and Davies-Bouldin cannot offer.

\textbf{When to use the Silhouette Score?}

When you have no labels, need to handle non-convex clusters or non-Euclidean distance, or want per-point diagnostics from the silhouette plot. Avoid Silhouette on very large datasets ($n > 100\text{k}$): the $O(n^2)$ pairwise computation gets expensive, and CH or Davies-Bouldin will usually pick the same $k$ much faster.

\enlargethispage{2\baselineskip}
\coloredboxes{
    \item Per-point granularity. The silhouette is defined for every point, so you can plot the silhouette diagram and identify exactly which clusters contain misassigned points (those with $s(i) < 0$).
    \item Works with any pairwise distance --- cosine, edit distance, custom metric. Unlike CH and Davies-Bouldin, no Euclidean assumption is baked in.
}
{
    \item $O(n^2)$ to compute. Naive pairwise distance gets slow past $100\text{k}$ points; CH and Davies-Bouldin are the practical alternatives at that scale.
    \item Favors convex, well-separated clusters. Density-based clusters (DBSCAN) and elongated shapes often score lower than k-means blobs even when they capture more meaningful structure.
}

    \centering
    \includegraphics[width=\textwidth]{figures/Silhouette_Score_comparison.png}
\end{figure*}

\textbf{Figure.} Silhouette plots for well-separated ($S = 0.88$) vs overlapping ($S = 0.63$) clusterings. \orangebox{Did you know that...}
{The silhouette plot is the actual practitioner tool, not the average score. The shape of the plot tells you more than the number: a single cluster with mostly low silhouette flags one bad cluster; uniformly mediocre silhouette across every cluster means the geometry isn't separable in this feature space; a few negative bars within an otherwise good cluster point to specific misassigned samples. The average collapses all three stories into one number.}

\textbf{Other related metrics}

CH and Davies-Bouldin pick $k$ faster but assume Euclidean centroids; Silhouette is the right choice when distance is non-Euclidean (text embeddings with cosine, graphs, custom). When Silhouette picks a different $k$ than CH or Davies-Bouldin, the disagreement is usually about cluster size uniformity --- both CH and Davies-Bouldin penalize uneven sizes more than Silhouette, which averages each point's local view.
