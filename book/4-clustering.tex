\section{Mutual Info Score}
\subsection{Mutual Info Score}

Mutual Information (MI) measures how much knowing one variable reduces uncertainty about another. In clustering, that's how much knowing the predicted cluster label tells you about the true class. A cluster that contains only one class gives high MI; a cluster that mixes classes evenly gives MI near $0$.

% Formula
\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                MI({\color{nmlcyan}U}, {\color{nmlpurple}V}) = \sum_{i=1}^{|{\color{nmlcyan}U}|} \sum_{j=1}^{|{\color{nmlpurple}V}|} \frac{|{\color{nmlcyan}U_i} \cap {\color{nmlpurple}V_j}|}{{\color{nmlred}N}} \log \frac{{\color{nmlred}N}\, |{\color{nmlcyan}U_i} \cap {\color{nmlpurple}V_j}|}{|{\color{nmlcyan}U_i}|\, |{\color{nmlpurple}V_j}|}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(-1.5,-0.1)$) to[bend right=15] node[pos=1, left] {true labels} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(0.0,-0.1)$) to[bend left=15] node[pos=1, right] {predicted labels} +(1,.5);
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(0.0,0.3)$) to[bend left=15] node[pos=1, left] {total samples} +(-1,-.5);
    }
\end{center}

MI ranges from $0$ (no information) to $+\infty$. The upper bound depends on label entropy, so raw MI is not comparable across datasets. NMI rescales to $[0, 1]$; AMI further subtracts chance agreement and ranges from $-1$ to $1$.

\textbf{When to use Mutual Info Scores?}

When you have ground-truth labels and want to compare clusterings across runs or algorithms. Use NMI for cross-dataset comparison, AMI when chance agreement could inflate the score (few clusters, balanced classes). Avoid raw MI alone --- the unbounded scale is hard to interpret.

\coloredboxes{
    \item Permutation-invariant. MI doesn't care which integer label is assigned to a cluster --- $\text{MI}([0,0,1],[0,0,1]) = \text{MI}([0,0,1],[1,0,0])$. This matters because cluster algorithms output arbitrary integer labels.
    \item Detects partial structure that purity-style metrics miss. If a class is split into two clusters that each contain only that class, MI rewards the alignment; purity would treat it as a failure.
}
{
    \item Raw MI has no upper bound, so a high value on one dataset doesn't mean anything compared to a high value on another. Always report NMI or AMI instead.
    \item Requires ground-truth labels. For unsupervised evaluation without labels, use the Silhouette Score or Davies-Bouldin Index.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=\textwidth]{figures/Clustering_external_metrics_comparison.png}
\end{figure*}

\textbf{Figure.} Six external clustering metrics on the same 3-class problem, comparing well-separated clusters (cyan) against overlapping ones (red). All metrics drop on the overlapping case. Note that the MI scale depends on the number of classes (here bounded by $\log 3 \approx 1.1$) --- raw MI is not directly comparable across datasets, which is why NMI and AMI exist.

\orangebox{Did you know that...}
{MI is the Kullback-Leibler divergence between the joint distribution of two labelings and the product of their marginals. If clusters and classes were statistically independent, MI would be exactly $0$ --- so MI literally measures how far the two labelings are from being independent. This is also why MI shows up in feature selection: the same formula measures how much a feature tells you about a target.}

\textbf{Other related metrics}

For cross-dataset comparison on a bounded $[0, 1]$ scale, use NMI. For chance-adjusted scoring, use AMI. When MI ranks two clusterings very differently from the Adjusted Rand Index, it usually means one of them captures partial structure (multiple clusters splitting a single class) that pair-counting metrics miss.

\section{Rand Index}
\subsection{Rand Index}

The Rand Index (RI) counts pair-agreements: out of all pairs of points, what fraction do the predicted clustering and the reference agree on --- either placing the pair together ($TP$) or apart ($TN$). Random labels on $3$ balanced classes already produce $RI \approx 0.56$, which is why the chance-corrected Adjusted Rand Index (ARI) exists.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                RI = \frac{{\color{nmlcyan}TP} + {\color{cyan}TN}}{{\color{nmlcyan}TP} + {\color{cyan}TN} + {\color{nmlpurple}FP} + {\color{nmlpurple}FN}}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.5,-0.1)$) to[bend right=15] node[pos=1, left] {agreeing pairs} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(2.0,0.3)$) to[bend left=15] node[pos=1, left] {disagreeing pairs} +(-1,-.5);
    }
\end{center}

RI ranges from $0$ to $1$, but the chance baseline depends on the number of clusters and approaches $1$ as $k$ grows --- raw RI drifts upward regardless of clustering quality. ARI subtracts that baseline and lands on a $[-0.5, 1]$ scale: $0$ means no better than random, $1$ means identical clusterings.

\textbf{When to use the Rand Index?}

When you have ground-truth labels and want a pair-counting similarity score. In practice, report ARI rather than raw RI --- the chance correction is essential. Avoid pair-counting on heavily imbalanced data, where the dominant class drives $TN$ and masks errors; use NMI or AMI instead.

\coloredboxes{
    \item Symmetric in true vs predicted. Swapping the two arguments returns the same score, which makes RI/ARI convenient for comparing two clusterings without designating a reference.
    \item ARI has a clear chance baseline at $0$, so scores stay comparable across datasets and across different values of $k$ --- something raw RI and raw MI cannot offer.
}
{
    \item Raw RI inflates with the number of clusters. When $k$ is large, most pairs end up in different clusters and $TN$ dominates, so RI drifts toward $1$ even for poor clusterings. Always report ARI.
    \item Pair-counting misses partial structure. Splitting one true class into two pure sub-clusters hurts RI but rewards MI/NMI --- the two families can rank the same clustering very differently.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=\textwidth]{figures/Rand_Index_separation.png}
\end{figure*}

\textbf{Figure.} Three clusterings of $300$ points across $3$ classes: perfect (left), partial overlap (center), and random label assignment (right). Raw RI stays high across all three ($1.00$, $0.90$, $0.56$) because between-cluster pairs vastly outnumber within-cluster pairs, so $TN$ dominates the score. ARI subtracts that chance baseline and collapses to $0$ for random labels, exposing the inflation.

\orangebox{Did you know that...}
{RI is the accuracy of treating clustering as a pairwise binary classification: each of the $\binom{n}{2}$ point pairs is either ``same cluster'' or ``different cluster'', and RI counts the fraction where the two clusterings agree. Every failure mode of raw accuracy applies --- including the class-imbalance inflation that makes RI useless on skewed data without the ARI correction.}

\textbf{Other related metrics}

If RI is high but AMI is low, the clustering matches pair-by-pair but loses information-theoretic structure --- often a sign that the algorithm has created many small clusters that trivially separate pairs without reflecting class identity. The Pair Confusion Matrix gives the raw $TP$, $TN$, $FP$, $FN$ counts behind RI; the Fowlkes-Mallows Index combines them as a geometric mean of pair-wise precision and recall.

\section{CH Index}
\subsection{Calinski Harabasz Index}

The Calinski-Harabasz (CH) Index scores a clustering without ground-truth labels by comparing how tight clusters are internally against how far apart they sit from each other. Higher CH means tighter clusters and wider gaps between centers --- the two properties that define a ``good'' partition when there is nothing to compare to.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                CH = \frac{{\color{nmlcyan}BCSS} / ({\color{nmlred}k} - 1)}{{\color{nmlpurple}WCSS} / ({\color{nmlred}N} - {\color{nmlred}k})}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.5,-0.1)$) to[bend right=15] node[pos=1, left] {between-cluster sum} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(0.5,0.3)$) to[bend left=15] node[pos=1, left] {within-cluster sum} +(-1,-.5);
        \draw[overlay,-latex,nmlred, semithick] ($(a.north)+(2.5,-0.1)$) to[bend left=15] node[pos=1, right] {clusters and samples} +(1,.5);
    }
\end{center}

CH has no upper bound, and the absolute value depends on the data, so $CH = 3000$ on one dataset says nothing about $CH = 5000$ on another. Its main use is picking $k$: compute CH across candidate values of $k$ on the same data and take the maximum. The degrees-of-freedom normalization ($k-1$ and $N-k$) is what stops the score from drifting upward as $k$ grows.

\textbf{When to use the CH Index?}

When you have no ground-truth labels and need to choose $k$, or quickly score a clustering's compactness-vs-separation. Avoid CH when clusters are non-convex or have very different sizes --- it favors convex, equally-sized blobs and will misrank elongated or hierarchical structure. Use the Silhouette Score for those cases.

\coloredboxes{
    \item Fast to compute. CH only needs cluster centroids and point-to-centroid distances, so it scales linearly in $n$. The Silhouette Score is $O(n^2)$ in the worst case --- CH is the natural choice when sweeping $k$ on $100\text{k}+$ points.
    \item Degrees-of-freedom normalization keeps CH comparable across different $k$ on the same dataset, which is what makes the elbow/maximum trick work.
}
{
    \item Assumes Euclidean geometry. Both BCSS and WCSS are sums of squared Euclidean distances, so CH misranks clusterings on non-Euclidean data (text embeddings with cosine distance, graph data). Compute CH in an embedding space where Euclidean distance is meaningful.
    \item Favors convex, equally-sized clusters. Long, curved, or nested clusters score low even when they reflect real structure --- DBSCAN-style clusterings can look terrible by CH despite being correct.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.75\textwidth]{figures/Calinski_Harabasz_elbow.png}
\end{figure*}

\textbf{Figure.} CH against $k$ on data with $4$ true clusters. The score climbs steeply as $k$ approaches the true count, peaks at $k=4$, then decays as further splits start fragmenting real clusters. Read the curve as ``where does CH stop rising'' --- the peak is the elbow.

\orangebox{Did you know that...}
{CH is structurally the $F$-statistic from one-way ANOVA applied to cluster assignments: between-group variance over within-group variance, normalized by degrees of freedom. That is why it works as a model-selection criterion --- you are literally asking ``is the variance between clusters significantly larger than the variance within them?'', the same question ANOVA answers for group means.}

\textbf{Other related metrics}

The Silhouette Score also picks $k$ without labels and handles non-convex clusters better, but costs $O(n^2)$. The Davies-Bouldin Index is minimized at the optimal $k$, the opposite direction from CH --- when CH and Davies-Bouldin disagree on the best $k$, cluster sizes are usually very uneven, which CH penalizes harder than Davies-Bouldin.

\section{Contingency Matrix}
\subsection{Contingency Matrix}

The Contingency Matrix is the clustering analog of a confusion matrix: rows are true classes, columns are predicted clusters, and cell $(i, j)$ counts the points that belong to class $i$ and ended up in cluster $j$. Unlike a confusion matrix, the row and column index sets do not have to match --- $5$ true classes and $7$ predicted clusters give a $5 \times 7$ matrix, not a square one.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                {\color{nmlcyan}M_{ij}} = \left|\{\, x : {\color{nmlpurple}\text{class}(x) = i},\; {\color{nmlpurple}\text{cluster}(x) = j} \,\}\right|
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(-2.0,-0.1)$) to[bend right=15] node[pos=1, left] {cell at row $i$, col $j$} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.5,0.3)$) to[bend left=15] node[pos=1, right] {points in class $i$ and cluster $j$} +(1,-.5);
    }
\end{center}

Reading the matrix is the diagnostic act: large diagonal entries mean clusters align with classes, large off-diagonals identify which classes the algorithm conflates. Row sums recover class sizes and column sums recover cluster sizes --- a mismatch between them flags imbalanced clusters.

\textbf{When to use the Contingency Matrix?}

When you have ground-truth labels and need to diagnose \emph{where} a clustering fails, not just measure overall quality. A single number from NMI or ARI hides the error structure; the matrix shows it. Avoid the matrix for high-$k$ problems --- a $50 \times 50$ grid is unreadable. Use it as a first lookup, then summarize with NMI or ARI.

\coloredboxes{
    \item Reveals the structure of clustering errors. An NMI of $0.7$ does not tell you whether class A leaked into cluster B or got split across three clusters --- the matrix does, in one glance.
    \item Foundation for every external metric. NMI, ARI, V-Measure, Homogeneity, and Completeness all derive from the contingency matrix --- once you have it, the summary metrics are one-liners.
}
{
    \item Does not summarize to a single number, so it can't be used directly to optimize hyperparameters or rank algorithms --- you have to derive a scalar first.
    \item Scales poorly with $k$ and $C$. A $20 \times 20$ matrix is still readable; beyond that, the matrix becomes a wall of numbers and you need a row/column reordering or a summary metric.
}

\clearpage
\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.5\textwidth]{figures/Contingency_Matrix_heatmap.png}
\end{figure*}

\textbf{Figure.} Contingency Matrix on a $3$-class clustering. The diagonal carries the agreement ($100$, $95$, $99$ out of $100$ per class); the off-diagonals expose the error pattern: class $1$ leaked $4$ points into cluster $0$ and $1$ point into cluster $2$. Read row by row to see where each class went.

\orangebox{Did you know that...}
{Every external clustering metric is a function of this matrix. NMI is the mutual information between row and column marginals normalized by their entropies; ARI counts agreeing pairs as a quadratic function of the entries; Homogeneity is one minus the conditional entropy of rows given columns. The contingency matrix is to clustering metrics what the confusion matrix is to classification metrics --- one table, every summary downstream.}

\textbf{Other related metrics}

The Pair Confusion Matrix collapses the contingency matrix to a $2 \times 2$ table by counting \emph{pairs} of points instead of individual points, which is what powers the pair-counting family (RI, ARI, FMI). When $k \neq C$, the Pair Confusion Matrix still works, but the class-vs-cluster diagnostic detail is gone --- you trade granularity for a tidy summary.

\clearpage
\thispagestyle{clusteringstyle}
\section{Pair Confusion Matrix}
\subsection{Pair Confusion Matrix}

The Pair Confusion Matrix is a clustering evaluation metric used to assess the similarity between two clusterings by
comparing pairwise relationships between data points. It is a $2x2$ matrix that extends the idea of the confusion matrix
to clustering scenarios, focusing on whether pairs of points are grouped together or not.

\begin{center}
    $\displaystyle
    C = \begin{bmatrix}
        {\color{nmlcyan}C_{00}} & {\color{nmlpurple}C_{01}} \\
        {\color{nmlpurple}C_{10}} & {\color{nmlcyan}C_{11}}
    \end{bmatrix}
    $
\end{center}

It has four key components, each representing a count of point pairs in specific configurations across two clusterings. It can
also be shown that $C_{00} + C_{11} + C_{10} + C_{01} = \frac{n(n-1)}{2}$

\textbf{When to use the Pair Confusion Matrix?}

Use the Pair Confusion Matrix when evaluating clustering algorithms that produce hard cluster assignments and when ground truth
is available.

\coloredboxes{
    \item Breaks down clustering agreements and disagreements into familiar components (TP, TN, FP, FN).
}
{
    \item Requires ground-truth labels.    
    \item Computation can be slow for large datasets due to the pairwise comparison of all points.
    \item Does not provide a single score.
}

\clearpage

\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=0.45\textwidth]{figures/Pair_Confusion_Matrix.png}
\end{figure*}

Analyse the following example to understand how to build the matrix. Lets say we have the following clustering results.

\[
\begin{array}{l|cccccc}
    & \text{$obj_{1}$} & \text{$obj_{2}$} & \text{$obj_{3}$} & \text{$obj_{4}$} \\
\hline
\text{True Labels} & 0 & 0 & 1 & 0 \\
\text{Pred Labels} & 0 & 1 & 0 & 1 \\
\end{array}
\]

With this we can compute $C_{00}$, $C_{11}$, $C_{10}$ and $C_{01}$.

\begin{itemize}
    \item $C_{00}$: number of pairs with different true and pred labels = $(obj_{2}, obj_{3})$; $(obj_{3}, obj_{4})$; $(obj_{3}, obj_{2})$; $(obj_{4}, obj_{3})$ = $4$
    \item $C_{11}$: number of pairs with same true and pred labels = $(obj_{2}, obj_{4})$; $(obj_{4}, obj_{2})$ = $2$
    \item $C_{10}$: number of pairs with same true but different pred labels = $(obj_{1}, obj_{2})$; $(obj_{1}, obj_{4})$;
    $(obj_{2}, obj_{1})$; $(obj_{4}, obj_{1})$ = $4$
    \item $C_{01}$: number of pairs with different true but same pred labels = $(obj_{1}, obj_{3})$; $(obj_{3}, obj_{1})$ = $2$
\end{itemize}

Thus, the final Pair Confusion Matrix looks like:
\begin{center}
    \[
        C =
        \begin{bmatrix}
            4 & 2 \\
            4 & 2
        \end{bmatrix}
    \]
\end{center}

\orangebox{Did you know that...}
{The Pair Confusion Matrix is the foundation for computing the Rand Index. In fact, $RI = (C_{00} + C_{11}) / (C_{00} + C_{11} + C_{10} + C_{01})$,
making the pair confusion matrix the clustering equivalent of the classification confusion matrix.}


\textbf{Other related metrics}

The Pair Confusion Matrix provides the raw counts from which the Rand Index and Adjusted Rand Index are computed.
For a non-pairwise view, see the Contingency Matrix. For a single summary score, consider the Fowlkes-Mallows Index.

\section{Completeness Score}
\subsection{Completeness Score}

The Completeness Score evaluates the degree to which members of a ground-truth class are assigned to the same cluster in a
clustering solution. It is one of two complementary measures (the other being Homogeneity Score) used to assess the quality of
clustering. Completeness is mathematically defined using conditional entropy between cluster labels and assignments.

% \[
% \text{Completeness} = 1 - \frac{H(K \mid C)}{H(K)}
% \]

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                Completeness = 1 - \frac{{\color{nmlcyan}H(K \mid C)}}{{\color{nmlpurple}H(K)}}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.5,-0.1)$) to[bend left=15] node[pos=1, right] {cond. entropy of clusters} +(1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(2.0,0.3)$) to[bend left=15] node[pos=1, left] {entropy of clusters} +(-1,-.5);
    }
\end{center}

A perfect completeness score of 1 indicates that all members of a single class are contained within a single cluster. 
A score of 0 means the clustering completely fails to keep members of the same class together.

\textbf{When to use the Completeness Score?}

The Completeness Score is particularly useful when you need to evaluate how well a clustering algorithm preserves class membership
within individual clusters. It is commonly applied in scenarios such as document clustering, where documents belonging to the same
topic should ideally belong to one cluster.

\coloredboxes{
    \item Class-Focused Evaluation. Completeness measures how well class integrity is preserved in clustering,
    providing a clear diagnostic for one aspect of clustering quality.
    \item Lower and upper bounded.
    \item Clustering algorithm agnostic.
}
{
    \item Requires ground-truth labels.
    \item Trade-Off with Homogeneity. Completeness tends to decrease as homogeneity increases, creating a challenge when
    trying to optimize both simultaneously.
    \item Not normalized with regards to random labeling.
}

\clearpage

\thispagestyle{customstyle}

\begin{figure*}[ht!]
    \centering
    \includegraphics[width=\textwidth]{figures/Clustering_good_vs_bad.png}
\end{figure*}

\textbf{Figure.} Well-separated clusters (left) achieve high Completeness: all members of each class end up in the same cluster. Overlapping clusters (right) lower the score as class members scatter across clusters.

\textbf{Other related metrics}

The Completeness Score is best used in conjunction with the Homogeneity Score or V-Measure. While completeness focuses on
ensuring all members of a class are in the same cluster, homogeneity ensures that clusters do not mix members from different
classes. V-Measure provides a balanced harmonic mean of these two metrics, offering a single comprehensive evaluation of
clustering quality​.

\clearpage
\thispagestyle{clusteringstyle}
\section{Homogeneity Score}
\subsection{Homogeneity Score}

The Homogeneity Score measures how well each cluster contains only data points from a single ground-truth class.
It is designed to assess the purity of clusters by evaluating the entropy of class distributions within each cluster.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                Homogeneity = 1 - \frac{{\color{nmlcyan}H(C \mid K)}}{{\color{nmlpurple}H(C)}}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(1.5,-0.1)$) to[bend left=15] node[pos=1, right] {cond. entropy of classes} +(1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(2.0,0.3)$) to[bend left=15] node[pos=1, left] {entropy of classes} +(-1,-.5);
    }
\end{center}

A score of 1.0 indicates perfect homogeneity, meaning every cluster contains data points from only one class. 
A score of 0.0 indicates that the class distribution within clusters mirrors the overall dataset distribution,
showing no class distinction within clusters.

\textbf{When to use the Homogeneity Score?}

The Homogeneity Score is particularly valuable when evaluating the ability of a clustering algorithm to form well-defined,
class-pure clusters. Common applications include customer segmentation, where customers within a cluster should share similar characteristics.
Topic modeling, where documents within a cluster should belong to the same topic.

\coloredboxes{
    \item Cluster Purity Focus. Homogeneity emphasizes the purity of clusters, providing a clear diagnostic of whether
    clusters contain mixed classes.
    \item Lower and upper bounded.
    \item Clustering algorithm agnostic.
}
{
    \item Requires ground-truth labels.
    \item Trade-Off with Completeness. Homogeneity tends to decrease as completeness increases, creating a challenge when trying to optimize both simultaneously.
    \item Not normalized with regards to random labeling.
}

\thispagestyle{clusteringstyle}
\section{V Measure}
\subsection{V Measure}

V-Measure is an external clustering evaluation metric that combines the strengths of two complementary criteria: Homogeneity
(how pure clusters are with respect to ground-truth classes) and Completeness (how well all members of a class are grouped into
the same cluster). It is computed as the harmonic mean of these two scores, similar to how precision and recall are combined into
the F-score.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                V = \frac{(1 + {\color{nmlred}\beta}) \cdot {\color{nmlcyan}h} \cdot {\color{nmlpurple}c}}{{\color{nmlred}\beta} \cdot {\color{nmlcyan}h} + {\color{nmlpurple}c}}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.5,-0.1)$) to[bend right=15] node[pos=1, left] {homogeneity} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(1.5,-0.1)$) to[bend left=15] node[pos=1, right] {completeness} +(1,.5);
        \draw[overlay,-latex,nmlred, semithick] ($(a.south)+(0.0,0.3)$) to[bend left=15] node[pos=1, left] {weighting parameter} +(-1,-.5);
    }
\end{center}

By design, V-Measure is bounded between 0.0 and 1.0, with higher scores indicating better clustering quality. A score of 1.0
means that both homogeneity and completeness are perfectly satisfied.

\textbf{When to use the V-measure?}

V-Measure is ideal for evaluating clustering solutions when you need a balanced assessment of both purity within clusters and the
completeness of class representation.

\coloredboxes{
    \item Combines homogeneity and completeness into a single score, providing a holistic evaluation of clustering quality.
    \item The $\beta$ parameter allows customization to prioritize either homogeneity or completeness based on specific use cases.
    \item Clustering algorithm agnostic.
}
{
    \item Requires ground-truth labels.
    \item V-Measure inherits the trade-off between homogeneity and completeness. Adjusting one often impacts the other, making it
    challenging to optimize both in some scenarios.
    \item Not normalized with regards to random labeling.
}

\textbf{Other related metrics}

V-Measure excels as a comprehensive metric for clustering evaluation. However, for specific insights, it can be supplemented with
individual Homogeneity and Completeness scores. Additionally, pair-based measures like Adjusted Rand Index (ARI) or
information-theoretic measures like Variation of Information (VI) may provide complementary perspectives in specific use cases​.

\section{Davies Bouldin Index}
\subsection{Davies Bouldin Index}

The Davies-Bouldin Index measures the quality of clustering by evaluating the average similarity between each cluster \( C_i \) and its most similar neighboring cluster 
\( C_j \) for $i,j = 1, 2, ... k$. This similarity \( R_{ij} \) is calculated as the ratio of the within-cluster distance (how tightly packed the cluster is) to the between-cluster distance (how far apart the clusters are).

% The Davies Bouldin score is the average similairty measure of each cluster $C_{i}$ for $i = 1,2,...k$  with its most similar cluster $C_{j}$, where similarity $R_{ij}$ is the ratio of within-cluster distances to between cluster distance. So the clusters which are farther apart and less dispersed will result in a better score. The Davis Bouldin Index is defined as 

\begin{center}
    \tikz{
    \node[inner sep=2pt, font=\Large] (a) {
    {
    $\displaystyle
    DB = \frac{1}{k} \sum_{{\color{nmlpurple}i}=1}^{k} max_{{\color{nmlpurple}i} \neq {\color{cyan}j}} R_{{\color{nmlpurple}i}{\color{cyan}j}}
    $
    }
    }; 
    }
% \end{center}

% \begin{center}
    \tikz{
    \node[inner sep=2pt, font=\Large] (a) {
    {
    $\displaystyle
    R_{{\color{nmlpurple}i}{\color{cyan}j}} = \frac{s_{\color{nmlpurple}i} + s_{\color{cyan}j}}{d_{\color{nmlpurple}i\color{cyan}j}}
    $
    }
    }; 
    \draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(1.2,0.05)$) to[bend left=15] node[pos=1, right] {cluster diameter} +(1,.5); 
    \draw[overlay,-latex,cyan, semithick] ($(a.south)+(0.6,-0.05)$) to[bend left=15] node[pos=1, left] {distance between centroids} +(-1,-.5); 
    }
\end{center}

% A lower Davies-Bouldin score indicates better clustering, as it suggests that clusters are more compact and well-separated from one another.
% where $s_{i}$ is the average distance between each point of cluster $i$ and centroid of that cluster and $d_{ij}$ is the distance between cluster centroids $i$ and $j$. The minium Davies Bouldin score is zero, with lower values indicating better clustering.

Here, \( s_i \) represents the average distance between each point in cluster \( i \) and the centroid of that cluster,
while \( d_{ij} \) is the distance between the centroids of clusters \( i \) and \( j \). The Davies-Bouldin score has a
minimum value of zero, with lower scores indicating better-defined clusters that are compact and well-separated.

\textbf{When to use the Davies-Bouldin Index?}

Davies-Bouldin Index is particularly useful when we have ground truth labels and clusters are roughly spherical and centroid-based.

\coloredboxes{
\item The computation of Davies-Bouldin Index is simpler than that of Silhouette scores, zero is the lowest possible score and closer the value to zero indicate a better separation.
}
{
\item Davies-Bouldin Index can generally be higher for convex clusters than other clusters, such as density based clusters.
\item The usage of centroid distance limits the distance metric to Euclidean space.
}

\section{FMI}
\subsection{Fowlkes-Mallows Index}

The Fowlkes–Mallows Index (FMI) is an external evaluation metric used to quantify the similarity between two clustering results
or between a clustering result and a ground-truth classification. It is defined as the geometric mean of precision and recall.

\begin{center}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                FMI = \sqrt{\frac{{\color{nmlcyan}TP}}{{\color{nmlcyan}TP} + {\color{nmlpurple}FP}} \cdot \frac{{\color{nmlcyan}TP}}{{\color{nmlcyan}TP} + {\color{nmlpurple}FN}}}
                $
            }
        };
        \draw[overlay,-latex,nmlcyan, semithick] ($(a.north)+(0.0,-0.1)$) to[bend right=15] node[pos=1, left] {correctly paired} +(-1,.5);
        \draw[overlay,-latex,nmlpurple, semithick] ($(a.south)+(1.5,0.3)$) to[bend left=15] node[pos=1, left] {incorrectly paired} +(-1,-.5);
    }
\end{center}

The FMI ranges from 0 to 1, where a higher value indicates a greater similarity between the clustering result and the ground
truth.

\textbf{When to use FMI?}

The Fowlkes–Mallows Index is particularly useful when assessing how well a clustering algorithm performs relative to a
known classification. Measuring the similarity between two different clustering results to determine consistency.

\coloredboxes{
    \item Provides a straightforward measure of clustering quality based on well-understood concepts of precision and recall.
    \item Can be used to evaluate both flat and hierarchical clustering algorithms.
    \item Clustering algorithm agnostic.
}
{
    \item Requires ground-truth labels.
    \item Relies on pairwise comparisons, which can be computationally intensive for large datasets.
    \item Not normalized with regards to random labeling.
}

\section{Silhouette Score}
\subsection{Silhouette Score}

The Silhouette Coefficient measures how well a data point fits within its assigned cluster compared to other clusters. 
It quantifies how similar a sample is to its own cluster (cohesion) compared to the nearest neighboring cluster (separation).
The Silhouette Coefficient $s(i)$ for a given data point $i$ in the cluster $C_I$, where $|C_I|$ is the number of data points in $C_I$, is given by:

\begin{center}
\tikz{
\node[inner sep=2pt, font=\Large] (a) {
{
$\displaystyle
s(i) = 
\begin{cases}
\frac{{\color{cyan}b(i)} - {\color{nmlpurple}a(i)}}{max\left\{ {\color{nmlpurple}a(i)}, {\color{cyan}b(i)} \right\}}  & if\, |C_I| > 1 \\
0  & if\, |C_I| = 1
\end{cases}
$
}
};
\draw[overlay,-latex,cyan, semithick] ($(a.north)+(-0.9,0.05)$) to[bend right=15] node[pos=1, left] {measures cohesion} +(-1,.5); 
\draw[overlay,-latex,nmlpurple, semithick] ($(a.north)+(0.2,0.05)$) to[bend left=15] node[pos=1, right] {measures separation} +(1,.5); 
% \draw[overlay,-latex,nmlpurple, semithick] ($(b.north)+(0.1,0.05)$) to[bend left=15] node[pos=1, left] {True negatives} +(-1,-.5); 
}
\end{center}

Where  $a(i)$ is the mean distance between a sample and all other points in the same cluster (mean intra-cluster distance), 
and  $b(i)$ is the mean distance between a sample and all points in the nearest different cluster (mean nearest-cluster distance). 
The value of  $s(i)$ lies between -$1$ and  $1$, where  $s(i) \approx 1$ indicates that the data point is well-clustered, 
 $s(i) \approx 0$ means the data point is on or very close to the boundary between two clusters, and  $s(i) \approx -1$ 
suggests that the data point has been misclassified into the wrong cluster.

\textbf{When to use Silhouette Score?}

Use Silhouette Score when the ground truth labels are unknown and the evaluation must be performed using the model itself.

\coloredboxes{
\item It provides a clear and intuitive measure of how well clusters are separated, +1 highly dense and -1 for incorrect clustering.
}
{
\item Silhouette Score can generally be higher for convex clusters than other clusters, such as density based clusters.
\item Higher Silhouette Score doesn't necessarily indicate that the clusters will have equal sizes; the clusters can still vary in cardinality.
}

For external evaluation when labels are available, consider the Adjusted Rand Index or Normalized Mutual Information.
