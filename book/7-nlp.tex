\chapteropener{NLP}{cyanhard}{cyanaccent}{%
Natural language processing (NLP) includes tasks such as translating text, summarizing documents and
transcribing speech. To evaluate the text a model produces, we often compare it with a human-written
answer, called a \textit{reference}. A translation can have several valid wordings, so an evaluation may
provide more than one reference for the same input.
\par\medskip
The metrics in this chapter measure different kinds of agreement with those references. Some count
shared words and phrases; others count the edits needed to turn the model's output into a reference.
Exact Match checks whether an answer matches an accepted reference in full. These comparisons help us
track changes between models, but they do not tell the whole story: different wording can express the
same idea, and shared words can hide a change in meaning. The GenAI chapter adds comparisons that
account for the context in which words appear.}{In this chapter}

\metricentry{BLEU}{Bilingual Evaluation Understudy (BLEU)}\label{sec:bleu}
% references:
% https://aclanthology.org/P02-1040.pdf



BLEU measures how much of a machine translation's wording matches one or more human references.
It looks for shared words and sequences of adjacent words, called \textit{n-grams}. A unigram is one
word, a bigram is a pair, and so on. The usual BLEU-4 score combines matches of one to four words,
so it rewards shared phrases as well as individual words.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                BLEU = {\color{nmlred}BP} \cdot \exp\left(\sum_{n=1}^{N} {\color{nmlpurple}w_n} \log {\color{nmlcyan}p_n}\right)
                $
            }
        };

        \draw[-latex,nmlred, semithick] ($(a.north)+(-1.35,-0.61)$) to[bend right=15] node[pos=1, left] {brevity penalty} +(-1.00,0.80);
        \draw[-latex,nmlcyan, semithick] ($(a.south)+(3.22,0.60)$) to node[pos=1, below] {n-gram precision} +(0.00,-0.79);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(1.75,0.69)$) to[bend left=15] node[pos=1, left] {n-gram weights} +(-1.00,-0.88);
    }
\end{metricformula}

Each $p_n$ is the fraction of output $n$-grams matching a reference, with each phrase's credit capped at its largest count in any one reference. BLEU pools counts across the test set, combines the four precisions with equal weights, and applies a brevity penalty $BP$ for output shorter than the references. Scores range from $0$ to $1$, often reported as $0$--$100$; higher means more overlap.

\metricheading{When to use}

Use BLEU to compare translation systems on the same test set and references. Compute it over the
whole set, rather than averaging sentence scores. Individual sentences often have too few long
phrase matches for a useful unsmoothed score.


\coloredboxes{
\item Fast to compute: it counts shared words and phrases without running another model.
\item Gives a repeatable comparison across model versions when the evaluation data and settings stay fixed.
}
{
\item Can miss valid paraphrases and meaning errors. Word overlap alone does not establish translation quality.
\item Tokenization, casing and smoothing affect the score. Report the test set and sacreBLEU signature,
which records its version and settings.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/BLEU_ngram_precision.png}
\end{metricfigure}

\metriccaption{Figure. BLEU.}{Replacing \textit{fox} with \textit{cat} and \textit{lazy} with \textit{tired}
breaks every four-word match. In this unsmoothed BLEU-4 example, $p_4=0$ makes the geometric mean
$0$, even though $78\%$ of individual words still match. An arithmetic mean of the four precisions
would be $0.39$, but BLEU does not combine them that way. Smoothing can give a nonzero score when
an $n$-gram order has no matches.}

\orangebox{Did you know that...}
{Papineni and colleagues at IBM introduced BLEU in 2002 to make translation evaluation faster and
less dependent on repeated human ratings. Their experiments compared systems over a collection of
sentences, not one translation at a time. That distinction still matters: BLEU's geometric mean
combines the precisions calculated from pooled counts, so averaging separate sentence scores gives
a different result.}

\metricheading{Related metrics}\metricsecondary

METEOR can recognize stems and synonyms that BLEU misses; BERTScore compares learned representations
of words in context. TER gives another view by counting edits, including phrase moves. If these scores
disagree, inspect the translations: a gap can reflect valid wording changes, but it does not rule out
errors.

\metricentry{METEOR}{Metric for Evaluation of Translation with Explicit ORdering (METEOR)}\label{sec:meteor}

METEOR measures how well the words in a translation match a reference, allowing some differences in
wording. Alongside exact matches, it can recognize shared stems (\textit{run}/\textit{running}) and
synonyms (\textit{quick}/\textit{fast}). It combines how much of each text matches, then lowers the
score when those matches are scattered rather than forming phrases in the same order.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                METEOR = (1 - {\color{nmlred}\gamma} \cdot {\color{nmlpurple}frag}^{\beta}) \cdot {\color{nmlcyan}F_{mean}}
                $
            }
        };

        \draw[-latex,nmlcyan, semithick] ($(a.north)+(2.91,-0.13)$) to[bend right=15] node[pos=1, left] {harmonic mean} +(-1.00,0.37);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(1.45,0.09)$) to[bend left=15] node[pos=1, left] {fragmentation penalty} +(-1.00,-0.30);
    }
\end{metricformula}

$F_{mean}$ combines word-match precision and recall. The fragmentation term
$frag$ is the number of contiguous matched groups divided by the number of matched
words; a group must stay adjacent and in order in both texts. $\gamma$ and $\beta$
control the penalty. The example uses the original settings, $\gamma=0.5$ and $\beta=3$.
Scores lie between $0$ and $1$; higher means closer agreement under these matching rules.

\metricheading{When to use}

Use METEOR for translation or captioning when you want to credit supported word forms and synonyms.
Check which matching resources exist for the language, and report the implementation, enabled
matching modules and parameter settings so others can reproduce the score.


\coloredboxes{
\item Recognizes some word changes that exact overlap misses, while still accounting for word order.
\item Can score individual sentences, combining how many output words match with how much of the reference
they cover.
}
{
\item Matches depend on language resources. A valid alternative can receive no credit if the matcher
does not recognize it.
\item Matching words need not keep the meaning: swapping \textit{fox} and \textit{dog} still scores
about $0.98$.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/METEOR_vs_BLEU.png}
\end{metricfigure}

\metriccaption{Figure. METEOR.}{A constructed example with hand-chosen synonym pairs and the original settings. Synonyms keep every word matched, so METEOR stays near $1$ (rounded) while unsmoothed BLEU-4 drops to $0$. Reordering the same words into three chunks barely moves METEOR ($0.98$) but cuts BLEU to $0.61$.}

\orangebox{Did you know that...}
{Banerjee and Lavie introduced METEOR at Carnegie Mellon in 2005, partly to address BLEU's lack of an
explicit recall term. Their weighted harmonic mean, $F_{mean}=\frac{P\cdot R}{\alpha P+(1-\alpha)R}$,
used $\alpha=0.9$, giving recall nine times the weight of precision. Missing a reference word therefore
matters more than adding an unmatched word. This is a parameter choice, also used in the figure,
not a fixed property of every METEOR configuration.}

\metricheading{Related metrics}\metricsecondary

A high METEOR score alongside low BLEU can reflect stems or synonyms that BLEU does not match.
It is a reason to inspect the wording, not evidence that the translation is correct. TER counts edits;
BERTScore, in the GenAI chapter, compares learned representations of words in context.

\metricentry{ROUGE}{Recall-Oriented Understudy for Gisting Evaluation (ROUGE)}\label{sec:rouge}

ROUGE compares a summary's wording with a reference. ROUGE-1 counts shared words; ROUGE-2 counts shared adjacent word pairs. ROUGE-L finds the longest word sequence in the same order in both texts, allowing gaps. Each comparison can report precision, recall or their combined F-score.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                ROUGE\text{-}N = \frac{\sum_{s \in Ref} \sum_{gram_n \in s} {\color{nmlcyan}Count_{match}}(gram_n)}{\sum_{s \in Ref} \sum_{gram_n \in s} {\color{nmlpurple}Count}(gram_n)}
                $
            }
        };

        \draw[-latex,nmlcyan, semithick] ($(a.north)+(2.34,-0.09)$) to[bend right=15] node[pos=1, left] {matching n-grams} +(-1.00,0.30);
        \draw[-latex,nmlpurple, semithick] ($(a.south)+(2.62,0.26)$) to[bend left=15] node[pos=1, left] {total reference n-grams} +(-1.00,-0.42);
    }
\end{metricformula}

The formula shows ROUGE-N \textit{recall}: matching $n$-grams divided by their reference count. Precision divides by their count in the model's summary. Scores range from $0$ to $1$; higher means more overlap. Specify the matching rule and quantity, such as ROUGE-1 recall or ROUGE-L F1.

\metricheading{When to use}

Use ROUGE to compare summaries or headlines against references under the same evaluation settings.
Recall shows how much reference wording is recovered; precision helps reveal extra, unmatched text.
Report an F-score when both matter, and inspect factual accuracy separately.


\coloredboxes{
\item Computes word and phrase overlap without running another language model.
\item Offers complementary comparisons: shared words, adjacent pairs and words appearing in the same order.
}
{
\item Recall alone does not penalize added words that leave existing matches intact. Precision and F1
help expose this padding.
\item Shared wording does not establish factual accuracy or fluency. Valid paraphrases can also lose
credit when their wording differs.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=.82\textwidth]{figures/ROUGE_variants.png}
\end{metricfigure}

\metriccaption{Figure. ROUGE.}{The reference is \textit{the central bank raised interest rates to curb inflation}.
The shorter summary, \textit{the bank raised rates to curb inflation}, matches seven of its nine words,
giving recall $7/9\approx0.78$. Appending filler keeps those seven matches while increasing the summary
to $24$ words: recall stays fixed and precision falls from $7/7=1$ to $7/24\approx0.29$.
ROUGE reports both scores; recall is the one that ignores the padding.}

\orangebox{Did you know that...}
{Chin-Yew Lin introduced ROUGE in 2004 for summary evaluation. Its name emphasizes recall, but the
original paper also defined ROUGE-L using precision and recall together. The distinction matters:
copying an entire source document can recover all the reference's wording \textit{if that wording
appears in the source}, while producing a poor summary. Recall alone misses the excess; precision
and an F-score help account for it.}

\metricheading{Related metrics}\metricsecondary

High ROUGE-1 with lower ROUGE-2 or ROUGE-L means that fewer shared words also match as adjacent pairs
or in sequence. This can help locate examples worth reading, but it does not tell us whether their
content is right. BLEU emphasizes output-side phrase precision; BERTScore can recognize similarities
beyond exact wording.

\metricentry{TER}{Translation Edit Rate (TER)}\label{sec:ter}

TER measures how many edits turn a machine translation into a reference, relative to the reference's
length. It counts inserted, deleted and replaced words, as well as \textit{shifts}, where a whole phrase
moves to a new position. A TER of $0.2$ means one edit per five reference words; lower scores mean
fewer edits to reach the reference.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                TER = \frac{{\color{nmlcyan}\text{insertions}} + {\color{nmlcyan}\text{deletions}} + {\color{nmlcyan}\text{substitutions}} + {\color{nmlpurple}\text{shifts}}}{{\color{nmlred}\text{reference length}}}
                $
            }
        };
        \draw[-latex,nmlcyan, semithick] ($(a.north)+(-0.51,-0.04)$) to[bend right=15] node[pos=1, left] {word-level edits} +(-1.00,0.55);
        \draw[-latex,nmlpurple, semithick] ($(a.north)+(5.63,-0.03)$) to[bend right=15] node[pos=1, left] {sequence shifts} +(-1.00,0.35);
        \draw[-latex,nmlred, semithick] ($(a.south)+(2.11,0.04)$) to[bend left=15] node[pos=1, left] {words in reference} +(-1.00,-0.30);
    }
\end{metricformula}

TER starts at $0$ for an exact match and can exceed $1$ when the edit count is larger than the number
of reference words. Some counted edits may replace wording that was already acceptable. Human-targeted
TER (HTER) addresses this by using a reference made by correcting the model's own output.

\metricheading{When to use}

Use TER when an edit count helps explain differences between translations, especially when phrases
move. For a benchmark, follow its evaluation protocol. If the question is how long editing will take,
measure that time directly: TER does not count the effort of reading and deciding what to change.


\coloredboxes{
\item A score of $0.3$ means three counted edits per ten reference words.
\item Treats an allowed phrase move as one edit, so reordering need not cost a separate edit for every word.
}
{
\item Different but correct wording still requires edits to match the reference.
\item Uses an approximate search for phrase moves. Its edit count is not guaranteed to be the smallest
possible, or to match a human's editing process.
}

\metricsecondpage

\thispagestyle{customstyle}

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/TER_edit_breakdown.png}
\end{metricfigure}

\metriccaption{Figure. TER.}{The model output moves \textit{on monday morning} to the front. With only word
insertions, deletions and substitutions, the minimum edit count is six: three deletions and three
insertions achieve it. That gives an edit rate of $6/7\approx0.86$. Allowing one phrase shift gives TER $=1/7\approx0.14$.}

\orangebox{Did you know that...}
{Snover and colleagues introduced TER in 2006 with phrase shifts alongside the usual word edits.
Finding the best combination of moves is expensive, so TER uses a greedy search: it repeatedly picks
a move that reduces the remaining edit count. WER has no shift operation, but it need not delete and
reinsert every word of a moved phrase. Moving a shorter neighboring phrase, or substituting words,
may produce a cheaper alignment.}

\metricheading{Related metrics}\metricsecondary

WER uses the same word-edit operations without phrase shifts. TER can therefore give a much lower
edit count when a shift resolves a reordering, as in the figure. BLEU measures phrase overlap, while
METEOR also allows selected word-form and synonym matches. Lower TER is better; higher BLEU and METEOR
indicate more agreement with their references.

\metricentry{EM}{Exact Match (EM)}\label{sec:em}

Exact Match measures the fraction of predictions that match an accepted reference answer in full.
Each prediction receives $1$ for a match and $0$ otherwise, under the task's comparison rules.
For example, if the only accepted answer is \textit{Martin Luther King}, adding \textit{Jr.} scores
$0$ even though the answer may refer to the same person. EM gives no partial credit for shared words.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                EM = \frac{1}{{\color{nmlred}N}} \sum_{i=1}^{N} {\color{nmlgreen}\mathds{1}}({\color{nmlpurple}\hat{y}_i} = {\color{nmlcyan}y_i})
                $
            }
        };

        \draw[-latex,nmlred, semithick] ($(a.south)+(-0.71,0.34)$) to[bend left=15] node[pos=1, left] {number of samples} +(-1.00,-0.45);
        \draw[-latex,nmlpurple, semithick] ($(a.north)+(1.11,-0.61)$) to[bend right=15] node[pos=1, left] {predicted text} +(-1.00,0.85);
        \draw[-latex,nmlcyan, semithick] ($(a.south)+(2.16,0.60)$) to[bend right=15] node[pos=1, right] {reference text} +(1.00,-0.30);
    }
\end{metricformula}

EM ranges from $0$ to $1$, with higher scores meaning more full matches. The rules may normalize text
before comparing it: SQuAD lowercases answers and removes punctuation, articles and extra whitespace.
Other tasks may require those details to match. When several reference answers are accepted, matching
any one can earn full credit.

\metricheading{When to use}

Use EM for short answers or labels when full agreement with an accepted answer matters. For JSON,
SQL or API arguments, also check the parsed structure or execution: different strings can behave the
same way, and removing punctuation can erase a meaningful difference.


\coloredboxes{
\item Easy to interpret: each prediction either matches an accepted answer or does not.
\item Directly measures full agreement, without giving partial credit to answers that only share words.
}
{
\item Rejects valid alternatives missing from the reference set, including equivalent names or phrasing.
\item Depends on the comparison rules. Report normalization and accepted answers; a match alone does not
validate the reference's correctness.
}

\metricsecondpage

\begin{metricfigure}
    \includegraphics[width=1\textwidth]{figures/EM_vs_F1.png}
\end{metricfigure}

\metriccaption{Figure. EM.}{Four predictions against the single accepted answer \textit{Martin Luther King}. Only the exact
match scores EM $=1$; adding \textit{Jr.}, abbreviating to \textit{Dr.\ King}, or answering
\textit{Malcolm X} all score EM $=0$. Token-level F1 instead grades the overlap --- $0.86$, $0.40$,
$0.00$ --- giving the partial credit EM withholds.}

\orangebox{Did you know that...}
{The Stanford Question Answering Dataset (SQuAD), introduced by Rajpurkar and colleagues in 2016,
reports EM alongside token-level F1. F1 combines word-match precision and recall: against
\textit{Martin Luther King}, adding \textit{Jr.} gives precision $3/4$, recall $3/3$ and F1
$\approx0.86$. SQuAD also allows multiple accepted answers and takes the best match for each
prediction, so a valid alternative need not score zero if it appears in the reference set.}

\metricheading{Related metrics}\metricsecondary

A large token-F1--EM gap means that many answers share words without matching in full. Some may have
extra words or different answer boundaries; others may contain a wrong date or a negation that changes
the meaning. Read those answers before deciding they are nearly correct. For longer text, ROUGE
measures word and sequence overlap, while BERTScore compares words in context.

\metricentry{WER}{Word Error Rate (WER)}\label{sec:wer}

WER measures the word edits separating a speech recognizer's transcript from a reference. It finds the fewest substitutions, deletions and insertions, then divides by the reference-word count. WER $=0.1$ means one edit per ten reference words: replacing a wrong word, restoring a missing one or removing an extra one.

% equation
\begin{metricformula}
    \tikz{
        \node[inner sep=2pt, font=\Large] (a) {
            {
                $\displaystyle
                WER = \frac{{\color{nmlcyan}S} + {\color{nmlcyan}D} + {\color{nmlcyan}I}}{{\color{nmlred}N}}
                $
            }
        };

        \draw[-latex,nmlcyan, semithick] ($(a.north)+(0.05,-0.01)$) to[bend right=15] node[pos=1, left] {edit operations} +(-1.00,0.30);
        \draw[-latex,nmlred, semithick] ($(a.south)+(0.99,0.05)$) to[bend left=15] node[pos=1, left] {words in reference} +(-1.00,-0.30);
    }
\end{metricformula}

WER starts at $0$ and can exceed $1$ ($100\%$) when the edit count exceeds the reference length.
For a test set, add the edit counts across recordings and divide by their total reference-word count;
do not average recording-level percentages equally. Report substitutions, deletions and insertions
separately when you need to see what kinds of differences dominate.

\metricheading{When to use}

Use WER for speech recognition, voice assistants and dictation. Compare systems on the same recordings,
references and text-processing rules. For languages such as Chinese, where written words are not
separated by spaces, Character Error Rate (CER) can avoid dependence on how text is split into words.


\coloredboxes{
\item Gives an edit count with a clear denominator: the number of words in the reference transcripts.
\item Separates extra, missing and replaced words, helping you choose examples to inspect.
}
{
\item Gives each edit the same cost. A wrong digit and a missing filler word can affect the score equally
while having different consequences.
\item Text processing affects the result. Decide how to handle punctuation, numbers and alternatives
such as \textit{can't}/\textit{cannot} before scoring.
}

\metricsecondpage

\begin{metricfigure}
    \includegraphics[width=\textwidth]{figures/WER_vs_errors.png}
\end{metricfigure}

\metriccaption{Figure. WER.}{The best alignment between reference and hypothesis splits the errors into one
substitution (\textit{fox}\,$\rightarrow$\,\textit{box}), one deletion (\textit{dog}), and one insertion
(\textit{very}). WER sums them over the reference length: $(1+1+1)/9 = 0.33$. That same alignment is what
lets WER report \textit{which} kind of error dominates, not merely how many.}

\orangebox{Did you know that...}
{WER is the Levenshtein (edit) distance computed over words instead of characters, normalized by the
reference length. The substitution, deletion, and insertion counts come from the \textit{minimum-cost}
alignment, found by dynamic programming --- so the split into error types is the cheapest explanation of
the differences, not the only one. Run the identical computation per character and you get Character
Error Rate (CER). The distance was introduced by Levenshtein in 1965.}

\metricheading{Related metrics}\metricsecondary

CER applies the edit-distance calculation to characters rather than words. The choice concerns the
written units and word boundaries, not whether a spoken language uses tones. TER adds phrase shifts
for translation, so it can reduce the edit count when words move together. BERTScore provides a
comparison based on learned text representations, but does not replace checking transcription errors.
\metricend
